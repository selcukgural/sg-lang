## 130. The library: regular expressions

Choices made in the hundred-and-thirtieth slice (the library: regular expressions). 1457-1468 were approved on
20 November 2026, before the slice was written; they take regular expressions and compression into `std`,
which 1406 had left to C libraries, and put both before the real programs of 1418. 1469-1476 were approved
the same day, also before:

1457. **Regular expressions and compression come with the language**, written in SG, the same interpreted and
     compiled; TLS and encryption stay with the libraries of C that are looked after for that (1406). Go keeps
     both in its library (`regexp`, `compress/*`, `archive/zip`); Rust leaves them to crates.
1458. **The order**: regular expressions (this slice), then compression and zip archives (1465-1467), then the
     real programs of 1418, whose `grep` uses `Regex`, then XML (1413).
1459. **The meaning is RE2's**: the time of a match grows with the length of the text and no more, so no
     pattern can make a search take for ever (ReDoS); there are no back references and no look-around, which
     would need it. Go's `regexp` and Rust's `regex` mean the same; PCRE and .NET do not.
1460. **The engine**: the pattern is read into a tree, the tree compiled to a program of steps (Thompson's
     construction), and the program run by Pike's machine, which follows every way the pattern could go at
     once, one character at a time, with where each group began and ended. Plain text every match starts with
     is looked for first, as text (`indexOf`), and a pattern that is plain text is only looked for. No lazy DFA:
     the measurement of 1418 says whether one is needed. (It said so: 1536 and 1539 add one.) `x*` of an `x` that can match nothing is compiled as
     `(x+)?`, so the empty way is taken in the order the pattern prefers (as Go since golang.org/issue/46123:
     `(|a)*` matches nothing of `aaa`). A search makes its lists of threads itself, and `findAll` and
     `replaceAll` make them once: a `Regex` is never written by a search, so one in a `static` is read by any
     number of tasks without a lock (Go and Rust keep a pool of them inside, behind one).
1461. **Go's syntax, less what needs more than a pattern**: `.` `[...]` `[^...]` `|` `*` `+` `?` `{n}` `{n,}`
     `{n,m}` and the same with `?` to take as little as can be, `(...)`, `(?:...)`, `(?<name>...)` and
     `(?P<name>...)`, `^` `$` `\A` `\z` `\b` `\B`, `\d \w \s` and `\D \W \S`, `\p` by the general category,
     `[[:alpha:]]` and the other classes of POSIX with `[[:^alpha:]]`, `\Q...\E`, `\x41`, `\x{1F600}`, `\101`
     (octal, as Go), the flags `(?i)` `(?m)` `(?s)` `(?U)` alone or around a group (`(?i:...)`), `-` taking one
     off. The text is matched by character; the positions are in bytes, as in Go and Rust.
1462. **Limits**: a count of a repetition is at most 1000 (as Go), and a program at most 100,000 steps
     (`((a{1000}){1000}){1000}` is `TooLarge`), so no pattern takes the memory of the machine; a number of
     the pattern past them is an error, never a slow program.
1463. **A pattern written in the program is checked when the program is compiled**: the language's own module
     reads it then, as a const is found, and one that is not a regular expression is a compile error that says
     where (`column 1: missing closing )`). Rust has only a lint of clippy (`invalid_regex`), Go nothing.
1464. **The calls**: `Regex.compile(pattern)` gives a `Result<Regex, RegexError>`; `isMatch`, `find` (a
     `Match?`, its `start` and `end`), `findAll`, `captures` (by number and by name), `replaceAll` (`$1`,
     `${1}`, `$name`, `${name}`, `$$`) and `split`. No replacement by a function: the language has no closures.
1465. **Compression** (the next slice): DEFLATE (RFC 1951), zlib (RFC 1950) and gzip (RFC 1952), both ways,
     zlib's levels 0 to 9 and its table; whole or as a stream (`StreamReader`, `StreamWriter`).
1466. **Decompressing takes a limit**, always: `decompress(data, limit)`, `TooLarge` past it, and the reader of a
     stream takes one too, so a bomb is refused by the signature. Go and Rust leave it to the program.
1467. **Zip archives**, as Go's `archive/zip`: read and written, stored and deflated, zip64 both ways, no
     encryption; a name with `..`, a root, a `\` or a drive of Windows is `InsecurePath` (as Go 1.20); no call
     that unpacks a whole archive to the disk, each entry is read; a size that differs from the one written in
     the archive is an error.
1468. **Tests**: RE2's search tests and those of Rust's `regex` where they hold for this syntax; compression both
     ways against zlib (`examples/zlib`); fuzz targets for the reader of a pattern and for inflate.
1469. **`Regex.of(pattern)` takes only a pattern written in the program**, checked and compiled when the
     program is, and gives a `Regex`, never an error when it runs; a pattern made when the program runs goes to
     `Regex.compile`, which gives a `Result`, and one written there is checked when the program is compiled too
     (1463). Go's `MustCompile` panics when the program runs; Rust writes `Regex::new(...).unwrap()`. Raw text
     (`"""\d+"""`) keeps the backslashes from doubling.
1470. **A `string` is matched, not bytes**: matching a `read byte[]` (Rust's `regex::bytes`, Go's `Match`) waits
     for a program that needs it, `grep` of 1418 first. *(Built in slice 173, when `grep` met a line that is
     not UTF-8: 1840, 1842.)*
1471. **`\d \w \s \b` are ASCII**, as in Go and RE2 (in Rust they are Unicode); Unicode is asked for with `\p`.
     `\p` names the general categories; a script (`\p{Greek}`) waits for its table.
1472. **A `Match` is where**: `start` and `end`, in bytes, `Copyable`; `m.of(text)` gives the text and
     `m.length()` its bytes. `findAll` gives a `List<Match>`; `captures` gives a `Captures`, whose `get(i)` and
     `named(name)` give a `Match?`, `null` for a group that took no part. As Go's `FindStringIndex`.
1473. **Only the leftmost match the pattern prefers** (Perl's, RE2's, Go's and Rust's); not POSIX's leftmost
     longest (Go's `Longest()`).
1474. **`static Regex Digits = Regex.of("""\d+""")`**, in place of the `const` 1469 named: a const holds only plain
     data, and a `Regex` holds lists. The pattern is still checked when the program is compiled; it is
     compiled the first time the static is read, once, as Rust's `LazyLock` and Go's variable of a package do.
1475. **The tables of Unicode take the general category** of every code point, five bits of its record (228
     records, 3,400 bytes more), so `\p` names every category and group of them.
1476. **`c.category()`** gives a `UnicodeCategory`, whose 29 variants are Unicode's long names as SG writes a
     name (`UppercaseLetter`, `NonspacingMark`, `DecimalNumber`, `CurrencySymbol`, `SpaceSeparator`,
     `PrivateUse`, `Unassigned`, ...), and `k.abbreviation()` the short one (`Lu`); no `Surrogate`, which no
     `char` is. `\p` takes the short names only: `\p{Lu}`, `\pL`, `\p{L}`, `\PL`, `\p{^L}`, and `\p{Any}`, as Go;
     Rust takes the long ones too. C#'s `char.GetUnicodeCategory` gives the same; Rust's library has none.

What writing it asked for, from 1477. Approved on 20 November 2026:

1477. **`(?i)` compares by Unicode's simple case folding**, the C and S lines of CaseFolding.txt, as Go does:
     `k`, `K` and the Kelvin sign are one, `s` and `ſ`, `ß` and `ẞ`; `ı` and `İ` are not `i`, since no language
     is taken into account (640). A class is folded before it is turned around: `(?i)\P{Lu}` takes neither `a`
     nor `A`, and takes `ı`, which has no upper case of its own. The record's folding now holds the S lines
     too, which changes no full folding (`foldCase`): every character with an S line has an F line, and the
     full folding reads its table for those.
1478. **`$1x` in a replacement is group 1 and an `x`**: a name after `$` is digits or a name, not both; Go and
     Rust take `1x` as one name and write nothing for it. A group the pattern does not have, and a `$` with
     nothing after it, are a panic that names it, never a group taken as empty; a group that took no part
     writes nothing.
1479. **Two groups of one name are an error** (`DuplicateGroupName`), as in Rust; Go takes them.
1480. **`split` of an empty text gives `[""]`**; Go gives `[]` when the pattern is written as nothing (`""`)
     and `[""]` otherwise, which depends on how the pattern is written, not what it matches. Otherwise as Go's
     `Split`.
1481. **Groups are nested at most 250 deep** (Go: 1000): reading a pattern goes down a few calls for each, and
     the stack of a task may be small.

Tested by `ok_regex` (the calls, the syntax, the flags, folding, the errors of `compile`, a pattern nested
250 and 251 deep, `(a*)*b` over 20,000 `a`s), `ok_char_category` (a character of each category, and how many
code points each holds, which are Python's), `error_regex_pattern`, `error_regex_compile_constant`,
`error_regex_of_variable`, `error_regex_match_fields`, `panic_regex_replacement_group`,
`panic_regex_replacement_dollar`, and `a_regex_suite` in `tests/cli.rs`, which runs RE2's search tests
(`tests/regex-suite`, from Go 1.27.4, BSD licence) interpreted and compiled: 1772 of the 1888 cases, each
the leftmost match and the match of the whole text with their groups, none wrong; the cases left out are
`\C`, `\B` in a text that is not ASCII (as Go leaves them), texts that are not UTF-8 and `\p{Greek}`. While
it was written, 207,000 patterns and texts made at random from this syntax were run by Go's `regexp` and by
`Regex` (`isMatch`, `findAll`, the groups, `replaceAll` and `split`), and every result was the same but the
two cases chosen above (1479, 1480); that is how 1477 and the order of `(x+)?` were found. The fuzz target
`regex` (`fuzz/`) runs any pattern and text through it in the interpreter; its first half hour, 126,000
inputs, found nothing.

Measured against Go's `regexp` (20 MB of text, `findAll`, best of three, Apple M3 Max): a plain word 0.020 s
(Go 0.053), `\w+@\w+\.com` 0.544 s (0.477), `(?i)error` 0.315 s (0.362), `[0-9]{4}-[0-9]{2}` 0.359 s (0.341),
`\bfox\b` 0.348 s (0.307), `ş\w+` 0.035 s (0.041). Against Rust's `regex` and C it is measured with the `grep`
of 1418.

With 1457-1481, 474 of the 1842 programs are compiled on macOS and on Linux (103 under the thread sanitizer), and the
236 programs of the site run as they show; on the Windows Arm VM `ok_regex` and `ok_char_category` print the
same interpreted and compiled, and RE2's search tests give the same count both ways.

## 131. The library: compression

Choices made in the hundred-and-thirty-first slice (the library: compression). 1482-1492 were approved on
20 November 2026, before the slice was written; they say how 1465 and 1466 are written, and 1490 and 1491 what
the zip archives of the next slice (1467) will be:

1482. **Two slices**: DEFLATE, zlib and gzip in this one; zip archives, which are built on them and have their
     own rules of safety, in the next, each with its own commit and its own run of CI.
1483. **The calls**, a type for each format, as Go has a package for each: `Deflate`, `Zlib` and `Gzip`, each
     with `compress(read byte[] data, int level)`, giving a `List<byte>`, `decompress(read byte[] data, nint
     limit)`, giving a `Result<List<byte>, CompressError>`, `reader(StreamReader source, long limit)`, giving a
     `Decompressor` with the calls of a `StreamReader` (`readSome`, `readBytes`, `readLine`, `readText`), and
     `writer(StreamWriter target, int level)`, giving a `Compressor` (`writeBytes`, `close`; `Closable`). One
     enum of errors, `CompressError`: `Corrupt(long position)`, `Truncated`, `ChecksumMismatch`, `TooLarge`,
     `TrailingData`, `Io(IoError)`.
1484. **The level** is an `int` from 0 to 9; one outside them is a panic, and one written in the program is a
     compile error. zlib's -1 for its default is not taken: the default is written, 6.
1485. **The bytes are zlib's** (1.3.1) at every level: the same ways of compressing (stored for 0, matches
     taken at once for 1 to 3, the lazy search for 4 to 9), the same hash and table of levels, and the same
     choice for each block between stored, fixed and dynamic codes (`trees.c`). The source names zlib and holds
     its licence, as an altered version must. Go's `compress/flate` makes other bytes.
1486. **Opening is by tables**, as zlib's: 9 bits at a time for a literal or a length, 6 for a distance, and
     tables below them for the longer codes; it is measured against zlib, and what is slower goes into
     "Slower than C".
1487. **gzip**: members one after the other open as one stream (as `gunzip` and Go do); the name, the comment
     and the extra field of a header are read and passed over, and its CRC is checked; what the header holds is
     not given yet. A header written holds no name, a time of 0 and 255 for the system (as Go), so every
     machine writes the same bytes.
1488. **Strict**: a byte after the end of the stream is `TrailingData`. The limit counts opened bytes: as many
     as the limit is no error, one more is `TooLarge`; a reader counts all it opens.
1489. **`Adler32`** comes into `std/checksum.sg`, public and used as `Crc32` is: zlib's format needs it.
1490. **Zip archives** (the next slice), as Go's `archive/zip`: `ZipReader.open(path)` and its `entries`, each a
     `ZipEntry` (`name`, `size`, `compressedSize`, `modified` as a `DateTime`, `isDirectory`, `method`);
     `reader.read(read entry, limit)` gives its bytes and `reader.copyTo(read entry, ref writer, limit)` writes
     them; `ZipWriter.create(StreamWriter)` with `add(name, read data, ZipMethod)`, `addFrom(name, ref
     StreamReader, ZipMethod)` (with a data descriptor), `addDirectory(name)` and `close()`; zip64 when it is
     needed, the flag of UTF-8 for a name that is not ASCII, the time as DOS writes it and as UTC in the extra
     field 0x5455.
1491. **Reading a zip archive checks more than Go**: two entries of one name are `DuplicateName`, a name in a
     local header that is not the one of the central directory is an error, and entries whose data lie over
     each other are refused (the overlapping bomb).
1492. **Tests**: compressing and opening against zlib, its bytes at every level (through the zlib of
     `examples/zlib`), streams made wrong by hand, and a fuzz target of inflate; for zip, archives made by Go,
     Python and `zip`, and the odd ones of Go's `archive/zip/testdata`.

Taken while the slice was written, and approved on 20 November 2026:

1493. **Where `Corrupt` points**: the byte of the compressed data where the part that is wrong begins: the
     header, the description of a block's codes, or the code itself.
1494. **A `Compressor` fails only by writing**: `writeBytes` and `close` give a `Result<void, IoError>`, the
     error of its `StreamWriter`; compressing itself cannot fail.
1495. **A reader gives the bytes up to its limit**, and asking for one more is `TooLarge`; it does not fail as
     soon as it has opened past the limit, which it does a block at a time.
1496. **A line that is not UTF-8** is `Io(InvalidText(position))`, the position counted in the opened bytes, as
     a `StreamReader` counts it in the file.
1497. **What a header may not hold**: gzip's flags that are reserved, a method other than 8, zlib's window
     above 32 KB and its preset dictionary are `Corrupt`; a dictionary is not given to a decompressor here.
1498. **At level 0 a stream's stored blocks follow its pieces**, as zlib's do: the bytes are zlib's for the
     same pieces; at levels 1 to 9 they are the same however the data is cut.
1499. **The opened bytes of `decompress` start at a guessed size**: gzip's length at its end, or four times the
     input, never past the limit nor past 1,032 times the input, the most DEFLATE opens into; the list grows
     from there.
1500. **A module is the folder of the name as written**: on macOS and Windows, whose file names ignore case,
     `Zlib.compress` in a program beside a folder `zlib` read that folder as the module `Zlib` and declared
     its C functions twice. The checker now takes a folder as a module only if its name is spelled as the
     program writes it.

Tested by `ok_compression` (zlib's bytes for a text at level 6 in the three formats, each level of gzip there
and back, Adler-32, every error of `CompressError` from data made wrong by hand, the limit at its edge, two
members of gzip, a gzip file written by a `Compressor` and read back by lines, as text and by bytes, a line
that is not UTF-8), `error_compress_level`, `error_compress_level_negative`, `panic_compress_level`,
`panic_compress_limit`, and two tests of `examples/zlib`, which compare the language's `Zlib` with zlib through
its C at every level and open each other's bytes. While it was written, the compressor was compared with zlib
1.3.1 built from its source on thirteen files (empty, one to three bytes, text, a program, random bytes, zeros,
repeats, a window of 32 KB three times, mixed) in the three formats at every level, 390 cases, all the same
bytes; a `Compressor` fed in pieces of 1 to 100,000 bytes was compared with zlib fed the same pieces, 176
cases, the same bytes, and each read back by a `Decompressor`; the zlib of macOS (1.2.12) gives the same bytes
as 1.3.1 on all of them at levels 0, 1, 4, 6 and 9. 23,000 streams made by zlib and changed at random (bits flipped, bytes
replaced, cut, lengthened) were opened by zlib and by `Gzip`, `Zlib` and `Deflate`: every one opened by both
into the same bytes or refused by both. The fuzz target `inflate` (`fuzz/`) opens any bytes in the
interpreter, and compresses and opens again an input of up to 2 KB; its first half hour, 4,705 inputs (each
checks the module again in a build made for the fuzzer, so it is slow), found nothing wrong; two took more
than its 10 seconds there, and give their `Corrupt` in 50 ms and 3 ms in `sg`.

Measured against zlib (`bench/gzip` and `bench/gunzip`, Apple M3 Max): sixteen megabytes of text compress at
level 6 in 1.04 times zlib's time, and open in 2.60 times it ("Slower than C").

With 1482-1500, 477 of the 1847 programs are compiled on macOS and on Linux (103 under the thread sanitizer), and the
240 programs of the site run as they show; on the Windows Arm VM `ok_compression` prints the same interpreted
and compiled, and the tests of `examples/zlib` pass both ways against vcpkg's zlib.

## 132. The library: zip archives

Choices made in the hundred-and-thirty-second slice (the library: zip archives). 1501-1512 were approved on
20 November 2026, before the slice was written; they say how 1467, 1490 and 1491 are written:

1501. **One enum of errors**, `ZipError`: `NotZip`, `Corrupt(long position)`, `Truncated`, `Encrypted`,
     `UnsupportedMethod(int code)`, `InsecurePath(string name)`, `DuplicateName(string name)`,
     `NameMismatch(string name)`, `Overlap(string name)`, `SizeMismatch(string name)`, `ChecksumMismatch(string
     name)`, `TooLarge`, `Io(IoError)`. An error of inflate becomes one of these, and the position of
     `Corrupt` is a byte of the archive.
1502. **A name that could lead out of a folder** is the same on every system: empty, beginning with `/`,
     holding a `\`, a `:` (a drive of Windows, and its streams: `a.txt:hidden`) or a NUL, a part `..`, or a
     part that Windows keeps for a device (`CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9`, `LPT1` to `LPT9`, in
     any case, with an extension or not). Go, on Unix, takes `:` and the names of devices; Rust's `zip` crate
     (`enclosed_name`) refuses only `..` and a root.
1503. **What is wrong in the structure is found when the archive is opened**: a name that could lead out,
     two entries of one name, data that lie over each other, a count of entries the directory cannot hold.
     `ZipReader.open` gives the error and no reader, as Go 1.20 does by default (Go gives the reader too).
1504. **Encryption and other methods**: such an entry is listed, and reading it is `Encrypted` or
     `UnsupportedMethod`. `ZipEntry.method` is the number the archive writes (0, 8, ...); a writer takes a
     `ZipMethod`, `Stored` or `Deflated`, so it cannot be given another, and `Deflated` is level 6.
1505. **Every entry written takes its time**: `add(name, data, method, modified)`, and so `addFrom` and
     `addDirectory`; a program that archives files gives `FileInfo.modified`, a build that wants the same bytes
     every time gives a fixed time. Read: the field 0x5455 when there is one, in UTC, else the time of DOS
     taken as UTC (as Go). Written: the time of DOS in UTC and the field 0x5455, so every machine writes the
     same bytes; a year DOS cannot hold (before 1980, after 2107) is 1980-01-01 in its fields.
1506. **The central directory is the truth**: the sizes, the CRC-32 and the method are its; the name of the
     header before the data must be its name; an entry whose size is larger than the limit is `TooLarge`
     before anything is opened, and one that opens into more than its size stops there, `SizeMismatch`.
1507. **Limits when an archive is opened**: the count of entries must fit in the size of the directory (46
     bytes each at least) and the directory in the file, before anything is made for them; the comments and
     the extra fields are read and passed over, and not given yet.
1508. **Bytes before the archive** (a program that unpacks itself) are passed over, as Go and Python do.
1509. **`ZipReader.open(path)` and `ZipReader.of(reader)`**: the reader seeks, so it is a file (a pipe is
     `NotSeekable`); the file is closed when the reader ends.
1510. **A writer refuses what a reader refuses**: `InsecurePath` and `DuplicateName`, so what SG writes SG
     reads; Go's writer does not look at names. A name that ends in `/` given to `add` is `Io(InvalidInput)`: a
     folder is `addDirectory`, which puts the `/` at the end when it is not there.
1511. **No reader of one entry as a stream** yet (`reader.open(entry)` giving a `Decompressor`): `readBytes`
     and `copyTo`, which writes a block at a time, do the work.
1512. **Tests**: Go's `archive/zip/testdata`, kept with its licence, archives made by Python's `zipfile` and
     by Info-ZIP's `zip`, a small overlapping bomb made by a script (after David Fifield's), archives written
     by SG opened by `unzip -t`, Python and Go, and a fuzz target `zip`.

Taken while the slice was written, and approved on 20 November 2026:

1513. **`entries()` gives a list of its own**, a copy: a `for` over the reader's own list would hold the
     reader while `readBytes` seeks in it, which the checker refuses. It is made once, and costs the names.
1514. **The bytes of a name** are UTF-8 when they are, else code page 437, the format's first encoding,
     whatever its flag says (a name in another code page of DOS reads with the wrong letters, but reads). The
     time of the change comes from 0x5455, from NTFS's field (0x000A) or from Info-ZIP's fields of Unix
     (0x5855, 0x000D), as Go reads them, the last in the record winning; without them, from DOS's.
1515. **A time of DOS that makes no day** (a date of 0, a month of 13) is 1980-01-01, the first day DOS
     writes; Go turns a date of 0 into 1979-11-30.
1516. **`read` is a word of the language**, so the call that gives an entry's bytes is `readBytes(read entry,
     limit)`, as `File.readBytes(path)` gives a file's. Its limit is an `nint`, as `decompress`'s, and the
     limit of `copyTo` a `long`, as a `Decompressor`'s; a limit below 0 is a panic.
1517. **A directory whose size is written wrong**: Go's rule. When a record of the directory is found at the
     offset the end record writes, no bytes come before the archive, and the directory runs up to its end
     record (two archives of Go's tests are so).
1518. **A data descriptor**: its CRC-32, after its signature or without one, must be the directory's; its
     sizes are not read, since writers do not agree on when they take 4 bytes or 8 (Go reads only the CRC
     too).
1519. **What a writer writes besides**: made by Unix, `rw-r--r--` for a file and `rwxr-xr-x` for a folder,
     with the folder bit of DOS; `add` knows the sizes before the data and writes no descriptor, `addFrom`
     writes one, with sizes of 8 bytes only when one has passed 4 GB (as Go); the field 0x5455 only for a time
     from 1970 to 2038, where the readers that take it as signed and those that take it as unsigned agree; an
     entry is deflated when asked even if stored would be smaller; a name longer than 65,535 bytes is
     `Io(InvalidInput)`.
1520. **One inflater and one compressor**: a reader keeps one inflater for all its entries, its buffers and
     the tables of the fixed codes, and a writer one compressor, restarted for each entry as zlib's
     `deflateReset` restarts it, so the bytes of every entry are those of `Deflate.compress(data, 6)`.
     `readBytes` copies an entry of less than a megabyte out of the reader's buffer, and gives the list a
     larger one was opened into.
1521. **The end record is the last one whose comment fits** in the file; bytes after it are passed over, as
     Go and `unzip` pass them over (gzip's `TrailingData` has no counterpart here: the end of an archive is
     found from the end of the file).
1522. **A message quotes a name**, with what is not seen or drives a terminal escaped as `Log` escapes it, so
     a name in an archive cannot forge what a program prints.
1523. **A file and a folder of one name** (`a` and `a/`) are `DuplicateName` too; Go's `dupdir.zip` holds
     `a/b` and `a/b/`. An empty name is `InsecurePath`; Go takes it.

Asked for on 20 November 2026, after the measurement below, and approved:

1524. **After a short stream the compressor empties only the places of its hash that the stream filled**,
     not all 32,768 as zlib's `deflateReset` does: the window has not moved, so the bytes of the stream are
     still where they were put, and the hash of a place is that of its three bytes, which is what the rolling
     hash gives. The bytes written do not change (3,000 entries of 0 to 6,000 bytes written one after the
     other, each checked against zlib, with a check that the whole hash was empty after every restart). Up to
     1,024 bytes: past about 1.5 KB the places, written one by one, cost more than emptying 64 KB at once
     (10-byte entries 20 % faster, 500-byte ones 5 %, 2,000 bytes and more the same).

Tested by `ok_zip` (an archive written with every call of `ZipWriter` and read back, the CRC-32 of its bytes,
the names a writer refuses, the limit at its edge for `readBytes` and `copyTo`, `ZipReader.of`, `NotZip`, a
missing file), `panic_zip_limit`, and `a_zip_suite` of `tests/cli.rs`, which reads the archives of
`tests/zip-suite` interpreted and compiled: the 33 files of Go's `archive/zip/testdata`, read as Go reads them but
for 1515, 1523 and `NotZip`; 34 made by `make.py`, every name of 1502, two entries of one name, a local name
that is not the central one, sizes that lie, wrong CRCs in the directory and in a descriptor, encryption, a
method not read, DEFLATE that is broken, short or long, a count of entries too large, a directory past the
end, entries at one offset and Fifield's bomb (50 entries of a megabyte from 5.5 KB, which Python opens), a
name in code page 437; and archives of Python's `zipfile` and Info-ZIP's `zip`, read as Go reads them. While it
was written, archives written by SG were opened by `unzip -t`, Python and Go with the same entries and bytes:
one of every kind of entry, one of 70,000 entries (zip64's end record), and one with an entry of 4.4 GB, deflated
and stored, and an entry after it at an offset past 4 GB (zip64's fields); 300 entries of every size and kind
written one after the other each gave the bytes zlib gives for it at level 6. The fuzz target `zip` (`fuzz/`)
opens any bytes as an archive and writes and reads back an input of up to 2 KB.

Measured (Apple M3 Max, release builds): the 70,000 small entries are read in 31 ms (Go's `archive/zip` 90 ms)
and written in 96 ms (Go 42 ms). Writing is zlib's own time: zlib in C, given the same 70,000 entries with a

makes other bytes. Skipping the trees for a short block would change the bytes, so it is not done (1485).

1534. *(Approved, then given up for 1538.)* Pike's machine of a small pattern on the stack, in arrays: an
     array of SG is filled with zeros each time it is made, so a machine on the stack costs a call about as
     much as one taken from the heap.
1535. **An inner text**: when the pattern is read, the plain text every match must hold is found (a run of
     literal characters along a concatenation, inside groups and repetitions of at least one; the one with the
     rarest byte, by a rough table, and the longer of two alike), and a text without it is passed over at the
     speed of `memmem`, by `isMatch` and by every search. Under `(?i)` an ASCII text is looked for in any
     case, a byte at a time; `k` and `s` are left out of it, since they also match `K` (Kelvin, U+212A) and
     `ſ` (U+017F). `-i error` went from 1.16 s to 0.36 s, `in [0-9]{4} ms: .*日本` from 0.83 s to 0.16 s.
1536. **A lazy DFA**, RE2's and Rust's way: a state is the list of steps a match goes on from and what came
     before (the start of the text, a line feed, a character of a word, when the pattern has an assertion);
     its move on a character follows those steps through jumps, splits and assertions, now that the
     character after is known, in Pike's order, and reads it; each state and each move is made the first
     time a search needs it and kept. A row of 129 moves (the ASCII bytes and the end of the text) for each
     state, a map for the characters past ASCII, a state known by where its row starts so that a move is an
     addition and a load, and a loop that follows the moves already made until one is missing. About 4,000
     states (2 MB); past that the cache is emptied and the search goes on, and emptied more than 8 times in
     one search it leaves the search to Pike's machine. `isMatch` uses it: the address took 0.23 s, from
     2.06 s (Rust 0.15 s, Go 1.33 s).
1537. **An `IoError` is written as a sentence**: `not found`, `permission denied`, `is a folder`, `no space
     left`, `invalid text at byte 812`, `system error 5`, `cancelled`, `connection refused`, `connection
     reset`, `address in use`, `host not found`, `line too long`, `already exists`, `not a folder`, `folder not
     empty`, `invalid input`, `message too long`, `cannot seek`; in lower case, as Go's errors, so that
     `$"grep: {name}: {cause}"` reads as a tool's message. Found by `grep` and `wc`, which wrote
     `grep: nope: NotFound` where Rust's write `No such file or directory (os error 2)`. The variants and
     their names do not change; `match` and `==` see them as before. The table is
     `check::IO_ERROR_TEXTS`, read by the interpreter and by the C it writes.
1538. **The states are kept in the `Regex`, behind a lock** (in place of 1534): a `shared locked RegexCache`
     holds the DFAs and Pike's machines of `find` and of `captures`, so `isMatch(read this, ...)` stays as it
     is, a `Regex` in a `static` is searched by any task, and tasks that share one wait for each other while
     its DFA runs (a task that should not wait keeps one of its own). A search takes the lock once
     (`findAll` and `replaceAll` once for all their matches), an uncontended lock costing tens of
     nanoseconds. Asked against `ref this` (no lock, but no search through `read`, nor of a `static`) and a
     cache for each thread (Rust's pool, a new mechanism of the runtime). `find` and `captures` of a short
     text took 3.64 s for two million calls and take 2.63 s with their machines kept.
1539. **Where a match is, by the DFA too**: RE2's three passes. A DFA forwards finds where the match the
     pattern prefers ends: its states keep their steps in the order of preference, a match cuts the steps
     after it as in Pike's machine, and once a match is seen no new one is started. A DFA of the reverse
     program (the concatenations backwards, `^` and `$` swapped, no groups) reads backwards from that end and
     finds the leftmost start. Pike's machine runs only for the groups, from that start. In the first state,
     when every match starts with plain text and there is no assertion, the search goes straight to where
     that text is next (RE2's acceleration of the first state). `findAll` over the 100 MB: `\w+@\w+\.com`
     0.30 s (Pike's machine 2.99 s, Go 2.62 s, Rust 0.08 s), `(?i)error` 0.33 s (1.47, 1.65, 0.02),
     `[0-9]{4}-[0-9]{2}` 0.25 s (2.04, 1.90, 0.04), `\bcache\b` 0.27 s (1.72, 1.50, 0.006), `ş\w*` 0.010 s
     (0.030, 0.031, 0.007), `in [0-9]{4} ms` 0.13 s (0.23, 0.22, 0.04), a plain word 0.04 s as before.

1540. **Zig in the place of Go** (decided after 1533-1539 were measured): SG is in the lane of C, Rust and
     Zig, compiled ahead of time with no collector and memory the program holds and frees, while Go's
     collector and runtime put it in another; so the trials are written in SG, Rust and Zig, and `grep` and
     `wc` were written again in Zig and their Go versions removed. The numbers of Go in 1533-1539 stay as

1542. **Zig is measured twice**: `ReleaseFast`, its fastest, and `ReleaseSafe`, which keeps its checks of

## 134. What the trials found, first: printing

Choices made in the hundred-and-thirty-fourth slice (what the trials found, first: printing). 1543 was
approved on 20 November 2026, after `grep` and `wc` were measured; 1544-1546 the same day, once the cost of
`print` had been taken apart:

1543. **The differences the trials found come first**, before the next trial, in this order: printing (the
     runtime, every program), reading lines and searching for a plain text (`-c timeout`), the reads of the
     DFA's table checked against its end (to be taken away by the compiler where it can show the read is
     inside, not by `unsafe` in the standard library), and a search in any case with the processor's vector
     instructions. Each is made where it serves every program, never as a trick for one, and after each
     the programs of `bench/` and the whole of the tests run again.
1544. **A line is written piece by piece where it is printed**: a `$"..."` given to `print` or to
     `s.write(...)` is taken apart by the compiler into its texts, numbers, characters and `bool`s, each
     added straight, where `sg_vlines` read the format at run time; a text written alone (`out.write(line)`)
     is one copy. The values of the line are computed first, from left to right, as they were computed
     before `printf` ran, so a value that reads the text being written sees it as it was, and one that
     panics leaves no part of the line written. A width or a count of digits (`{x,8}`, `{n:X4}`) still goes
     through `sg_vlines`; so does `$"...".toString()`, which counts before it writes.
1545. **The output has a block of 64 KB of the program's own**: what `print` and `Stdout` write is gathered
     there and given to C's `stdout` when the block is full, when the program ends (`atexit`, so by
     returning, by `exit` and by a panic), and before anything else writes where the output may go:
     `printError` and `Stderr`, another program started, a read of a terminal, a call of C (whose `printf`
     writes into C's `stdout`) and the return of an `export` function to C. Into a terminal each call is
     given on at once, as C gives a line. Writing the output keeps `errno` and Windows' last error as the
     program's own calls of C left them. The interpreter, which wrote its own output in order already,
     gives C's streams on after each call of C and when an `export` function is entered, and on Windows
     puts them in binary mode as compiled code does: a `puts` inside a program came out at its end, and
     with `\r\n` on Windows.
1546. **One lock of the program's own for the output**, on every program, taken for each call: one atomic
     operation when nobody else holds it (`os_unfair_lock` on macOS, a slim reader/writer lock on Windows,
     pthread's elsewhere), where `flockfile` and `fwrite` took C's twice. Not left out where the program
     has no threads: a thread of C may call SG back. A panic takes it and keeps it, as it keeps C's streams.

## 135. A `print` that cannot write

Choices made in the hundred-and-thirty-fifth slice (a `print` that cannot write), approved on 20 November
2026:

1547. **Compiled code ends where it cannot write the output, as the interpreter ends**, as "`print` error" in
     `design/04` has it: compiled, a full disk was silent and the program ended with 0. What the block of
     the output holds is checked wherever it goes out with no `Result` to tell the error to: at `print`,
     before `printError` and `Stderr`, another program started, a read of a terminal and a call of C, and
     at the end of the program, where an output shorter than the block is written for the first time and
     C's `stdout` is given on too (after `exit` as well). The program ends with `error: cannot write
     output: ...` and 1, the message the interpreter writes on Linux and macOS (C's text of the error and
     its number; on Windows C's text, where the interpreter writes Windows'). A pipe whose reader is gone
     ends it silently: by `SIGPIPE`, set back to its default first as the interpreter sets it (1330), so
     also when the program was started with the signal ignored, and with 0 on Windows. An output that was
     never open (`>&-`) takes what is written and drops it, as the interpreter's, which is Rust's, does.
     `Stdout`'s own calls still give the error in their `Result`, and the program goes on. Rust's `println!`
     panics where it cannot write, but what is still in its block at the end is dropped silently; C looks
     at nothing; Zig returns the error. Cost: nothing on the way of the bytes; one branch at the end of
     each `print`, and one `fflush` more at the end of the program.

1548. **`ok_lock_when_async` waits for both of its producers**: whichever ended first set the list done,

     the pauses and the address sanitizer on Windows x64). The fault was the program's, not the lock's:
     `main` now marks the list done after both, with an ordinary `lock` from a task, as before.

## 136. What the trials found, second: reading lines, searching for a plain text

Choices made in the hundred-and-thirty-sixth slice (what the trials found, second: reading lines and
searching for a plain text, `grep -c timeout`), approved on 20 November 2026:

1549. **A plain text is looked for by its two rarest bytes**, sixteen starts at a time: `indexOf`,
     `contains`, `split` and `replaceAll` with a text, and a regular expression that is a plain text or
     holds one (1535). Compiled code looked for the text's first byte with `memchr` and compared the rest
     wherever it was, so a text whose first byte is common stopped at each one: `timeout` at every `t`,
     one byte in 38 of the trial's log. The bytes of the text are now ranked by a table of how common each
     byte is (`sg_byte_rank`, made by `tools/byte_rank.py` from the text and code the repository keeps),
     and its two rarest are compared at sixteen starts at once with the processor's vector instructions
     (the C compiler's vectors, SSE2 on x64 and NEON on Arm; a start at a time where it has none); only
     where both are found is the text compared. A single byte is still `memchr`'s. As Rust's
     `memchr::memmem`, which its `str::find` and `regex` use, with a table of its own. Measured on the 100
     MB of the trial, the time the search adds to splitting the lines: `timeout` 29 ms to 10.5,
     `connection` 27 to 13, `in 1234 ms` 39 to 9, `ERROR` 16 to 8.5; a text whose first byte is already
     rare and found early in the line takes a little longer, `INFO` 6 ms to 11 and `@example.com` 2 to 7.
     `grep -c timeout` takes 0.049 s, where it took 0.073 (Rust and Zig 0.066). Cost: the table, 256 bytes.
1550. **UTF-8 is checked by going straight to the first byte past ASCII**: of sixteen bytes that hold one,
     the count of the zero bits below its high bit gives its place, where the bytes before it were read one
     by one. The trial's log, with a character past ASCII every forty bytes, is checked in 10 ms per 100 MB
     where it took 15 (Rust's `str::from_utf8` 14 ms): every `readLine`, `readText`, `string.fromUtf8` and
     reader of text has it. No vector instructions, so nothing to look for when the program starts (the
     candidate of "Slower than C").

The programs of `bench/` were all measured again on macOS after both: `lines` 0.077 s to 0.070, `rewrite` 0.58 to
0.53, `asynclines` 0.113 to 0.104, `netlines` 0.095 to 0.088; the others as before. `fields` first took 1.2
times as long, since the longer search, put inside `split`'s step by the C compiler, kept that step out of
the loop; the longer search is now a call the compiler keeps apart, and `fields` takes its time again.

Tested besides: `ok_find_text`, 16,000 searches in texts of up to 80 pieces of one to three bytes, a few
kinds of piece at a time so that the two bytes are found often, held to a search byte by byte, and a text
of a hundred `t`s; `ok_utf8_check`, 6,000 runs of bytes with characters of two, three and four bytes, `0xFF`,
a character cut off, an encoding too long and a surrogate at every place of a block, held to a check byte by
byte. Both run interpreted and compiled. The new `sg_find` and `sg_utf8_valid` were held besides, in a
program of C, to a search and a check byte by byte on twenty million texts, under the address and undefined
behaviour sanitizers, with the vector instructions and without them (`-mgeneral-regs-only`). With 1549 and
1550, 483 of the 1853 programs are compiled on Linux, all clean under the sanitizers (107 under the thread
sanitizer), and the whole of the tests passes on macOS and on Linux.

Approved the same day, for what comes next:

1551. **XML is not in `std`**, in place of 1413. A format few programs need, with a large surface for
     attacks, goes into a package of the language's own, kept outside `std` and given versions apart from
     the language, as Go keeps `golang.org/x/`. JSON, compression and regular expressions stay in `std`; each
     new library of a format or a protocol is asked the same question before it is written.
1552. **Packages without a registry, as Zig's and Go's, and next**: a package is the URL of a repository and
     a version tag, pinned by the SHA-256 of its contents in a file of locks; the versions are chosen by Go's
     minimal version selection, so a new release changes no build; they are fetched by the system's `git`,

## 137. Packages, first: the project file, packages from folders, `internal`

Choices made in the hundred-and-thirty-seventh slice (packages, first: the file of the project, packages

1564. **The commands**: `sg add URL[@1.4]` takes the newest tag that fits, writes both files and shows the

## 140. The second safety review, second: the rules of borrowing

Choices made in the hundred-and-fortieth slice (fixing what the second review found, second: the rules of
borrowing). The review showed that each fix of 1340 closed the shape it was shown and left the shapes
beside it open; one fix had opened a fault of its own. So the rules are made rules here, not cases, each
the way Rust has it, and each after a test that showed its fault (each program below compiled, before,
into C that read freed memory under the address sanitizer):

1592. **The rules of borrowing, made whole**:
     - **A `break` or a `continue` ends the blocks between it and its loop**, as their ends do. Since
       the state of borrows joined branches (1340), a borrow taken on a way that leaves by `break` or
       `continue` (`if i == 1 { r = read b; break }`, `b` declared in the loop) was forgotten where the
       branch was left and came back after the loop, its owner gone: an error again, as it was before
       1340, also for `break outer`, an arm of a `match` and the names of `read ... as`.
     - **A `ref` given on as it is lends it again, to be changed**: `wipe(xs)` with `ref List<string>
       xs` (a parameter, a variable or a field) changes `xs` as `wipe(ref xs)` does, so a `read xs[0]`
       held over the call is an error, and the same `ref` given to two `ref` parameters, or beside a
       `read` of it, is lent twice. So is a `ref` copied into a variable (`var b = w.items`): two
       copies of one `ref` are not both used. Rust's implicit reborrow of a `&mut T`.
     - **A `ref` field reached through a `read` borrow only reads** there, as `&&mut T` does: with
       `read W w`, `w.items` is not given to a `ref` parameter, copied into a variable or put into a
       `ref` field (an error with the hint `read w.items`). 1340 had made writing through it an error,
       and copying it out gave the `ref` back.
     - **Giving away a value that holds a `ref`** (as `ref`, by value, to its own `ref this` method)
       **changes what it borrows**, and so does its `dispose`: `wipe2(ref w)`, `consume(w)`, `w.clear()`
       and the end of a `Guard` that empties its list are changes of the list `w.items` borrows.
     - **A part of a value with no name carries what the value borrowed**: `wrap(read text).text`,
       `two(read text)[0]` and `pair(read text).second.me()` borrow `text`, and a function that returns
       one of them returns a borrow of its own local; the borrow was lost before.
     - **Every value made of parts computed from left to right lends them until it is made**, as a call
       does (1340): a struct (`Word { text = read xs[0], n = g(ref xs) }`), `with`, a variant, a list, a
       comparison (`xs[0] == take(ref xs)`), `??` and `$"..."`. `s == change(ref s)` is an error too
       now, as in Rust, though it read no freed memory: which `s` it compares depended on the order.
     - **An argument that looks at a place another argument lends as `ref` is an error**:
       `Hex.encodeInto(ref s, s.asBytes())`, `grow(ref s, s[1..])`, `fill(ref doc, doc.get("k")?.asString()
       ?? "-")`; the call may move what it changes while it reads the view. Only one written `read s` was
       found before.
     - **A borrow put where no variable of the function is**, into what a call gave
       (`map.getOrAdd(k, v).add(Word { text = read text })`, `pick(ref all).add(...)`), or through a `ref`
       field (`w.items.add(...)`), **is held by what that place borrows**, `map` and `all`; it was kept
       nowhere, or by the carrier, which ends first.
     - **The names `for`, `is` and `match` give out of a `shared` value end with their statement**, as
       the names of `lock` do: another owner may change or end the value after it (`b.clear()` with `var

## 142. The second safety review, fourth: modules of `std` that read what others write

Choices made in the hundred-and-forty-second slice (fixing what the second review found, fourth: the
modules of `std` that read what others write). The review gave each of them input made to hurt it; what it
found that compiled code and the tool must fix (a line of `Log` that is not one write, a search for a long
text that repeats, `printError` to a pipe that is gone) waits for 1595:

1594. **The readers of `std` hold on what an input gives them.**
     - **Compression**: `readLine` and `readText` of a `Decompressor` ask for more of the stream when a
       line or a character is cut by what is ready; they looped for ever on a last line with no `\n`, a
       line longer than a block of 64 KB and a character cut by one (all ordinary files). A limit of
       `long.MaxValue` overflowed. And a symbol of codes is begun only with 48 bits held while more input is
       to come: a valid stream whose long codes (a length of 20 bits and a distance of 28) met the end of
       the reader's block was `Truncated`, in `Deflate.reader`, `Gzip.reader` and `ZipReader`, though
       zlib, `gzip` and `unzip` read it. Its test (`ok_compression_streams`) writes such streams with a
       generator that follows the bits the inflater holds, one for each number it may hold where codes
       begin, and the code before this slice refuses all five.
     - **Regular expressions**: `x*` counts its body among the 100,000 steps of the limit, as `x{n}` did
       (`((a{1000})*){1000}`, a program of a gigabyte, is `TooLarge`, also when it is compiled); each DFA is
       emptied at about 2 MB counted in the bytes of its states and moves, which its page promised and a
       count of 4,000 states did not keep (a state of 100,000 steps: 1 GB, now 26 MB); the slots of the
       groups grow with the threads of Pike's machine that are alive, kept by thread, not with the program
       (4,000 empty groups: 1 GB, now 4 MB); a `[:` with no `:]` in a class is looked for once, not to the
       end of the pattern at each; the items of a class with `(?i)` are folded once, when the class is
       finished (`(?i)[\p{Lu}\p{Lu}...]`: 570 MB, now nothing more than one); and a repetition after
       `\Q...\E` repeats its last character, or what came before an empty `\Q\E`, as Go and RE2 do (it
       repeated the whole text). A pattern that keeps many threads alive with many groups, `(a?)` written
       4,000 times, still takes their product, 520 MB, as Go's 540 MB (Go is 7 times faster there).
     - **Zip archives**: a name is refused by the rule of `Path.joinInside`, part by part (`./x`, `a//b`,
       `x.txt.`, `dir./f`, `lpt0`, `CONIN$`, C1), so a name `ZipReader` gives is one `joinInside` takes, and
       `InsecurePath` says "or name another file on another system"; two names that differ only in case
       are `DuplicateName`, as macOS and Windows take them for one file. Two names in different Unicode
       forms of one text are not compared, since `std` has no normalization: written in the library page.
       (They are compared since the hundred-and-forty-seventh slice, 1615.)
       An NTFS time before 1684 or past 2255, and a locator of zip64 past 2^63, are no longer panics (41
       of 6,000 archives changed at random were; none now).
     - **Paths**: `joinInside` refuses the control characters of C1 too, and on Windows `\\?\UNC\` is
       read byte by byte, so a character of several bytes there is no panic (135 of 4,000 paths, run on a
       copy of `path.sg` with the rules of Windows).
     - **What a person reads**: `UnicodeCategory.hides`, one list for the library, says which characters a
       reader does not see or that drive the text around them (the control characters, every character of
       format, the separators of lines and the fillers), and a line of `Log`, a key of JSON in an error,
       the name of an entry of a zip archive and a word of the command line in an error have them escaped
       (`\u061c`, `\u{e0041}`); `Log` let through the tags, the soft hyphen and the Arabic letter mark, JSON
       and the command line wrote them as they were.
     - **The command line**: the nearest name is looked for only among names of about the length of the
       unknown word: a word of a megabyte took a minute in the interpreter, now 2 ms.
     - **Written down, not changed**: `JsonObject.remove` keeps the order, so it is linear, as
       `IndexMap.shift_remove`; a JSON text takes 50 to 200 bytes a byte once read, as a tree of values
       does in Go and Rust; `toJson` writes any depth and `Json.parse` reads 128. Each in its page.
       (Since the hundred-and-forty-eighth slice, 1600, `toJson` writes 128 too.)

Tested by `ok_compression_streams`, `ok_regex_limits`, `ok_text_hidden` (new), and by
`ok_command_line`, `ok_path_roots` and `ok_path_join_inside` (with their Windows output), the archives

## 143. The second safety review, fifth: compiled code and its runtime

Choices made in the hundred-and-forty-third slice (fixing what the second review found, fifth: compiled
code and its runtime, where they did not do what the interpreter does). Each was shown red first, with the
review's own programs:

1595. **Compiled code does what the interpreter does.**
     - **An assignment whose place is reached through a call** (`b.next().name = text`, `b.me().n += 5`)
       made the call twice, once to drop the old value or read it and once to write: the borrow the call
       gives is now kept in a temporary, so the call is made once (it freed the wrong item's name, a use
       after free under the address sanitizer).
     - **A field that borrows is pointed at something else**, as a `read` variable is: `slot.text = read
       other`, `view.it = read b`, `edit.it = ref d`, `maybe.it = null`, `bytes.data = more[1..]`. The C of
       each did not compile; the back end wrote what the field points at, as the type it points at.
     - **A standard stream closed when the program started** (`program >&-`) is opened on `/dev/null`
       first, on Linux and macOS, as Rust's runtime does for the interpreter: the first file the program
       opened took the number of the closed stream, and what `print` wrote went into it.
     - **A line of `printError`, and so of `Log`, is one write of the system**, however long: compiled code
       wrote a line past 512 bytes in pieces, and the interpreter wrote its `\n` apart, so four programs
       appending to one file mixed their lines (1,625 of 2,000 lines of 2 KB compiled, 39 interpreted;
       none now). A line is gathered on the stack and, past 512 bytes, in memory of its own; a panic's
       message is one write too.
     - **A long text that repeats, looked for in a text that repeats it** (`indexOf`, `contains`,
       `lastIndexOf`), was compared whole at every place its two rarest bytes were found, which took time
       that grew with the square of the text (1.6 MB: 6.4 s). Past a budget of comparing, sixteen bytes
       for each start passed and 64 KB more, the rest of the search is Two-Way (Crochemore and Perrin), as
       Rust's `memchr::memmem` turns to; `lastIndexOf` runs it from the end. The same 1.6 MB: 0.01 s. An

       show in a measurement.
     - **The header of a library** named a plain struct in the type of a pointer to a function before it
       declared the struct (`struct Leaf { CFunc<raw Leaf, int> get }`), and C did not compile it: every
       plain struct such a type names is declared first.
1601. **A standard error whose reader is gone ends the program by `SIGPIPE`** on Linux and macOS, as
     `print` does (1330) and as C's and Go's programs end, also when it was started with the signal
     ignored; on Windows the line is lost and the program goes on. The interpreter went on and compiled
     code ended: the two did not agree.
1602. **A panic in a program whose output was closed early is told**, and the program ends with 1:
     compiled code ended by `SIGPIPE` while it gave out what was printed, before it wrote the panic, where
     the interpreter told it. A panic leaves the signal out from its first line.
1603. **`main`'s error comes first**: a `main` that ends with an error when the output cannot be written

     output's and the interpreter only the program's; a pipe whose reader is gone is not told.
