## 186. A static program with musl, set aside

`sg build` makes one file, the program, its modules and the runtime compiled together; only the C library of the
system is linked when it starts (glibc on Linux, libSystem on macOS; on Windows the C runtime is inside the
program already). A container of it starts from an image with glibc, where a program of Go starts `FROM scratch`.
Approved on 26 November 2026, for a build with nothing outside it:

1927. **`sg build --static`.** The default build does not change. `--target` is not used for it.
1928. **On Linux with musl; on macOS an error** (libSystem is the only C library there). On Windows as 1942 says.
1929. **The C compiler that links musl:** the one `CC` names; on a system whose own `cc` builds for musl (Alpine),
     that one; else `musl-gcc` on the `PATH`; without one, an error with what to install. sg does not carry musl.
1930. **The libraries of `extern` blocks only as static archives;** with none, an error that names it, never a
     shared library in its place.
1931. **`--static` with `--test` is allowed; with `--library`, `--shared` or `--freestanding` it is a usage error.**
1932. **Where the C library has no `posix_spawn_file_actions_addclosefrom_np`** (musl, glibc before 2.34), the
     descriptors are marked close-on-exec before a spawn: `close_range` with `CLOSE_RANGE_CLOEXEC` (Linux 5.11),
     else through `/proc/self/fd`, else each number up to the limit of open files.
1933. **Tested** on the CI and on Alpine, each program looked at for a loader and for libraries it names.
1934. **Measured:** the server lane and a program that allocates much, glibc against musl, published whatever the
     result; a large loss is a choice of its own.
1940. **No `--target` for programs.**
1942. **On Windows `--static` is accepted** (the C runtime is linked into every program already); a library of an
     `extern` block that is a DLL is an error.

It was built, and the programs of the golden tests ran built static, on Linux and on Alpine. Then it was measured
(1934), on Linux in the container of the server lane, 8 cores. A program that allocates much, the best of five
runs, the release build:

| Program | glibc | musl | |
|---|---|---|---|
| `list`: a linked list of a million nodes, twenty times | 0.263 s | 0.417 s | 1.6 times slower |
| `tree`: a tree of 111,111 folders, `shared` and `weak` | 0.113 s | 0.170 s | 1.5 times |
| `words`: words copied onto the heap and freed | 0.687 s | 7.003 s | 10 times |
| `blocks`: pieces gathered into one buffer | 0.038 s | 0.035 s | the same |
| `tasknodes`: the list of `list` on four tasks at once | 0.081 s | 3.690 s | 45 times |
| `tasklist`: lists of tasks | 0.699 s | 0.829 s | 1.2 times |

The same programs in C lost as much: the cost is musl's `malloc` and `free` (one heap behind a lock, where glibc
keeps an arena for each thread), not SG's. The servers of the lane, which allocate little for a request, kept their
rate for the store (1,290k against 1,368k answers a second with 50 connections; 2,078k against 2,049k with 16 in
flight) and held less memory (2.4 MB against 3.9 MB), but an idle connection took 5.73 KB against 4.97 KB; the HTTP
server lost a quarter (1,350k against 1,017k a second with 50 connections, 110k against 85k with a connection for
each request); and with 10,000 slow clients the p99 of the store went from 192 µs to 4.1 s.

The loss is large, so by 1934 it was a choice of its own, and on 26 November 2026 the slice was **set aside**: a
program is built for Linux, macOS and Windows on each of them, and the C flags of the next slice (1935-1942)
give what a build needs now. The work stays on a branch of its own, not merged (`slice-186-static`): the flag, the
compiler of 1929, `-static-pie`, the golden programs built static (`SG_TEST_STATIC=1`), the CI step, `bench/run.py
--static`, the bench `tasknodes` and `sg-musl` in `measure.py`. What it found on the way is written there: Debian
puts musl's loader in `/lib` beside glibc's, so whether `cc` builds for musl is asked of `cc -dumpmachine`;
`musl-gcc -print-file-name` names archives its linker does not take; a static program has no loader, so `dlopen`
finds nothing; musl writes a null `%p` as `0`; rustup's Rust links `sg` itself for musl statically, with a musl of
its own that has no `renameat2`. When it comes back, a faster allocator in front of musl's is the first question.

**Built now: 1932,** which is right for every program on such a C library, static or not. A program built with
glibc 2.34 or later closes the descriptors in the spawn as before; one built with musl, or with an older glibc
(RHEL 8 has 2.28), handed a descriptor 7 open and not close-on-exec, gave it to every program it
started. Now `sg_proc_close_on_exec` marks them first; a library of C (`--library`, `--shared`) leaves the
descriptors of the program it is in as they are. **Test:** `cli.rs` `a_started_program_gets_no_other_descriptor`
starts the program with descriptor 7 open and has it start `ls /proc/self/fd`, which sees 0, 1, 2 and its own:
built by `sg build`, and linked with `musl-gcc` where it is installed (the container of the tests and the CI have
it now). Without the change the musl program hands 7 on.

## 187. Flags of C on every build

Flags of C were taken only for a machine without an operating system (`--freestanding -- -mcmodel=medany`); a
program could not be built with `-O3`, `-march=native`, `-flto` or `-g` without going through `emit-c` and the C
compiler by hand. A programmer of systems wants them, and some of them change what the language promises.
Approved on 26 November 2026, to give them out safely, with a warning where they are dangerous:

1935. **`sg build app.sg -- <flags of C>` on every build:** a program, `--test`, `--library`, `--shared`,
     `--freestanding`. `emit-c` with `--` is a usage error (it compiles nothing). No variable of the environment.
1936. **sg's flags first, the user's after,** so that the last written wins (`-O3` over `-O2`). `-Wl,`, `-l`,
     `-L` and `-I` go in the same list.
1937. **Three kinds.** Given quietly, unknown ones too: `-O*`, `-march`, `-mcpu`, `-mtune`, `-flto`, `-g`, `-s`,
     `-fsanitize`, `-fno-omit-frame-pointer`, `-D`, `-I`, `-l`, `-Wl`. Given with a warning: what changes
     fractional results (`-ffast-math`, `-Ofast`, `-ffp-contract=fast` or `on`, `-funsafe-math-optimizations`,
     `-ffinite-math-only`, `-fno-signed-zeros`, `-freciprocal-math`, `-fassociative-math`, `-mfpmath=387`); what
     takes a guard away (`-fno-stack-clash-protection`, `-Wl,-z,execstack`, `-Wl,-z,norelro`); a setting of SG's
     runtime (`-DSG_*`, `-USG_*`). Refused: what sg owns (`-o`, `-c`, `-S`, `-E`, `-x`, `-std=`, `-shared`,
     `-static`, `--target`), and what changes the size of a type or the layout of C (`-m32`, `-mx32`,
     `-fshort-enums`, `-fpack-struct`, `-fshort-wchar`, `-funsigned-char`, `-fsigned-char`).
1938. **The warning is one line on every build, and cannot be silenced:** `warning: -ffast-math: fractional
     results may differ from the interpreter's and between machines`.
1939. **A flag of C turns off no check of SG:** overflow and the other checks of a debug build are left out by
     `--release` alone, and the documents say so.
1940. **Programs have no `--target`:** building for another machine stays out of scope.
1941. **On Windows the same rules, written as GNU writes them** (Clang is the driver), not as MSVC (`/O2`).

(1942 was a change to 1928, the `--static` of slice 186, set aside with it.)

What was built. `sg build` keeps what follows `--` for every kind of build and judges it before anything is
compiled (`sg::cc::judge_flags`): a refused flag is an error with exit code 2 that says why (`error: -m32 in the
C flags: it changes the size or the layout of C's types, which the C that sg writes, and the libraries it calls,
are written for`); a flag with a warning is said on the standard error each time, one line for each. A flag and
the word after it are read together, so `-D SG_COUNT=0`, `-z execstack` and `-Xlinker norelro` are seen as
`-DSG_COUNT=0` and `-Wl,-z,execstack` are; `-Wl,` is split at its commas. The flags go last on the line of the C
compiler, after the C file, the libraries and the system's, so that a `-l` of them links and the last `-O` wins.
`-static` is refused as a program that is not built yet (186). A build that the C compiler refuses with flags
given names them (`error: the C compiler did not build the program with the C flags given after --: ...`),
not "a mistake in sg". `--freestanding` keeps its flags, now judged as every build's.

**Tests.** `cc::tests::flags_of_c_are_given_warned_or_refused` (the three kinds, flags in two words, the
`-Wl,` forms); `cli.rs` `builds_with_flags_of_c` (a program with `-O3 -g` runs, the program of tests, a static
and a shared library; two warnings on each of two builds; seven refused flags, 2 and nothing written; an
unknown flag named; a debug build with `-O3` still stops on an overflow and a release build with `-O0` still
wraps); `refuses_what_is_not_a_usage` has `emit-c -- -O3` in place of `build -- -Os`, which is now a build.

## 188. A compiled program in the debugger

A debug build carried what a debugger reads only on Windows, and the C named no line of SG: gdb and lldb could
stop only on lines of a C file that was written into a temporary folder and gone when the build ended. A
language for systems is debugged in the system's debugger. Approved on 26 November 2026:

1943. **A debug build carries what the debugger reads, on the three systems:** `-g` on Linux (inside the
     program), on macOS (`x.dSYM` beside it, which the C compiler makes) and on Windows (`x.pdb`, as before).
     `--release` carries none; `-- -g` gives it. Rust's dev profile carries it and its release profile does not.
1944. **The C names the line of SG of every function and statement** (`#line N "/absolute/path/a.sg"`), in a
     debug build and a release build: without `-g` nothing of it reaches the program, and with it an optimised
     build is debugged on the lines of SG. The path is absolute, since the C compiler runs in a folder of its
     own that is gone when the debugger reads the program; a program built so names the full path of its files,
     as Rust's do (Rust has `--remap-path-prefix`, which SG has not yet).
1945. **What has no line of SG names the C file:** the runtime, the helpers and C's `main` (`#line N "a.c"`), so
     that a step never lands on a wrong line of SG.
1946. **The names stay those of the C** (`v_total_1`, `f_sum`, `m_x`), with a table on the site that says how to
     read them. They are not given the names of SG, which would meet C's keywords and the macros of its headers
     (`errno`, `stdout`, `int`); Nim, which compiles through C too, keeps such endings.
1947. **The language's own module and packages get lines too,** under the names messages give them
     (`<built-in>/std/files.sg`): the debugger shows the line, not the text, as Rust's does without `rust-src`.
1948. **Tests:** lldb on macOS and gdb on Linux (gdb joins the image of the tests and the CI), each in batch: a
     stop on a line, a stack of two frames of SG, the variables, a stop in a file of a module, and once a release
     build given `-g`; on Windows the `.pdb` names the files of SG.
1949. **Documents:** a chapter of the book, "Debugging a program", with the building chapter, 06, this record
     and *Not here yet*, where the row of `setLength`, built in slice 175, is taken out.

What was built. Each statement the back end writes is preceded by a mark of its line and of the number of its
file (`#line 4 @0`), and each function by the line of its name; a function ends with a mark that gives the C
its own lines back. The marks hold no path, so that the C that is searched for names while it is written
(what allocates without a system, the state of an async function) holds no text of one. At the end
(`place_lines`) each mark becomes a `#line`, with the absolute path of its file written as `#line` takes it:
the bytes of UTF-8 as they are and only `\\`, `\"` and `\?` escaped, since Clang refuses a number of a byte
(`\303`) there. `#line N` numbers the lines after it N, N + 1 and on, so each line of C a statement takes after
the first is given its line again (`#line 4` with no file). The columns are left out (`-gno-column-info`), as
they would be those of the C. `sg::source::program_name` names the C file (`main.c`, or the folder's name), for
`sg build` as for the libraries. The tokens the state of an async function is found from now pass over a line
of the preprocessor: with the marks, a variable was no longer seen as declared, stayed a local of the function
that polls, and was lost at an `await` (a file opened async read a closed descriptor; found by
`opens_only_a_regular_file` and the servers of `cli.rs`).

In an optimised build a line that only computes may have no place of its own: the arithmetic of SG is in
helpers of the runtime that the optimiser inlines, whose instructions keep the lines of the C, so a line of
SG is found where it calls. That is the cost of debugging optimised C, and the chapter says so.

**Tests.** `tests/debugger.rs`: a debug build in lldb or gdb, run from another folder so only the absolute path
finds the source, in a folder of the temporary folder whose name has a space and letters that are not ASCII
(`çalışma klasörü`; not under the repository, since on macOS a program lldb starts waits for leave to open a
file under `~/Documents`, and the test waited for ever): a stop
at `total += x` with `f_sum` and `f_main` on their lines of `main.sg`, the variables, the line shown, then a
stop in `shapes/area.sg` with its parameters; a release build given `-g` stops on the line of a `print`; a release
build names no file of SG and has no `.dSYM`; the C names the language's own module, gives absolute paths, and
each `#line` of the C file names the line after it; on Windows the `.pdb` names `main.sg`, `area.sg` and the
folder in UTF-8. mac (lldb), Linux in podman (gdb) and the machine of Windows on Arm.

## 189. Names of the system that are not text

A `string` is always UTF-8, and a name of the system is not: on Linux and macOS a name of a file, a word of the
command line or a variable of the environment is any bytes, and on Windows any units of UTF-16. A word that was
not UTF-8 stopped the program before `main`, one such name made `Directory.list` fail for the whole folder, and
`Environment.get` gave `InvalidText`: a `find`, a `tar` or an `rsync` could not see or open such a file. Go and Zig
take text as bytes, Rust has a type of its own (`OsString`), Python writes what is not UTF-8 as characters that go
back to their bytes (PEP 383). The way was chosen first, with three others beside it (bytes forms of each call
beside the text ones, a type of names of its own, or only softer errors); approved on 26 November 2026:

1950. **The escape:** from the system to SG, the bytes are read as UTF-8, and a byte that is no part of a
     character, and each byte of a character from U+10FF80 to U+10FFFF, is written as the character U+10FF00 +
     the byte (U+10FF80 to U+10FFFF); from SG to the system, each such character is its byte, the rest is UTF-8.
     So every name goes and comes back as it was. On Windows names are carried as WTF-8, so a half of a pair
     alone is three bytes that are not UTF-8 and goes back alone: one rule for the three systems.
1951. **Every name of the system, in the interpreter and compiled:** the words of `main`, the names and values
     of the environment, the names in a folder, the current folder, the temporary folder, every path given to
     a call of files, folders and programs, and the program and words of a started program (with `PATH` and
     `TMPDIR` as they are read). Not what a file, the input or the network holds, nor `string.fromUtf8`: that is
     data, and stays `InvalidText`.
1952. **`Path.systemBytes(read string name) -> List<byte>`** gives the bytes the system is given, to write a
     name as it is (`ls`, `find -print0`); **`Path.fromSystemBytes(read byte[] bytes) -> string`** gives the text
     of bytes, for a name read out of data (an entry of an archive, a line of `-print0`), and never fails.
1953. **Such a character is text:** `print` and formatting write it as UTF-8, with no case of its own.
1954. **A text not made from a name** that holds such a character becomes its byte when it goes to the system,
     without an error. Only bytes from 0x80 come out, never `/`, `\`, `.`, `:` or a zero byte, so a check of a
     name against those still holds.
1955. **What no longer fails:** a word of the command line no longer stops a program; `Directory.list`,
     `Directory.current` and `Environment.get` no longer give `InvalidText` for a name; `VariableError` keeps
     `Missing` alone. `IoError.InvalidText` stays, for what a file holds.
1956. **Made the same on the way:** the temporary folder of Windows, which the interpreter gave with U+FFFD and
     compiled code refused (its buffer held only `MAX_PATH`); a long path of the interpreter on Windows, made
     whole through a text that lost a half of a pair; sg's own words (the program, `-L`, `-o`), which were
     read with U+FFFD; and the copies compiled code makes of the words and the environment of a started
     program, which now end the program on a zero byte instead of cutting the text short (the language's own
     module refuses one before).
1957. **Tests,** as below.
1958. **Documents,** as below.

Approved the same day, after the slice was built:

1959. **On Windows a byte that no WTF-8 has** (a character from U+10FF80 written in a text, not made from a name)
     is U+FFFD when the name is given to the system: a name of Windows is units of UTF-16, and such a byte is
     none.

What was built. The interpreter has the two ways in `names.rs` (`text_of`, `bytes_of`, `os_of`), on `utf8_chunks`;
each call of the system takes its path through `os_of`, the names it gives back through `text_of`. The C runtime
has `sg_name_escape` (two passes: a name that is text is kept as it is, with no copy), `sg_name_unescape` (a
character of the escape is `F4 8F BE` or `BF` and one byte, so it becomes its byte in place) and, on Windows,
`sg_name_wide`, which reads WTF-8 itself, since `MultiByteToWideChar` makes a half of a pair U+FFFD. `sg_path`,
`sg_wide`, the copies of a started program and of the environment unescape; the words of `main`, a listing,
the current and the temporary folder escape. `System.nameBytes` and `System.nameText` are the two calls of the
compiler behind `Path`. `std/log.sg` read `SG_LOG` with a case of its own for a value that was not UTF-8; such a
value now names no level, as any other. `trials/std/environment` printed `not text` for `caf\xe9`; it prints the
value now, and its numbers, taken on 23 November with the old error, were not measured again.

**Tests.** `names::tests` (every byte from 0x80 between two letters, cut short, overlong, a half of a pair, past
U+10FFFF, the escape's own UTF-8, a text written with a character of the escape, 100,000 random names both ways,
WTF-8 of halves of pairs); `ok_path_system_bytes` (the same cases interpreted and compiled, which must agree);
`ok_environment` (a value and a name that are not text, set through C: bytes on Linux and macOS, a lone
half on Windows); `tests/names.rs`: words of the command line that are not text given to the program
interpreted and compiled, and a folder of 136 names (on Linux every byte from 0x80, six broken sequences and two names that are UTF-8;
on macOS, whose APFS takes only UTF-8, the names of the escape's own range; on Windows four names with halves
of pairs), each listed, read, looked at, given as the word of a started program that writes its bytes back,
moved and deleted. Run on macOS, Linux in podman and the machine of Windows on Arm.

## 190. Sockets of the machine, the options of a connection, one side closed, pieces written to a file

What a program of the system needs of its connections and SG did not have: a socket at a path of the machine
(what a server behind nginx, Docker's API or a database on the same machine listens at), the side that sends
closed alone, `TCP_NODELAY` (now on by default) and keep-alive, a listener on every v6 address that does the same on every system,
and several pieces written to a file with one call. Approved on 26 November 2026:

1960. **`UnixListener` and `UnixStream`,** two types of their own, as Rust has them: the names say what they are.
     The cost, said when it was chosen: with no interface of the program's own, a server that listens at a port
     and at a path writes the code of a connection twice, and `HttpConnection.create` takes a `TcpStream`, so
     HTTP over a socket of the machine is not here yet. Go has one `net.Conn` for both; a `TcpListener` bound
     to `unix:/path` would have served both with a name that says TCP.
1961. **A path is a `read string`,** as for `File`, the bytes of a name of 189 included. A path longer than the
     address of the system holds (103 bytes on macOS, 107 on Linux and Windows) is `IoError.TooLong`, where Rust
     says `InvalidInput` and Go `EINVAL`; one with no byte or a zero byte names no file (`NotFound`, as for a
     file), so a path is never the abstract name of Linux by mistake.
1962. **The listener takes its file away where it ends,** as Go's does (Rust's leaves it, and the next bind is
     `AddressInUse`), but only while the file is still the one it made: its device and number (on Windows the
     time it was made) are kept at the bind and looked at again. A file there at the bind is `AddressInUse`, as
     the system says; the program removes a file left by a program that was killed.
1963. **A `UnixStream` has the methods of a `TcpStream`:** `receive`, `send`, `sendPieces`, `reader`, their async
     versions and `closeSending`, with the same rules of `read`, `ref` and `shared`; a `UnixListener` has
     `accept` and `acceptAsync`. Neither has an address of the network (`remoteAddress`, `localAddress`,
     `port`), nor TCP's options. `UnixStream.connect` looks nothing up and is made at once; a listener with no
     room left for one more refuses (`ConnectionRefused`) on every system, where a blocking socket of Linux
     would wait, and so does a file that is not a socket (macOS says `ENOTSOCK`). Like `TcpStream.connect`, it is
     a compile error in an async function, where `connectAsync` is written.
1964. **Not here:** the abstract names of Linux (`@name`), datagrams of the machine (Windows has none), who the
     other side is (`SO_PEERCRED`), a descriptor sent over the socket, and `socketpair`. A socket of the machine
     works on Windows 10 1803 and later.
1965. **`try conn.closeSending()`** on a `TcpStream` and a `UnixStream`, through a `read` borrow: the other side
     reads the end of what this side sends, and this side still receives (Go's `CloseWrite`, Rust's
     `shutdown(Write)`, C#'s `Shutdown(Send)`). A second call, or one after the other side broke the connection
     off, does nothing. A `send` after it is `ConnectionReset`, as one after the other side has gone (Windows'
     `WSAESHUTDOWN` is said so too): no new rule and no new error. No side that receives is closed alone; the
     whole connection is closed where it ends.
1966. **`try conn.setNoDelay(on)`** on a `TcpStream` (`TCP_NODELAY`), **on by default** for every connection a
     listener takes or a connect makes, as Go has it (Rust and C leave Nagle's wait on): approved after the
     measurement of 1972, which found a question sent in two pieces waiting 42 ms a round on Linux with it off,
     against a loss of 1 to 5% of the store of RESP on Linux with it on. `setNoDelay(false)` asks for the wait.
1967. **`try conn.setKeepAlive(idle)`** on a `TcpStream`, a `Duration?`: after `idle` without a byte either way the
     system asks whether the other side is still there, and again as often; `null` turns it off. The time is
     rounded up to whole seconds; one of none or less is `InvalidInput`. Off by default, as in Rust (Go turns it
     on at 15 seconds).
1968. **Not taken:** the sizes of the system's buffers (they turn off what Linux sizes itself), `SO_LINGER`,
     `SO_REUSEPORT` (Windows has none), and timeouts of a call (async and `cancelAfter` do it). TTL, broadcast
     and multicast wait for the rest of the datagrams.
1969. **`[::]:port` takes v4 too on every system** (`IPV6_V6ONLY` off, as Go sets it; Linux and macOS do so unless
     the machine is set otherwise, Windows did not), for a listener and a datagram socket. A v4 peer is given
     as the v4 address it is, `127.0.0.1:port`, not `[::ffff:127.0.0.1]:port` as Rust gives it, and a datagram
     socket of a v6 address sends to a v4 one in a v6 one, so it answers a v4 sender at the address it was given.
1970. **`try writer.writePieces(read pieces)`** and `writePiecesAsync` on a `StreamWriter`, `pieces` a
     `List<read byte[]>`: as `writeBytes` of each in turn. Pieces the block has room for are copied into it;
     more go out after the block with one `writev` on Linux and macOS (1,024 pieces a call), piece by piece on
     Windows and into the pipe of another program, as Rust's `BufWriter::write_vectored` does.
1971. **`sendfile` is not in this slice.**
1972. **Measured:** a store of RESP over a socket of the machine and over TCP, against Redis over the same; TCP
     with `TCP_NODELAY` on and off; `writePieces` against `writeBytes` of each piece; small, middling and large.

**Measured** (1972), on an Apple M-series machine (macOS) and Linux in podman on it, each run in turn with the
other way, three times unless said:

A question sent in two `send`s (a head, then a body) and answered with one, 2,000 rounds, the time of a round:

Found on the way and made right: a `for` with `read` over a list of `read` borrows gave each item as
`read read byte[]`, which nothing took; an item that is a `read` borrow already is now lent as it is. On Windows,
`File.info` of the file of a socket of the machine gave `File` interpreted and failed compiled (a point Windows
does not follow, `ERROR_CANT_ACCESS_FILE`); it is `Other` in both now, as on Linux and macOS. And a connect to a
path where nothing is, which Windows refuses, is `NotFound` there too.

What was built. The checker gives the two kinds of socket one type each with a kind, `Ty::Listener(Net)` and
`Ty::Socket(Net)`, so every method of a connection is the same code; `UnixListener.bind` and
`UnixStream.connect` are `NetCall::UnixBind` and `UnixConnect`. `closeSending`, `setNoDelay` and `setKeepAlive`
are done by the language's own module (`SocketAddress.closeSendingOf` and the others in `std/net.sg`) over one
call of the compiler, `System.streamOption`. The C runtime has `sg_unix_listener` (the socket, the path and what
the file was), `sg_net_unix_bind`, `sg_net_unix_dial` (a socket that does not block, so a full listener refuses),
`sg_net_option`, `sg_net_every_v6` and `sg_writer_pieces` with `sg_write_pieces`; an async connect at a path is
made when the call starts, so a cancelled one leaves no socket. The interpreter holds a stream of the machine as
std's `TcpStream` (its calls are those of any connection): on Linux and macOS through std's `UnixListener` and a
connect of its own that does not block, on Windows through Winsock (`sys::net::UnixSocket`). Where a v4 address
in a v6 one becomes v4 again, and back, is SG, in `std/net.sg` (`SocketAddress.given`, `UdpSocket.target`), so
the interpreter and compiled code cannot differ.
