# Decisions and open questions

What has been decided, what is still open, and what comes next. The reasons for the dropped generation model are
in the [memory model](01-memory-model.md) file.

## The idea of the language

A language's reason to exist should fit in one sentence. The direction changed on 5 November, and the current
sentence is: **a systems language as fast as C, without macros, that gives Rust's compile-time guarantees in a
notation that reads like C#.** The solutions come from Rust, the naming and the notation are ours. No arena. A
side project / research, with no revenue goal.

## Core principle: safe default

*Decided on 6 November 2026.* That people can trust this language matters as much as speed. If something can go
wrong, the default behaviour is not to stay silent but to warn or to stop. The risky path is allowed, but it is chosen on purpose:

- Checks are on by default and give a panic or a compile error.
- The unchecked path is visible in the code: `wrappingAdd`, `unsafe { }`.
- The choice is made per line. There is no compiler setting that turns checks off for the whole program.
- An error that can be caught at compile time is not left to run time: the code does not compile, and the error shows in the editor while typing. Panic
  is only for cases whose outcome depends on data and cannot be known at compile time (such as an index typed by the user).

- An error whose fix is known comes with code that shows the fix. An error says "what to write" as much as "what is wrong".

For this reason the checking part of the compiler is written as a library that the language server will also use. The rules for hints:

- The suggested code must compile, and the compiler's tests verify this. Where there is no certainty, no hint is given.
- The risky path (`unsafe`, `wrappingAdd`) is never suggested as a hint. The safe path is shown.
- A mechanical hint is applied in the editor with one click.
- A panic message also prints the values and the safe path: `index 5, length 3`, `xs.get(i)`.

If a performance decision conflicts with this principle, the principle wins, and the loss is recovered through the path that is written on purpose. Every new decision is
tested against it.

*Narrowed on 12 November 2026, in the author's words:* "to be as fast as C, and since it keeps memory safety, we take
Rust's way ... it keeps memory safety, it causes no memory leak, and we gain performance; and the language still offers
the developer the ways to do it safely. From now on we weigh this criterion in every choice." So the principle above
holds without exception where memory safety is at stake: a check that keeps memory safe (bounds, use after free, data
races) is never given up for speed. A run-time check that guards only the correctness of a result is weighed
differently: if removing it keeps memory safe and leaks nothing, the fast behaviour is the default of a release build,
the check stays on in debug builds and tests, and the checked form can always be written out (`tryAdd`). Integer
overflow was the first case; the bullet "there is no compiler setting" above no longer holds for it.

The goal of the language is not to be complex and to avoid bad notation. On its own the principle always pushes towards more rules, and every compile
error rule also rejects some correct code and adds to the rules that must be learned. So before a new rule is added
it is weighed with these four questions:

1. Does the error it catches silently give a wrong result, or is it visible anyway?
2. How often does it fire in real code?
3. Can the fix be shown in one line and with a hint?
4. Does it need a new concept?

A rule that does not satisfy all of them can still be added, but its cost is then accepted knowingly.

*Added on 11 November 2026.* The goal is performance and simplicity like C: the language stays as small as possible. Before a new feature
is added, the question is "can this be written without it", and there are never two ways to do the same thing. On the same day the table was reviewed with this in mind,
and what was removed is in the [dropped decisions](#dropped-decisions) section.

*Restated on 12 November 2026, in the author's words.* The promise of the language is software that is safe and runs
fast: memory safe like Rust, as fast as C. It is not a promise of fast development. The language may be tiny, like C: C
lacks many features and everything is still written in it, operating systems included. Having the features Rust has is
not a goal. The two things that are not given up are performance and simplicity: a feature that costs nothing at run
time and does not complicate the language can stay (the collection methods, the text of a collection); a feature that
costs at run time needs a reason that is about safety, and one that adds concepts and rules needs to be worth them.

*Added on 12 November 2026.* We are not tied to a single language. Rust's guarantees, C#'s notation, Go's simplicity, Zig's
smallness: what each language does best is taken in the form that fits us, and is not taken if it does not fit. A proposal is accepted not because
"Rust does it this way" but because it fits the goals of this language.

## Decisions made

| Topic | Decision | Reason |
|---|---|---|
| C compatibility | Unimportant | Performance comes first |
| Use-after-free | At compile time: single ownership and borrowing, Rust's rules | The error should appear at compile time, not in production. The problem is not the rules but Rust's notation |
| Arena | Not in the language | Going with Rust's solution is enough, no separate memory model is needed |
| Lifetime notation | No `'a`; `from a, b` at the end of the signature, with default rules | The name of the source variable is written instead of an abstract name. Details: [syntax](02-syntax-draft.md) |
| `from` and `where` | `from` states the source of the return value, `where` states a type constraint. If another parameter stores the borrow, `where r from name` *(12 November: `where` is deferred with generics; `from` stays.)* | `where return from` was crowded, and it is clear that the subject is `return` most of the time |
| Read-only borrow | `read T` | It says directly what it does and is not confused with `for x in xs` |
| Owning pointer | `T*`, created with `new` | Short, and consistent with the `T*?` notation |
| Move | Implicit, the compile error shows the line where the value was moved | `list = push(move list, 1)` was getting crowded |
| Local borrow | `read T x` is not written. `var` infers the type, and the borrow is on the right-hand side: `var x = read items[0]` | `read` is a contract in a signature and in a field, and in a local it is information the compiler already has. `string x` asks for an owner; assigning a borrow is an error, a copy must be made |
| Null | No universal null: `T` cannot be empty, every type has `T?`, built into the language | Implicit null is a source of bugs; `Option<T>` would need generics, and magic values like `-1` should go too. `Node*?` is 8 bytes, `int?` is 8 bytes with a flag |
| Array | Slice (pointer + length), bounds check panics | |
| Panic | Only for programmer errors (array bounds, `checked` conflict), the whole process stops. The only exception is `print`, in the "`print` error" row | No unwinding. Errors expected from the environment are returned as values with `Result` and need no unwinding |
| Safety checks | On in release too, cannot be turned off | If they could be turned off, the design would lose its reason |
| Macros | None | |
| `T?` check | `if x is null`, `while x is not null`; flow narrowing on local variables and parameters | After the check the same name counts as `T`. Fields are not narrowed, a local copy is taken first |
| `T?` unwrapping | `x ?? default`, `x ?? panic("message")`; `orelse` is gone | No separate `throw.ifnull` is needed: `throw` suggests something that can be caught, while panic stands in for every type |
| Name of the empty value | `null` | Familiar from C#, but valid only in the `T?` type |
| Notation direction | C#: type-first declarations, `public`, `int`, `var`, `Node { value = v }` | No semicolons, `while` without parentheses |
| `T*?` notation | Postfix, read left to right | `Node*?` is a nullable pointer, `Node?*` is a pointer to a nullable value; C#'s pointer notation |
| `ref` | Writable borrow (`&mut T`); also written at the call site | Familiar from C#. Can also be used in a return type and in a field |
| `main` | `void main()` | Every function starts with its return type, no exceptions |
| Shared ownership | `shared T`, a second owner with `share x`, creation with `new shared x` | One name for `Rc` and `Arc`: the counter is always atomic. A non-atomic version can be added later if needed, the reverse is hard. The cost is paid only on `share` and when an owner lets go, a borrow does not touch the counter |
| Weak reference | `weak T`, `weak x`. The result of `share w` is `shared T?` | Not an owner, breaks cycles. `null` if the object is dead |
| Interior mutability | `checked T` (`RefCell`) borrows on access and panics on a conflict. Its duration is in the "`checked` borrow duration" row | A run-time check like the array bounds check, visible in the type |
| Lock | `locked T` (`Mutex`), access only inside a `lock x as c { }` block | A two-step operation cannot be left halfway. Since a panic stops the process, there is no poisoning and no `.unwrap()` |
| Escape hatch | `raw T`, dereference only inside `unsafe { }` | Since `T*` is the owning pointer, the raw pointer gets a separate name |
| `?` and borrows | `ref T?` is a borrow of the original variable of type `T?`; "the borrow may be absent" is written `(ref T)?`. `read T?` has a single meaning, `shared T?` says the pointer may be absent | A C# reader expects `ref T?` to read this way. Since `read` cannot write, the two readings do not differ. `T*` cannot be empty; null cannot be assigned through `ref T*`, the caller's type would be lying |
| Methods | In the struct body, with `read this`, `ref this` or `this` as the first parameter. Field access must be written `this.x`. At the call, `read`/`ref` is not written for the receiver | `this` follows the same rule as the other parameters, and fields are not confused with local variables |
| Interface | C# notation: `struct Version : Comparable`, `where T : Comparable`, the implementing type is `Self`. Generic interfaces exist *(12 November: an `interface` of your own and `where` are deferred with generics; the built-in ones stay: `Copyable`, `Formattable`, `Equatable`, `Hashable`, `Comparable`, `Disposable`, `Closable`.)* | Static dispatch in the first version |
| Copy and cleanup | The `Copyable`, `Clonable`, `Disposable` interfaces. The compiler generates the body of the first two | No macros. `dispose` does not run during a panic |
| Source name parameter | `Match<from text, from pattern>`, also for a single source: `Parser<from source>`. If the type has a single source, `from` is not written on the field, and if it has more than one it is: `read string found from text`. In a method `from source`, outside `from lx.source` | It is told apart inside the same `<>` as a type parameter. `from this.lexer.input` was pulling a private field into the signature. With a single source there is no ambiguity, and repeating it on the field is noise |
| Thread rule | An argument to `spawn` cannot carry a borrow, an unlocked `checked` or a `Func`, including one stored in a struct field *(12 November: a `Func` is now only the address of a function and can be passed to `spawn`.)* | Since the counter is always atomic, Rust's `Send` and `Sync` distinction comes down to this single rule. `Func` is forbidden because its type does not show what it holds |
| `enum` | Variants carry data: `Circle(int radius)`. Construction with the full name: `Shape.Circle(2)`, `new Expr.Number(1)` | Takes a tag plus the size of the largest variant, no heap. An enum that contains itself needs `T*` |
| `match` | `match x { Circle(r) => ... }`, as an expression or a statement. A missing variant is a compile error. Short names in patterns | When a new variant is added, every place that needs a look gives an error |
| Patterns | `_` catches everything, `var other` also takes the value, an unknown bare name is an error. The condition is `when` | A mistyped name should not silently become "catch everything" |
| `match` and ownership | `match x` behaves like `var y = x`: it moves if `x` is an owner, `match read x` and `match ref x` borrow, and if `x` is already a borrow it gives the same kind of borrow | No new rule |
| Testing a single variant | `if s is Circle(r) { }`, the same word as `is null` | The counterpart of Rust's `if let` |
| `is` and ownership | `x is Circle(r)` only looks: it never moves `x`. The names are `read` borrows, or `ref` borrows when `x` is a `ref` borrow or the test is written `ref x is Circle(r)`. To take the values out, `match` | `is null` already only looks, and a test that uses its subject up would surprise. Rust's `if let` moves; we differ on purpose |
| Pattern shape | A pattern names or skips every value: `Rect(w, _)`. A bare `Rect` for a variant that carries data is a compile error | One way to write it; adding a field to a variant shows every pattern that needs a look |
| Unreachable arm | An arm that can never run (its variant is handled above, or an arm above takes every value) is a compile error | Rust warns; there are no warnings here |
| Arm of a statement `match` | Follows the statement rule: a call, an assignment (`Circle(r) => r += 1`), `return`/`break`/`continue`, or a block. `Circle(r) => r * 2` is "the value is not used". `Empty => {}` does nothing | No new rule |
| Separators in `enum` and `match` | Variants and arms are separated by line ends, never commas | The line-end rule; one way to write it |
| `match`, `is` and `T*` | Both look through `T*`, like field access. `var other` gets the value as it was given (the `T*` itself) | No new rule |
| Recoverable errors | `Result<T, E>` is an ordinary enum: `Ok(T value)`, `Error(E cause)`. Success is `return Ok(value)`, and for an operation that returns no value `Result<void, E>` and `return Ok()`. `main` can return it too, the error is printed and the exit code is 1 | No new type feature is needed, and because it is a value it can be stored and passed to generic code. The `int f() fails E` notation was ruled out for this reason |
| Error propagation | `try x`, a prefix like `await`. On an error it returns to the caller, on a `T?` it returns `null`. Parentheses in a chain: `(try a()).b()` | `?` is used as a type suffix. Returning through `try` is a normal exit, `dispose` runs |
| `Result` unwrapping | `x ?? default`, `x ?? panic("message")`. There can be a `return` on the right of `??` | The same operator as for `T?`, like `x ?? throw` in C# |
| Error conversion | `try` finds by itself the variant of the target error type whose only field is the source type. If there is none or more than one, a compile error | No hand-written `From` as in Rust, and no macro either |
| Unused `Result` | Compile error, and `_ = f()` to discard on purpose. A `Result` that is assigned to a variable and never unwrapped gives the same error, an exit through `try` is exempt | An error should not be lost silently |
| Type of `Ok` and `Error` | `Ok(...)` and `Error(...)` take their type from where the value goes, like `null`: a `return`, a declaration with a type, an argument, a field. `var r = Ok(1)` is a compile error, and the hint is to write the type | Nothing in `Ok(1)` says what the error type is. Rust infers it from later lines; here a line is read on its own |
| Taken names | `Result`, `Ok` and `Error`: no type called `Result`, no function called `Ok` or `Error`. A variant of your own enum can be called `Ok` (`Status.Ok`) | The short names must mean one thing everywhere |
| `Result` in a variable | "Never unwrapped" is checked as "never looked at": any read of the variable counts (`try r`, `r ?? 0`, `match r`, `r is Ok(v)`, passing it on) | Exact for the common mistake, and needs no flow analysis |
| `_ = e` | Drops any value on purpose, not only a `Result`. On a call that returns nothing it is a compile error | One way to say "I do not want this"; with `void` there is nothing to drop |
| `??` on `Result<void, E>` | Compile error; the hint is `try` or `_ = ...` | Success carries nothing, so there is nothing to fall back to |
| `tryDivide` | Gives `null` for division by zero too, not only for overflow | Rust's `checked_div`. "`null` where the operator would panic" is one rule for the whole `try...` family |
| `return` in an expression | Written only on the right side of `??` | The one place it reads well; anywhere else it hides an exit in the middle of a line |
| Arithmetic on small integers | An operation happens in the type of its operands: `byte + byte` is a `byte`, and overflow panics as everywhere else. A `byte` widens to `int`, `long` and `nint` on its own; the way back is `(byte)x` | Rust's rule. C# computes in `int`, which is one more rule to know. Cost: `int x = b + 1000` is an error and is written `(int)b + 1000`. Approved on 12 November with the interpreter's sixth slice, as are the rows below |
| A character is a `byte` | `'+'` is a `byte` and nothing more: `int x = '+'` is 43 through the ordinary widening, and `print('+')` writes `43` | Follows from the `char` row and the widening rule, no new rule. Writing a byte as a character waits for `char` |
| `-` on a `byte` | Compile error; the hint is `-(int)b` | The result could only be 0 (Rust). Caught at compile time instead of a panic |
| Type of an index | An index and the ends of a range take any integer that widens to `nint` (`byte`, `int`, `nint`). A `long` is converted with `(nint)` | The widening rule as it is; no special case for indexes |
| Backwards range | `text[3..1]` panics, it is not an empty text | Rust. A range that ends before it starts is a mistake in the data, not a request for nothing |
| `match` on a number | Patterns are numbers and characters, `_` and `var name`. `_` or `var name` is required, even when all 256 values of a `byte` are listed. The same number twice, or a number that does not fit the type, is a compile error | The check does not count values: one simple rule. An arm that can never run is an error, as for enums |
| Quotes and escapes | `\'` is an escape in both kinds of quotes; neither quote has to be escaped inside the other (`'"'`, `"'"`) | C#'s rule |
| A range is written bare | `text[a..b]` is a `read string` on its own. `read text[a..b]` is a compile error whose hint is the bare form. `read items[0]` stays: it lends one element | One way to write it; the range already says "a window". Decided on 12 November |
| `Copyable` receiver | A method that takes `this` by value copies a `Copyable` receiver, so the value stays usable | The argument rule applied to the receiver; the same in Rust |
| Generated text | A `Formattable` type without its own `format` is written the way it is built: `Place { line = 3, file = "a.txt" }`; a variant without its enum: `NotFound("x.txt")`, `Ready`; text inside another value is in quotes; a missing value is `null`; a `T*` is written as what it owns. The error `main` ends with is written this way: `error: Syntax(NumberTooLarge(0))`. A struct with its own `format` may hold fields that are not `Formattable` | Our own construction notation instead of a second one (Rust writes `line: 3`). Quotes keep the parts apart |
| `print` and `null` | `print` of a `T?` or a `Result` is a compile error; the hint is `??`, `is null` or `try`. Inside a generated text `null` is written | A silent `null` in the output is more likely a forgotten test. Rust does not print an `Option` either; C# prints an empty line |
| `Formatter` | A taken type name. `f.write(x)` takes whatever `print` takes | |
| Built-in collections | `List<T>`, `HashMap<K, V>` and `HashSet<T>` are known to the compiler, like `Result<T, E>`; there are no generics of your own for now. A key of a map and an item of a set is `Equatable` and `Hashable`: an integer, a `bool`, a `string`, or a type of your own written with both. `List<int>(` and `List<int> {` start a value, so `a < b > (c)` is read as a type (C#'s rule), and in a condition the braces need parentheses | Go's old way; the generics question stays open |
| Reading an item | `xs[i]` lends an item that cannot be copied: `names[0]` is a `read string`; an item is never moved out through an index (the hints are `.clone()`, `read`, `replace`). A copyable item is the value itself | Follows from `at` returning `read T`. In Rust `v[0]` cannot move a `String` either, and `&v[0]` is written; here the `read` comes on its own |
| List and set methods | `removeLast()` gives a `T?`, `null` for an empty list. `xs.get(i)` gives a `read T?`, and `xs.get(i) ?? 0` is the value when it can be copied. `xs.indexOf(v)` gives a `nint?`. `set.remove(v)` gives a `bool`. `for x in ref set` is a compile error | Rust's `pop`, `get` and `position`. An item of a set changed in place would sit under the wrong value |
| Looking a key up | A method that only looks a key up takes text as `read string`: `ages.get(read name)`, a literal as it is; a number or a `bool` by value. `add` takes the key itself | The existing rule for passing a `string` where a `read string` is expected; without `read` the call would read as a move. Rust writes `map.get(&name)` |
| `Comparable` is written | `: Comparable` needs a `compare` method written by hand: `int compare(read this, read T other)`. It is not made from the fields; only `equals` and `hash` are. An enum cannot be `Comparable` until enums have methods. Decided on 12 November | An order made from the order of the fields is rarely the one that is meant, and it would change silently when a field is moved. Rust's `#[derive(Ord)]` does exactly that |
| A looked-at argument | An argument a method only looks at is lent when it cannot be copied: `old.compare(read next)`, `tags.contains(read tag)`; a `Copyable` one is passed as it is. The operators need no `read`: `old < next`. Decided on 12 November | The same rule as "Looking a key up"; operands are never taken ("Looking is not taking") |
| Equality of collections | A collection is `Equatable` if what it holds is: a `List` with the same items in the same order, a `HashSet` with the same items, a `HashMap` with the same keys and equal values (order does not count for the last two). A struct that holds one is `Equatable` field by field. A collection is not `Hashable` and not `Comparable`. Decided on 12 November | The same pattern as `Copyable` on a generic type and as the text of a collection; no new concept. Rust does the same for `==`; C# compares identity (the trap we ruled out), Go refuses. Not a key and no `<`: rarely needed, easy to add later, and an order is written, not made up |
| `Equatable` and `Hashable` details | `==` wants the same type on both sides and looks through `read` and `T*`; `a != b` is `!a.equals(b)`. In the generated `equals` a `T?` field is equal when both are `null` or both hold equal values, and a `T*` field is compared by what it owns. `Hashable` needs `Equatable`. Integers and text have `a.compare(b)` and `a.equals(b)` (`bool` has `equals`). A failed `assert(a == b)` writes both sides field by field, `Formattable` or not. Decided on 12 November | What the design's rows on equality left unsaid |
| Text of a collection | A collection is written as text if its items are: `[1, 2, 3]`, `{"ada": 36}`, `{1, 2, 3}`; text inside is in quotes. A struct that holds one can be `Formattable` without its own `format` | One rule less, and it is what is wanted while looking for a mistake. Go prints a slice too; Rust needs `{:?}`, C# prints the type name |
| A collection inside its own `for` | The compile error of the "`for` and ownership" row covers: a changing method, `xs[i] = v`, `xs = ...`, `ref xs`, moving `xs`, and a `ref this` method on what holds it. Looking, and changing other fields, is allowed. Pointing a `read` variable elsewhere is not a change | The same as Rust. The hint: go over the positions, or keep the changes until the loop ends |
| Integer overflow | Rust's way, decided on 12 November: `+`, `-`, `*` and unary `-` panic on overflow in a debug build and in tests, and wrap in a release build (two's complement, defined, never undefined behaviour). `tryAdd` returns `int?` and is checked in every build; `wrappingAdd` wraps in every build. Division by zero and `MIN / -1` panic in every build | Overflow cannot break memory safety, because an index is still bounds checked; it is a correctness error. Measured on 12 November: the check cost nothing in ordinary code and 40 to 60% in loops that are only arithmetic. The first decision (6 November) was to panic in release too, as Swift does; it was changed when the cost was measured. Whoever needs the check in release writes `tryAdd` |
| Implicit conversion | `read T` stands in for `T` if `T` is `Copyable`. A `read T*` can be given to a `read T` parameter | Otherwise a dereference would be needed on every line |
| `new` | Required. It puts the value on the heap and gives a `T*`, it does not mean creating an object. `HashMap<K, V>()` takes no `new`, it is the value itself | A separate heap allocation should stay visible, and `var` should know which type is wanted. An implicit conversion can be added later, but cannot be removed |
| Constructor | `T(args)` is short for the call `T.create(args)`. `create` is an ordinary function and can return a `Result` | There is no half-built object, and no separate constructor concept is needed |
| Collection initialisation | `List<int> { 1, 2 }`, `HashMap<string, int> { {"x", 10} }`. Each item is an `add` call, and `reserve(n)` is called first. `HashMap()` and `add` are valid too | As in C#, works without macros, and user collections benefit as well |
| Field order | The compiler orders struct fields freely so that no gaps remain | Since C compatibility is unimportant, a memory gain at no cost |
| Characters and slices | `'+'` is a byte constant, `string` is UTF-8 and byte indexed, a slice is `text[a..b]` (C#). `read string` is pointer + length. Unicode operations are in the library. The single-character type is in the "`char`" row | The language core stays small, indexing is O(1) |
| Types that carry a borrow | Every type that contains a borrow declares its source: `enum Token<from source>`. The rule of not writing `from` holds only when `read` or `ref` is visible in the return type. If the borrow is hidden in the name of the type, `from` is required: `Result<Expr*, E> parse(read string input) from input` | The dependency should be readable from the signature. It is not written on parameters and locals: on a parameter the borrow ends with the call, and on a local a compile error shows it if there is a problem |
| `Copyable` and enums | The same as for structs: all fields of all variants must be `Copyable`. `read T` and `raw T` count; `ref T`, `T*`, `string`, `shared T`, `weak T`, `locked T`, `checked T` do not. On a generic type `: Copyable` holds if the type parameters are `Copyable` too | Without this, `T?` and `Result<T, E>` could never be copied |
| `take`, `replace`, `swap` | In the standard library: `x.take()` only on `T?`, gives the value and puts `null` in its place. `x.replace(newValue)` gives the old value, on every type. `swap(ref a, ref b)`. A field is moved through a `ref` only with these: `var node = this.top` is a compile error, the hint is `this.top.take()` | Rust's `mem::take` needs a default value, and we do not have that concept |
| `Disposable` and moving a field | Moving a field out of a `Disposable` type is a compile error | `dispose` should not see a half object |
| `for` and ownership | The `match` rule: `for x in xs` moves, `for x in read xs` and `for x in ref xs` borrow, and if `xs` is already a borrow it gives the same kind of borrow. Changing `xs` during the loop is a compile error *(12 November: `for` goes over a range, the built-in collections and the built-in iterators such as `text.lines()`; going over a type of your own is deferred with generics.)* | No new rule. The run-time `InvalidOperationException` of C# appears here at compile time |
| `readonly` field | Given only at construction, cannot be assigned afterwards. The whole object can be changed through a `ref` | Immutability should be checked at compile time. It does not replace `read`: `read` is a borrow, a `readonly` field owns its own data |
| Index | `xs[i]` is short for the call `xs.at(i)` when reading and `xs.refAt(i)` when writing | The `T(args)` pattern. No general operator definition is needed, and user collections benefit as well |
| `length` | A method everywhere: `xs.length()`, `text.length()` | Since a `public` field can be written from outside, `xs.length = 100` would corrupt the list |
| `raw T` operations | `Memory.allocate<T>(n)`, `Memory.free(p)`, `Memory.moveItems(a, b, n)`, `p.put(i, v)`, `p.take(i)`, `p[i]` | Memory operations are in the library, and dereference is still only inside `unsafe { }` |
| Number types | Based on the C# types: `byte`, `short`, `int`, `long`, their unsigned counterparts, the pointer-sized `nint` and `nuint`, `float`, `double`. `int` is 32 bits on every platform. Indexes and lengths are `nint` | No new names for a C# reader. If `int` were the index, `List` would stop at 2 billion items |
| String constant | The type of `"x"` is `read string`. Where a `string` is expected it becomes a `string` without allocating: capacity 0, data inside the program. It is not freed, and the first write or growth copies first. Only for constants, a `read string` variable needs `.clone()`. If a function with no borrow parameter returns `read string`, the source can only be a constant, and nothing needs to be written | No `.clone()` noise, and no hidden heap allocation either. To keep a constant in a struct field, `string` is enough, no separate source name is needed |
| Text formatting | `$"{a}: {b}"`, C# notation. It is a language feature, checked at compile time, and does not allocate. The result is a value that borrows its arguments and implements `Formattable`. For a `string`, `.toString()` is written. `{{` writes a curly brace | It has to be in the language because there are no macros. The only difference from C#: so that heap allocation stays visible, a `string` is not created by itself, and where a `string` is expected the hint is `.toString()` |
| `Formattable` | `void format(read this, ref Formatter f)`. `print` and `writeLine` accept it. If no body is written the compiler generates one, and all fields must be `Formattable`. The error type of `main` must be `Formattable` | A write error stays in the `Formatter`, and `writeLine` returns it. This way there is no `try` noise inside every `format` |
| `string` guarantee | Always valid UTF-8. A bad byte on reading gives `IoError.InvalidText(long position)`, the only way from bytes to text is `string.fromUtf8`, which returns a `Result`, and raw data is read as a `byte` slice. String constants are checked at compile time. A slice through the middle of a character panics. `text[i]` is read only, a byte cannot be written | Core principle: bad data should not silently become `�` (C#), and Unicode operations should not meet garbage |
| File API | C# names: `File.openText` gives a `StreamReader`, `File.createText` gives a `StreamWriter`. `reader.readLine(ref line)` reuses the buffer and returns `Result<bool, IoError>`. `reader.lines()` gives an owned `string` per line and ends after the first error. `int.parse` returns a `Result` | `Iterator.next` cannot lend from its own buffer, since `next` would change that buffer on the following call. And there is no loop that gives the same error forever |
| `HashMap.getOrAdd` | `map.getOrAdd(key, initial)` returns `ref V` and copies the key only if it is missing | One hash, one `clone`. `counts[k] += 1` panics if the key is missing |
| `HashMap.add` and `map[key] = value` | `map.add(key, value)` panics if the key is already there, also inside `HashMap<K, V> { ... }`. `map[key] = value` writes only under a key that is there and panics otherwise, like `map[key]` and `map[key] += 1`. "Put or overwrite" has no notation of its own: it is written with `contains` or `getOrAdd`. Decided on 12 November | Core principle: neither a silent overwrite nor a key that appears silently. C#'s `Add` throws too, but its `map[key] = value` inserts; Rust's `insert` overwrites and returns the old value |
| `HashSet.add` | `set.add(value)` gives a `bool`: `true` if the item was added, `false` if it was already there. It does not panic. Decided on 12 November | C# and Rust agree. Unlike a key in a map, adding what is already in a set is ordinary use (`if !seen.add(id) { continue }`) |
| Order of a `HashMap` | The language promises no order, and neither the interpreter nor compiled code gives one: a `HashMap` and a `HashSet` are hash tables, gone over in whatever order the table has, as in Rust. Changed on 12 November (until then the interpreter went over the entries in the order of their keys, for the golden tests). Since the twenty-fourth slice both build the same table (entries one after the other, a removed one replaced by the last), so a program prints the same in both; what falls out is the order of adding until something is removed, and it is not promised | A sorted structure would make every lookup slower to give an order nobody was promised. A program that needs an order sorts the keys |
| `dispose` order | The reverse of declaration | What is declared later may have borrowed from what is declared earlier |
| Close error | `writer.close()` takes `this`, writes the buffer and returns a `Result`. `Closable` is an empty marker (`StreamWriter : Closable`): if a local variable of such a type is dropped at a normal exit without being closed or moved elsewhere, it is a compile error, and the hint is `try writer.close()`. An error exit through `try` is exempt, `dispose` runs there. To give up on purpose, `_ = writer.close()`. If the value is moved into a struct field, a list or a `shared`, the compiler stops tracking it and there is no restriction | A forgotten `close` silently loses the write error. In C# the same idea is an analyser warning (CA2000), in Rust there is no check. It is an error because the language has no concept of a warning and the check is exact. The heavy version that tracked everywhere was removed on 11 November, and this version that looks only at locals was added the same day. Cost: one marker and one rule; a value moved into a field and dropped without being closed is not seen, and the responsibility lies with whoever writes the struct |
| `checked` borrow duration | An access borrows for the duration of the expression. A borrow at the head of a `for` or `match` lasts for the whole statement. A local variable cannot hold a `checked` borrow, compile error. A block for several lines: `read x as n { }`, `ref x as n { }` | With the "for the duration of the expression" rule it was impossible to loop over a `checked` list. The block has the same form as `lock x as c { }`, no new word is needed, and the duration of the borrow is visible in the code |
| `this` with a type | `this` can also take a type: `read FolderRef this`, `FolderRef this`. `read this` is short for `read Folder this`. The method is called only on a value of that type | `ref this` does not give the wrapper that holds the counter, so the method could not write `weak this` or `share this`. The method does not lock the object for the whole call, and code that walks upwards does not conflict with itself. `read shared checked this` was considered too, and since an alias cannot be written there, a single form remained |
| Type alias | `using FolderRef = shared checked Folder`, C# notation, can take `public`. It is not a new type but the same type, and it disappears at compile time. `new FolderRef(args)` means `new shared checked Folder(args)`, and `FolderRef?` is `shared checked Folder?` | Repeating `shared checked` was making signatures long. |
| `checked` conflict | A conflicting access on the same variable while a borrow is in progress is a compile error: `for x in read a.items { a.items.add(y) }`. A conflict that comes through another variable panics, and the message prints both lines | The `for` rule extended to `checked`: code that would panic every time it runs does not compile. Cost: location information per `checked` and one write on every borrow, the principle wins |
| Equality | `Equatable` (`bool equals(read this, read Self other)`), `Hashable` (`long hash(read this)`). If no body is written the compiler generates one field by field. `a == b` is short for `a.equals(b)`; `a < b` is short for the call `a.compare(b) < 0`. `==` on a type that is not `Equatable` is a compile error. `HashMap<K, V> where K : Equatable, Hashable`. Numbers and `string` implement all three | The `xs[i]` pattern: no general operator definition is needed. There is no silent reference comparison as in C# |
| `weak T?` and `share` | The result of `share` is a single `null`: `shared T?`, whether it is not linked or the object is dead. `x is null` answers "is it linked", `share x` answers "is it alive". If the difference matters, `if x is not null { var up = share x ?? panic("parent was deleted") }` | There is no `T??`. The difference is not needed in most places, and where it is, two separate questions are asked |
| Copy of `shared T` | `Clonable`, and `.clone()` means `share`, it does not copy the content. `List<shared T>.clone()` shares the items | So that `for child in folder.children.clone()` can be written. For a single value the `share x` notation stays |
| Function value | `Func<int, bool>` is the type of a function, the last parameter is the return type (`Func<int, void>` for none). A value of it is the address of a named function and nothing more: `Copyable`, no heap, no captured data. It is written by naming the function (`Func<read Order, bool> rule = isPaid`, `apply(isPaid)`) and called like one (`rule(order)`). A method bound to an object is not a function value. There is no lambda notation; what a function needs comes in as a parameter. Decided on 12 November | C's function pointer, and it costs what a call through a pointer costs. Lambdas that capture were removed the same day: they brought a run-time check and the largest group of rules in the language |
| Function value details | Only a top-level function is a value: not a method, not a function inside a struct, not `main`, not a built-in. A variable that holds a function value wins over a function of the same name when it is called. The result of a call is not called directly (`pick(true)(2)`): a variable goes in between. A function value is not written as text and not compared with `==`. `x => ...` in an argument is a compile error that says there are no lambdas. Decided on 12 November | The smallest form that covers callbacks and tables of operations |
| How long a borrow lasts | Until its last use, not until the end of the block: after the last line that uses `first`, what `first` borrowed from is free again. Decided on 12 November | Today's Rust (since 2018). The rule the user learns is one sentence either way; "until the end of the block" is simpler for the compiler but rejects much correct code and makes people open blocks only to end a borrow. No cost at run time in either |
| Borrows that do not go together | While a variable holds a borrow and is used again later: with a `read` borrow the place cannot be changed, moved or lent as `ref`; with a `ref` borrow it cannot be touched at all. A variable gets a borrow from `read x` / `ref x`, a range of text, a lent item (`names[0]`), the names of a `match` or `is` pattern, a copy of another borrow, and a call that returns a borrow. Fields are told apart (`ref p.x` and `read p.y` go together), items of a collection are not. A use in the other branch of an `if` or `match` does not count as later; a use anywhere in a loop does, unless the variable is declared inside the loop. In one call the same place is not lent twice when one of the two is `ref`. Pointing a `read` variable elsewhere frees what it held. Decided on 12 November | Rust's rule. A value read for an argument is not a borrow, so `xs.add(xs.length())` is fine |
| A borrow does not outlive its owner | A function that returns a borrow returns one that comes from a borrowed parameter: with one such parameter nothing is written, with more `from a, b` says which (leaving it out is a compile error that shows what to write; it may name fewer than are borrowed, and it may be written with one). `from` is checked in both directions: inside, every returned borrow comes from a named parameter; at the call, the result borrows only from the named arguments. Returning a borrow of a local or of a parameter taken by value is a compile error; with no borrowed parameter only a constant can be returned. A variable cannot keep a borrow of something declared in an inner block and be used after that block. A built-in method that returns a borrow lends from its receiver; a call through a `Func` value from every borrow it was given. Decided on 12 November | Rust's lifetime rules with the design's notation: the source is named, not a lifetime |
| `var` and a borrowed variable | `var kept = a`, with `a` a `ref int` or `read int`, copies the number: a borrowed variable used as a value is the value behind it. A second borrow is written `ref a` / `read a`. What cannot be copied (`read string`) is copied as a borrow, and a call that returns a `ref` keeps it (`var slot = map.getOrAdd(key, 0)`). Decided on 12 November | It used to make a second borrow silently, and a swap written with it was wrong. C#'s `var` copies too |
| Following a type that carries a borrow | A value of a type with a source (`struct Word<from source>`) is followed like a `read` variable: it keeps what it borrowed from until its last use; so does a list or a map of such values and a struct built from them. `from source` in a method means what the value holds, not the value: after `var word = words.next()` the `words` is free. Lending a field that is itself a borrow (`this.input[a..b]`, `word.text`) lends what the field borrowed. A type that holds a type with a source names a source too, and a type that names one holds something that borrows. A function with no borrowed parameter that returns such a type writes no `from`. One source per type for now. A borrow from outside is not stored through `ref` (`this.input = other`): no notation for it for now; a value is built where its source is known. Decided on 12 November | What the "Types that carry a borrow" row left unsaid. `where r from name` went away with `where`, and nothing written so far needed it |
| Back end | The compiler writes C and a C compiler makes the program (`sg build`, `--release` for a release build): the smallest path, every platform has a C compiler, and its optimiser does the heavy work. A compiled program panics with the same text as the interpreter, which stays as the reference: every program the back end accepts is compiled and compared with it. Deep recursion is not caught in compiled code (the stack depth question stays open). Decided on 12 November | Machine code or LLVM's form would be a much larger step for the same result at this stage |
| Owned values in compiled code | The checker decides who owns a value and the back end follows it: an owned value is freed where its variable ends, on every way out of the block; a use that moves the value empties the place it leaves, so the later free finds nothing to do. No garbage collector and no reference count. A text constant is never allocated or freed. A `read string` is a pointer and a length, a `string` a pointer, a length and a capacity. An owned value without a name lives until the end of its statement. If memory runs out the program stops; there is no notation for handling it. An index and a range of text are checked in every build, the character boundary of a range too (its cost could not be measured). Decided on 12 November | Emptying the place on a move is the simplest correct form (a value moved in only one branch needs nothing more), and the C compiler removes most of the tests. Stopping when memory runs out is Rust's default too |
| Heap and missing values in compiled code | A `T*` is one pointer to a block made by `new`, freed with what it owns where its owner ends. A `T*?` is the same pointer, with `null` as the address zero; every other `T?` is a flag and the value. A struct that points to itself through one field (a list) is freed in a loop, not by recursion, so a long list cannot run out of stack; a tree is still freed as deep as it is. `print(p)` with `int* p` writes the number. The methods of numbers, `bool` and text are found through a `T*`, like fields and the methods of a struct. A move on a right side of `??` that always leaves (`?? return list`, `?? panic(...)`) does not count for the code after it. A limit of the back end for now, not a rule of the language: the output needs GNU statement expressions (clang, gcc); where `try` and `?? return` can stand is in "`Result` in compiled code". Decided on 12 November | A missing pointer costs nothing (Rust does the same for `Option<Box<T>>`); the list benchmark runs in 1.01 times the time of C. Rust frees a list by recursion unless `Drop` is written by hand |
| A borrow that may be missing, in compiled code | A `read T?` is a pointer to the `T`, null when there is nothing; for text it is the pointer and the length of a `read string`, with the length -1 for nothing. A function that gives one back (`read Product? get(...) from this`), `list.get(i)` and `map.get(key)` give a pointer into what they were lent, and nothing is copied. Where a `T?` that is kept is lent (`read account.limit`), its flag is tested once, there. A `ref T?` stays a pointer to the flag and the value, because `null` can be written through it. Decided on 13 November | What would be written in C by hand, and no cost that grows with the size of the struct. The other form (a flag and a copy of the value's bytes that nobody drops) kept `read T?` and `ref T?` in one shape but copied a `T` on every call; an optimised build removed that copy where the function was inlined, a debug build did not (4.75 s against 3.66 s for three hundred million lookups of a struct of 128 bytes). Cost: the two borrows of a `T?` have different shapes in C, which is not seen from the language |
| Enums in compiled code | An enum is a tag of one byte and, beside it, room for the largest variant; an enum whose variants carry nothing is the tag alone. `match` is a chain of tests on the tag (not a C `switch`: `break` and `continue` in an arm mean the loop around it). A `match` on an owned value takes it apart: the names of the arm own what the variant carried, what the pattern skips is freed as the arm starts, a `T*` subject gives its block back; on a borrow the names are pointers into the value. An enum moved out of its place is left with a tag that is no variant (255, so at most 254 variants). The drop of a variable that was certainly moved is not written. At first `match` was compiled only as a statement or as the whole right side of one, and the names of `is` and of a borrowing `match` needed a value that has a name; both limits are gone (twenty-fifth and twenty-eighth slice). Decided on 12 November | What a C programmer writes by hand; Rust packs the tag further, which is not done here. The expression-tree benchmark runs in 1.02 times the time of C |
| `when` only looks | The condition of a `match` arm (`when`) cannot move a value; it reads, or lends with `read`. If it could move a value and then not hold, the arms below would run without it. Decided on 12 November | Rust has the same rule. No cost at run time, one rule, and compiled code can then fill in the names of an arm before its condition is known |
| `Result` in compiled code | A `Result<T, E>` has the shape of an enum: a tag of one byte and room for the larger of the value and the error; a `Result<void, E>` is the tag and the error. `try` is one test of the tag and, on an error, a `return`: the error is moved, wrapped in the caller's error type where that is asked for (one more tag), and the function frees what it owns on the way out. `??` frees the error, then computes the right side. A `Result` moved out of its place gets the tag 255, like an enum. An error that `main` ends with is written as `error: ...` and the exit code is 1. Limits of the back end for now, not rules of the language: `try` and `?? return` are compiled wherever no value that owns something was computed before them in the statement and is still without a name (after such an argument or field only since the twenty-eighth slice, which keeps it under a name; not as an argument of a method call, inside `$"..."`, on the right of `&&`, `||`, `??`, or inside `assert`); the error of `main` is text, a number or a `bool`. Decided on 12 November | No unwinding and no tables: an error costs what a returned value costs. Rust's `Result` and `?` are the same, with the tag packed further. The parsing benchmark runs in the time of C that returns error codes (0.99 to 1.05) |
| `List` in compiled code | A `List<T>` is a pointer to its items, a length and a capacity; an empty list has no block, a full one gets room for twice as many. `xs[i]` is the item where it is, and the index is checked in every build. A `for` over a list that is handed over gives each item to its round, and leaving early frees the items not reached; over `read xs` / `ref xs` the name points at the item. `xs.get(i)` is a look at the item or `null`. Limits of the back end for now: `get` cannot stand on the right of `??` (on the right of `&&` and `||` it can since the twenty-fifth slice); `indexOf`, `contains` and `sort` are compiled for integers, `bool` and text (`sort` is the C library's `qsort`, which does not keep equal items in order; that cannot be seen for these types). Decided on 12 November | Rust's `Vec<T>` is the same three words. The index check is what keeps memory safe; in `for i in 0..xs.length()` the C compiler removes it. The list benchmark runs in 1.02 times the time of C |
| Writing and comparing in compiled code | A struct, an enum or a list is written by a helper of its type (field by field or by its own `format`; text inside in quotes) into a text that is then printed: one allocation for a value that is written, none for numbers and text. A `Formatter` is that text. `==` compares two values where they are, through pointers, by the struct's own `equals` where it wrote one; `<` and the others call `compare`. `sort` keeps equal items in the order they had (a merge sort, with one block as large as the list while it runs). Decided on 12 November. Since the twenty-fifth slice (13 November) printing a struct allocates nothing: the value is written into one block that the program keeps and uses again (not straight into the output, so that a line still comes out whole; a block that one line made larger than 64 KB is given back as soon as it is empty), and `f.write` writes a struct straight into the text it is adding to. The block was approved on 13 November after writing straight into the output was measured (2.7 times slower: every piece is a call into the C library's output); `f.write` always writes so, which the rule for the values of a line makes possible (see "Order of evaluation"); both approved on 13 November | The same text as the interpreter's. Rust's `Display` allocates nothing and keeps no block; Rust's `sort` is stable too. The printing benchmark runs in 0.57 times the time of a C `printf` |
| Borrows and function values in compiled code | A field that borrows is a pointer to what someone else owns (for text a pointer and a length); it is never freed with the value that holds it, and `<from source>` leaves no trace in the compiled program. Looking at a field that itself borrows gives the pointer the field holds. A function value is the address of the function, and a call through it is an indirect call. A field of a value that has no name can be read (`longer(a, b).text`): the value is kept for the statement. Decided on 12 November | The checker did the work at compile time; at run time this is the pointer a C programmer writes. Rust's lifetimes and `fn` pointers cost the same: nothing |
| `HashMap` and `HashSet` in compiled code | Both are hash tables: the entries lie one after the other in one block, and a block of 32-bit slots says which entry a hash points at (open addressing, at most three quarters full); a removed entry is replaced by the last one. `map[key]` is the value where it is and a missing key stops the program; `get` is a look or `null`; `getOrAdd` copies the key only when it adds it; `remove` gives the value back. A `for` over a table that is handed over gives each entry to its round, and leaving early frees the rest. Keys are numbers, `bool`, text and `: Hashable` structs and enums. The hash has a secret key drawn from the system when the program starts (SipHash-1-3), so keys chosen by someone else cannot all be made to collide; this stays the default although it is not a memory-safety check, and a plain hash can be offered by name later. A table holds at most about two thousand million entries. Limit of the back end for now: `getOrAdd` with a key that owns memory other than text. Decided on 13 November | The default is the one that cannot go wrong. Rust's `HashMap` has the same keyed hash and pays the same: the table benchmark runs in 1.20 times the time of C, 0.99 with C's plain hash. Rust mixes the order of a table on purpose; this one, like C#'s `Dictionary`, does not |
| Order of evaluation | The parts of an expression are computed from left to right: the arguments of a call (the receiver first), the two sides of an operator, the fields of a literal, the values of a formatted text. The values of a formatted text (`$"..."`) are all computed before any of them is written: a `format` method runs when every value of the line is there (`$"{a} {say(3)}"` calls `say(3)` first, then `a`'s `format`; decided on 13 November, Rust's `write!` does the same, and it lets `f.write` put a struct straight into the text with no allocation). Compiled code keeps to it although C does not promise it: where the order can be seen (two parts that can stop the program or call a function, or one that lends with `ref` what another reads) the earlier parts are computed into variables first. Decided on 12 November | The interpreter always did this; a program must not depend on the C compiler it was built with. Nothing is paid where the order cannot be seen |
| `char` | 32 bits, holds every Unicode character (`Rune` in C#). `'+'` fits the expected type like a number constant: `byte` where a `byte` is expected, `char` where a `char` is expected, and `var c = '+'` gives a `byte`. A constant that does not fit in one byte (`'é'`) is a compile error where a `byte` is expected, and the hint is `char`. To walk through text character by character, `text.chars()` | C#'s 16-bit `char` splits an emoji into two parts, and that mistake should not be carried over. Cost: the same name, a different size from C# |
| Panic and buffers | `dispose` does not run on a panic, the last lines in a file buffer are lost, and this was accepted. `stdout` is flushed before the panic message. `writer.autoFlush = true` (the C# name) writes every line at once and is the recommended way for logs | The half-written file of a crashed program is not to be trusted anyway, and trying to write a buffer in a broken state means running code. Cost: a log that does not turn on `autoFlush` loses the lines from the moment of the crash |
| Narrowing conversion | Written `(int)x`. It follows the overflow rule (12 November): if the value does not fit it panics in a debug build and in tests, and is cut to size in a release build; `tryToInt` is checked in every build and `wrappingToInt` cuts in every build. *(Until 12 November: a panic in every build.)* `x.tryToInt()` returns `int?`, `x.wrappingToInt()` truncates on purpose. A conversion whose value is known at compile time and does not fit is a compile error: `(byte)300`. No warning on every conversion; hovering over it in the editor shows the possibility of a panic and the two methods, and the panic message shows the value and `tryToInt`. `(int)3.7` gives 3, `NaN` or out of range panics. A widening conversion (`int` → `long`) is implicit | C# truncates silently and a wrong number comes out. A warning on every line would also appear in correct code and would be ignored; `a + b` and `xs[i]` do not warn either. Cost: one comparison per conversion |
| `print` error | `print` does not return an error. If it cannot write, the program stops with a message, exit code 1. On a closed pipe (`program \| head`) it exits silently, like Unix tools. Whoever wants to handle the error writes `Console.out.writeLine(...)`, which returns a `Result` | If it returned an error, every line would need a `try`. Rust panics too, but it also prints a message on a closed pipe, and we differ there. Cost: the only exception to the rule that panic is "only for programmer errors" |
| `float`, `double` and `NaN` | The C# way. The `==` and `<` operators are as in the hardware: `NaN == NaN` is false. `equals` and `compare` give a total order: `NaN` is equal to itself and is the smallest, and `sort`, `max`, `contains` work. Both are `Equatable` and `Comparable`, not `Hashable`: `HashMap<double, V>` is a compile error | Rust splits equality and order into "partial" and "total", and `sort` does not compile on a list of fractional numbers; that means two more concepts. Cost: the rule "`a == b` means `a.equals(b)`" does not hold only for fractional numbers. The ban on keys can be relaxed later |
| `shared` cycle | It cannot be made a compile error: a tree without cycles also contains itself in its type. In test and debug builds, `shared` objects still alive when the program ends are reported: the count, the line where they were created, the field through which they hold each other, and the hint `weak`. No report in release | Rust counts a leak as safe and does not report it, an outside tool is needed. Cost: in release a leak stays silent. Example: [cities and roads](05-examples.md) |
| `share` and `null` | `share x` gives `null` if `x` is `null`, whether it is `weak` or not: `share cur.parent`, `share map.get(id)` | So that `if x is null` does not have to be written everywhere. `null` still stays `null`, nothing is hidden |
| Identity and equality | `a == b` compares content on every type, on `shared T` too; if `T` is not `Equatable` it is a compile error, and the hint is `same`. `same(a, b)` is `true` if two `shared` values point to the same object (`ReferenceEquals` in C#, `Rc::ptr_eq` in Rust). For a structure that refers back to itself (`City.roads`) the compiler cannot generate `equals`, and whoever wants it writes it by hand | In C# `==` looks at identity on a class and at content on a `string`, and one has to know which. Two words for two questions |
| Collection names | `HashMap<K, V>`, `HashSet<T>` (the Rust names; C# says `HashSet` too). `List<T>` stays. The old spelling was `Map`, changed on 11 November | The target audience comes from Rust. The name says that order is not guaranteed, and when an ordered version arrives the difference can be read from the name. `Vec` says nothing to a C# reader, `List` is clear to both sides |
| Module | A folder is a module. There is no module declaration in a file, the name comes from the folder path (`shop.stock`). Files in the same folder are one module and see each other without writing `use` | The Go way. In Rust a file is a module and `mod stock;` is written in the parent file, in C# `namespace` is written in the file and can drift away from the folder. Since there is nothing to write, there is nothing to write wrongly. Cost: a folder is created to split a large module |
| Visibility | A name without `public` is visible inside the module. One rule for types, functions, fields and methods, two levels. Enum variants are visible together with the enum. A `public` field can be written from outside, and if it should only be read, `public readonly` | Rust's rule (inside the module if there is no `pub`). In C# a field is private to the type and a type is open to the project; because there are free functions, that distinction would need a third word here. Cost: another file in the same module can change the field |
| Consequences of visibility | A `public` function, field or alias cannot expose a type that is not `public`, and the compile error shows both lines. A struct with a field that is not visible cannot be built outside with `T { ... }`, the hint is `T(args)` | Not a new rule, it follows from the visibility rule. The first is an error in C# and a warning in Rust; the second is the same in Rust too |
| `use` | `use stock` brings in all the `public` names of the module directly. It is written at the top of the file. If two modules have the same name, it is a compile error where the name is used, and the hint is the full name: `billing.Line`. The full name is valid without `use` too. On an unknown name the hint writes the missing `use` line | The word is from Rust, the behaviour is C#'s `using`: Rust lists names one by one (`use stock::Warehouse`). `using` is already taken for type aliases. Cost: which module a name comes from cannot be read from the code, the editor shows it |
| `use` details | Modules can `use` each other mutually. An unused `use` is not an error, the editor shows it dimmed. The basic standard names need no `use`: `List`, `HashMap`, `HashSet`, `string`, `Result`, `File`, `Console`, `print` and the others that appear in the earlier examples | Mutual use is allowed in Rust and C# too, and a ban (Go) pushes towards splitting code artificially. An unused `use` produces no wrong result, and if it were an error the code would not compile while experimenting. The ready names are as in new C# projects; in Rust `HashMap` and `File` need `use`. The exact list of ready names will be settled with the standard library |
| A program is a file or a folder | `sg main.sg`: that file alone is the root module, and the folders next to it are the modules it can name. `sg shop`: every `.sg` file of the folder is the root module. A module is read when a file names it, with `use` or with a full name; the test command with a folder reads every folder under it and runs the tests of all of them. A folder is a module only if its name can be written as a name. Decided on 13 November | The first form lets one folder hold many small programs, each with its own `main`; Go does the same (`go run file.go`, `go run .`). A folder nobody names is not read, so a mistake in it does not stop the program |
| Name of a module | Always the whole path from the root of the program: `use shop.stock`, also from inside `shop`. The root has no name: no module can `use` it, and `public` says nothing there, so the rule that a `public` name does not show a type that is not `public` is checked in the modules only. `use` lines stand before everything else in a file; the same line twice and a folder that is not there are errors. Decided on 13 November | One way to write a module, no short form to learn. Cost: a long path is written in full |
| Which name wins | A variable, then a name of the file's own module, then a `public` name brought in by `use`. A `Point` of your own next to a `use` that brings another `Point` is yours and no error; the other is `stock.Point`. The same name in two modules named with `use` is an error where it is used, for functions as for types. Decided on 13 November | C# and Rust do the same. Otherwise adding a name to a module could break every file that uses it |
| `readonly` goes all the way down | Nothing behind a `readonly` field can be changed: no assignment, no `ref`, no `ref this` method on it, no `add` on a `readonly List`. It holds inside the module too. The value that holds the field can still be replaced as a whole. Decided on 13 November | C#'s `readonly` goes all the way for a struct and stops at the assignment for a class; here every value is owned like a C# struct. No cost at run time |
| Modules in messages | `print` writes the name of a type without its module (`Product { ... }`); the checker's messages write the full name of a type of another module. The test command writes the module in front of a test's name (`stock: nothing ships`), and two tests may share a name in two modules, not in one. A name that was not found but is `public` in a folder nobody named gets the hint `use stock`. Decided on 13 November | The output of a program should not change when a type moves to another folder; an error should say exactly which type is meant |
| Modules in compiled code | `sg build` takes what `sg` takes, a file or a folder, and compiles the modules the program names with it into one C file; `test` blocks are not compiled, the test command runs them in the interpreter. A name of a module is written into its C name with each folder and its length in front (`shop.parts.Part` is `S_4shop_5parts_Part`); a name of the root is written as it is. A compiled panic names the file of the module it happened in. The stock and invoice example is compiled and compared with the interpreter. Decided on 13 November | No name of the root starts with a digit, so a root name and a module name never meet, and the lengths keep two modules apart whatever they are called. Nothing of this is seen from the language |
| Leaving in the middle of a line, in compiled code | A `match` gives its value inside a larger expression: it is written before the statement and the parts before it are computed first, so the order stays left to right. A value that owns something and has no name (an argument, a field of a struct being built, a value of an enum value) is kept under a name when something after it can leave the function (`try`, `?? return`, a `match`), and the way out frees it. Every compiled program is looked at for leaks by the tests, and the leak check itself is tried on a program that leaks on purpose. Still refused, as limits of the back end: leaving after an item of a list being built or after a side of an operator that owns something, in an argument of a method call, inside `$"..."`, on the right of `&&` and `\|\|`, inside `assert`. Decided on 13 November | Nothing is paid where nothing can leave; one store for each kept value where something can. A value left behind is not seen in the output or by the sanitizers, so it is looked for by name |
| Tests in compiled code | `sg test <path> --compiled` runs the `test` blocks as compiled code; without the word the interpreter runs them, as the reference that needs no C compiler. `sg build <path> --test` keeps the program that runs them. Each test runs in a process of its own, so a panic ends that test only, and the report is the interpreter's, letter for letter, with the exit code 1 if a test failed. A `try` that meets an error in a test writes it and ends the test, freeing what the test owns. `--only N` runs one test in the same process. The tests of the back end compare the two reports, run the compiled tests under the sanitizers and look at every passing test for leaks. For now POSIX only (`fork`). Decided on 13 November | The process per test is what "Test" decided; here it costs one `fork` for each test. The same `.out` file checks both ways of running, so they cannot drift apart |
| Slice type | `read T[]` is a readable window, `ref T[]` a writable one: pointer + length. A bare `T[]` is not a type, compile error; the hint is `List<T>` for an owner and `read T[]` for a window. What `read string` is for text, `read byte[]` is for raw data. Conversion to a slice: `read xs` and `ref xs` give a slice where a slice is expected (`parse(read buffer)`), for `List<T>` and `T[N]`; passing it without writing `read` is a compile error, and the hint is `read xs`. `xs[..]` stays valid as range notation | Rust's `&[T]` and `&mut [T]` types, in our notation. No new name is needed, `read` and `ref` are enough. In C# `T[]` is an owning array on the heap, here it is not: the same name, a different meaning, and the error hint says so. Conversion to a slice is the same rule as `string` → `read string`, and in Rust `&buf` works this way too. The first decision was `xs[..]` only; it made people memorise a separate notation for lists, and it changed on 11 November |
| Range | In the `a..b` notation the ends can be left out: `data[..end]` from the start, `data[start..]` to the end, `data[..]` the whole. The same on `string`, `List<T>` and slices | The same as Rust and C#. `data[0..end]` and `line[i..line.length()]` were noise, and no new concept is needed |
| Text and bytes | `text.asBytes()` views text as `read byte[]`, for free. `string.fromUtf8(bytes)` views bytes as text: it checks the UTF-8, does not copy, and returns `Result<read string, TextError>` | The Rust names (`as_bytes`, `str::from_utf8`). C# has no path without a copy. The `string` guarantee is kept: there is no unchecked conversion. The copying `string.fromBytes` was removed on 11 November, and whoever wants a copy writes `.clone()`: one way, and the copy is visible in the code |
| Fixed-size array | `T[N]`, where `N` is an integer constant: `int[8] values`. It is a value and stays where it is (on the stack or inside the struct), no heap. `length()` is known at compile time. `xs[i]` is bounds checked; if the index is known at compile time and out of bounds it is a compile error, and if it depends on data it panics. Construction: `int[3] { 1, 2, 3 }` writes the items (a compile error if the count does not match), `byte[16](255)` puts the same value in every item (`T` must be `Copyable`), and `byte[16]` alone fills with zero; a zero value exists only for numbers, `bool` (`false`) and `T?` (`null`), and for any other type it is a compile error. There is no uninitialised memory. If `T` is `Copyable` the array is `Copyable` too, otherwise it is moved (the struct rule). Conversion to a slice is in the "Slice type" row | Rust's `[T; N]` type, in our notation. C# has no natural counterpart (`stackalloc` only in locals, `fixed` only in `unsafe`). Without this every buffer goes to the heap through `List`, and C-level performance does not hold. For construction Rust writes `[1, 2, 3]` and `[255; 16]` and has no short form for zero; in C# `new byte[16]` is always zero, and the short form comes from there. Cost: `T[]` (a slice, needs `read`/`ref`) and `T[N]` (a value) look alike; a large array passed by value is copied silently; the cost of zeroing |
| A range that is written through | `xs[a..b]` on a list, an array or a slice is a `read T[]`: it only looks, as a range of text does. `ref xs[a..b]` is a `ref T[]` and needs what `ref xs` needs. `read xs[a..b]` is a compile error whose hint is the bare range. A `for` over a slice lends its items; a list cannot be changed inside a `for` over a range of it | Rust writes `&mut xs[a..b]`. One rule for every range: bare means "look", and the one word that asks for more is `ref`. Approved on 13 November 2026 |
| Arrays and slices, details | `T[0]` is a compile error. `byte[16]` alone builds an array when `byte` names a type and no variable has that name; in a condition `int[3] { ... }` needs parentheses, like a struct literal. An array and a slice have the methods of a list that only look (`length`, `get`, `indexOf`, `contains`); `==` compares the items in order when they are `Equatable`; `print` writes `[1, 2, 3]`. Only an index on an array is checked at compile time; the ends of a range and an index on a slice panic. Put off: an array of arrays, `read T[]?`, an array as a key | An array without items has no use and no natural form in C. The rest follows what `List` already does, so nothing new has to be learned. Approved on 13 November 2026 |
| `TextError` | A built-in struct, `TextError : Copyable, Formattable, Equatable`, with one field: `public readonly nint position`, the place of the first byte that is not valid UTF-8. Seen from every module with nothing written; the name is reserved | Rust's `Utf8Error::valid_up_to`. The design had named the type and nothing more; a position is what a caller can act on. Approved on 13 November 2026 |
| `Result` with a borrowed success | `Result<read T, E>` can be written; a function that returns one says where the borrow comes from with `from`, like any type that carries a borrow. A borrow as the error is not allowed yet | `string.fromUtf8` gives a `Result<read string, TextError>`, and a function must be able to pass it on. Approved on 13 November 2026 |
| A borrow of a value with no name | It cannot be kept: `var part = make()[..5]`, `var label = make().label()`, `return first(read make())`, and the same put into a field or an item are compile errors whose hint is to give the value a name. Inside one statement it is fine (`print(make()[..5])`). A text constant is exempt | The value a call returns lives until its statement ends, so a borrow kept longer looks at freed memory; compiled code showed it under the address sanitizer. Rust has the same rule ("temporary value dropped while borrowed"). Core principle: caught at compile time, with the fix in the hint. Approved on 13 November 2026 |
| Test | `test "name" { }`, a block written at the top level of a file. Only the test command compiles and runs it, it is not part of a normal build. `test` is a keyword only at the top level and when followed by a string, and it can be used as a name. A test belongs to the module of the folder it is written in: it sees every name of the module, and only the `public` names of other modules. In the block `try` works with every error type; an error fails the test and is printed (it must be `Formattable`, as for `main`). A failing test is a panic, and the test command runs each test in a separate process | Zig's notation. In Rust `#[test] fn` and `#[cfg(test)] mod tests`, in C# a separate project and a library, in Go a naming rule (a `_test` file, a function starting with `Test`). A separate `main` program cannot see what is not `public` and stops at the first error. Go's naming rule adds no word but makes people memorise two invisible rules, and a test name cannot be a sentence. The visibility follows from the module rule, it is not a new rule. Cost: one word; the only place where `try` works without a target error type being written; the time to start a process per test (a tooling decision) |
| `assert` | `assert(condition)`: panics if it is false. The message prints the text of the expression and, if it is a comparison, the values of both sides (if they are `Formattable`). Valid outside tests too, and on in release too. There is no `assertEqual` | A single form. In Rust three macros (`assert!`, `assert_eq!`, `debug_assert!`), in C# `Assert.Equal` is in a library and `Debug.Assert` is deleted in release. In the same direction as the rule that safety checks cannot be turned off. Cost: since there are no macros the compiler knows `assert`, like `$"..."` |
| Test command | `sg test file` compiles the file with its tests and runs them: one line per test, `ok    name` or `FAIL  name` followed by the panic or `error: ...`, then a count; exit code 1 if any failed. A test file needs no `main`. Two tests with the same name are a compile error. `try` on a `T?` in a test is a compile error (there is no caller to give `null` to; the hint is `assert(x is not null)`). `test "..."` inside a function is a compile error. Decided on 12 November | What the "Test" row left open. The interpreter runs the tests one after the other in one process, each with variables of its own; with no global state the difference to a process per test cannot be seen yet |
| End of line | No semicolons, the end of a line ends the statement. A statement continues on the next line in these cases: inside `(` or `[`; if the line ends with an operator, a comma, a dot or an opening parenthesis; if the next line starts with `.` (a method chain). A line cannot start with an operator, and the hint says to move the operator to the end of the previous line | Go's rule + Python's parenthesis rule; the leading `.` is for the chain notation of C# and Rust. A leading operator creates ambiguity (`- x`), a leading dot does not. Approved on 12 November together with the interpreter |
| Place of `{` and `else` | `{` at the end of the line, `else` on the same line as `}`: `if x {`, `} else {`. Writing them on a new line is a compile error, and the hint shows the right place | The Go way: a single form. C#'s usual layout (`{` on a new line) was deliberately not taken, there would be two ways to write the same thing |
| Statement | Only a call, an assignment and a declaration are written as a statement; `a + 2` alone is a compile error. A name at the start of a statement, followed by `*` and `?`, followed by a second name, is a declaration: `int x = 1`, `Node*? list = null` | The C# rule (CS0201). This way the distinction between `Node* n` and `a * b` is resolved with lookahead: `a * b` cannot be a statement anyway |
| Struct construction in a condition | In the head of an `if`, `while` and `for`, `{` starts the block; struct construction there needs parentheses: `if p == (Point { x = 1 }) {`. Everywhere else without parentheses | Rust's rule. `if x == Node { ... } {` cannot be told apart otherwise. Cost: two parentheses in a rare case |
| Assigning to a `ref` and a `read` variable | Assigning to a `ref` variable writes to what is borrowed: `void clear(ref int? slot) { slot = null }`. Assigning to a `read` variable rebinds the variable: `cur = read cur.next` | This is how a `ref` parameter works in C#, and no separate "write into it" operator (`*x = ...`) is needed. Since nothing can be written through a `read`, the only meaning of assigning to it is rebinding |
| Looking does not move | The two sides of an operator, a method receiver and the arguments of `print`, `assert` and `$"..."` are borrowed only for that moment: `name` can be used after `print(name)`. A value is moved when it is given to a variable, a field, a parameter or a `return` | `a == b` already means `a.equals(b)` and takes `read`; `print` too reads the `Formattable`. In Rust `println!` gives the same result because it is a macro |
| Language name | SG. Source files end in `.sg` | The author's initials; short, and free as an extension. Decided on 12 November 2026 |
| Method names `replace` and `take` | A struct cannot define a method named `replace`. `take` can be defined | `x.replace(value)` exists on every type, so a method of that name would clash with it. The built-in `take` exists only on `T?`, and a method is never called on a `T?`. Approved on 12 November with the interpreter's third slice |
| Name clashes | A method and a field of the same struct cannot share a name. A function cannot have the name of a type | A name on a struct should mean one thing. `Stack(...)` always means `Stack.create(...)`. Approved on 12 November |
| `Name.f()` | A variable called `Name` wins over a type called `Name` | The nearer name wins, as everywhere else. Approved on 12 November |
| `take` and narrowing | `take` on a variable known not to be null ends that knowledge: the variable is `T?` again | `take` puts `null` in its place. Approved on 12 November |
| `ref this` on a new value | A `ref this` method can be called on a value that was just built: `Stack().push(1)` | The same as Rust. No variable is needed just to make the call. Approved on 12 November |
| `this` by value through a `T*` | A method that takes `this` by value, called through a `T*`, uses the pointer up | Taking `this` by value moves the value, and the pointer is its owner. Approved on 12 November |
| Moving a field out of an owned value | A field can be moved out of an owned value. Moves are tracked per field: the other fields stay usable, and the value as a whole is unusable until the field is assigned again | Follows from the `take`/`replace` rule, which restricts only a move through a `ref`: an owner may give up a part. Implemented in the interpreter's third slice on 12 November |

## Deliberately deferred

- **comptime:** later.
- **Not in the first version:** async, macros.
- **After the first version:** implementing an interface outside the definition of the type (`extend`), using an interface
  as a type (`read Shape`), associated types, default method bodies, operator definitions, constant parameters, nested patterns
  (`Add(Number(a), b)`), a variable that `is not` opens into the outer scope, a format specifier inside `$"..."` (`{x:N2}`), a `sync` that pushes the data to disk after `close` (`Flush(true)` in C#), generic type aliases (`using Link<T> = shared checked T`), lazy list chains (like LINQ).

*Deferred on 12 November 2026: generics of your own.* They cost nothing at run time, but they are the largest source of
concepts in the design (type parameters, `where`, your own `interface`, associated types, conditional `Copyable`), and
eleven slices of the interpreter ran without them. `Result<T, E>`, `T?`, `List<T>`, `HashMap<K, V>` and `HashSet<T>`
are known to the compiler and stay generic; the built-in interfaces stay as names written after `:`. A container of your
own is written for the type it holds. If a real need shows up it is talked through with that example. The rows moved
out of the decisions table, as they were:

| Topic | Decision | Reason |
|---|---|---|
| Generics | C# notation, compiled separately for each type | No run-time cost, in exchange the binary grows |
| Form of `where` | Several conditions as `where T : A, B`, a separate `where` for each subject, in any order: `where K : Hashable where r from name`. At type level `struct TopList<T> where T : Comparable`, and a function that uses the generic writes the condition again. A method can put a condition on the type's parameter: `void sort(ref this) where T : Comparable`, and if the type does not meet the condition only that call gives an error | C# notation. C# has no condition on a method, but without the deferred `extend` this is how `List<T>.sort()` is written |
| `for` pattern | Works by pattern, like `foreach` in C#. `takeItems()` is called for `for x in xs`, `readItems()` for `read`, `refItems()` for `ref`, and the returned value implements `Iterator<T>`. If the value is already an `Iterator` it is used directly | It could not be written with an interface, because associated types and overloading on the receiver are deferred |

## Open questions

- Generics: closed on 12 November 2026 as "deferred", see the section above.

- Notation. The [C# variant](02-syntax-draft.md) is the current draft, and it will be stressed with example programs.
- Library boundary: in a library with more than one folder there is no level for "my own folders can see it, the user cannot"
  (`internal` in C#, `pub(crate)` in Rust). To be handled together with the package system.
- Stack overflow on deep structures: freeing a long linked list is recursive. For types that contain themselves the compiler could turn freeing into a loop,
  and the overflow could be a readable panic. Not tested.
- Inside `Func<read T, U>`, `U` cannot depend on the argument, so `orders.map(o => read o.customer)` does not compile and `.clone()` is needed. Whether this has to be overcome has not been tested.
- Type-first grammar without semicolons: the distinction between `Node* n` and `a * b`, and between `Node? x` and `a ? b : c`,
  needs lookahead. The end-of-line rule must also be settled at the interpreter stage. A `T { ... }` initialiser cannot be told apart from a block
  inside a condition (`if x == Node { ... } {`); parentheses could be required there, as in Rust.
  *12 November 2026:* the end-of-line rule, the place of `{`/`else` and the statement rule were approved and are in the decisions table. The `Node* n` and `Node? x`
  distinction was resolved by the statement rule. `T { ... }` inside a condition was also decided the same day ("Struct construction in a condition").
  This item is closed.

## Performance note

Notation does not affect the machine code: `read`, `ref`, `from` and type names disappear at compile time. Decisions about meaning do.
None of this has been measured, and what follows are expectations.

| Effect | Decision | Compared to Rust |
|---|---|---|
| Same | `T*`, `read`, `ref`, `T?`, `enum`, `match`, `Result`, `try`, monomorphization, bounds checks, `locked` | The same rules, the same optimisation information |
| Better | Panic does not unwind | Like Rust's `panic=abort` setting: no cleanup path is generated, and the binary gets smaller |
| Same | Overflow is checked in debug and wraps in release | Changed on 12 November from "checked in release too". One difference in the C that is generated: a wrapping operation is written with unsigned arithmetic, so the C compiler cannot assume "this never overflows" as it does for C's own `int` |
| Worse | `shared` is always atomic | More expensive than `Rc`, only on `share` and when an owner lets go |

This goal holds only with a back end at the level of LLVM. A tree-walking interpreter is for testing the language and gives no performance.

*First measurement, 12 November 2026.* The first slice of a back end writes C and lets the C compiler optimise
(integers, functions, structs, `read`/`ref`). Against the same programs written by hand in C, with the same `-O2`, and
with overflow checked in release as the design then said: trial division 0.97 times the time of C, recursive Fibonacci
1.38, a Collatz loop 1.59. The check cost nothing where arithmetic is rare and up to about 60% in a loop that is nothing
but arithmetic. On this measurement the overflow rule was changed to Rust's (checked in debug, wrapping in release); after the
change a release build runs the three programs in 0.96, 0.98 and 1.00 times the time of C
([interpreter/README.md](../interpreter/README.md)). The first program with memory (text read byte by byte, compared, copied to the heap and freed) runs in 1.05 times the
time of C: that is the cost of the checks that stay, on every index and every range. The first program that follows
pointers (a linked list of a million nodes built with `new`, walked and freed) runs in 1.01 times the time of C: a
`Node*?` is one pointer and `is not null` one comparison. The first program with an enum (an expression tree
built, evaluated with `match`, rewritten and freed) runs in 1.02 times the time of C written as a tagged union and a
`switch`. The first program with errors as values (numbers read out of text, an error found three calls deep and
passed up with `try`) runs in the time of C that returns error codes (0.99 to 1.02): a `Result` is a tag and a value,
and `try` is one test. The first program with a list (a million numbers added, changed through their index, added
up and freed) runs in 1.02 times the time of C that keeps a growing array by hand. One thing it showed about the
overflow rule: in a loop that is nothing but arithmetic on its counter, wrapping can cost what C's undefined signed
overflow saves (1.28 on such a loop, until the arithmetic was taken out of the measurement). Rust pays the same.
The first program with a hash table (a million numbers counted under fifty thousand keys) runs in 1.20 times the time
of C; all of it is the keyed hash (SipHash-1-3, as in Rust), and with the plain hash of the C program the two take the
same time. Printing two million structs first took 1.22 times the time of C's `printf`, because each printed value was
allocated; written into one block that the program keeps, it takes 0.57 times (a `printf` reads its format on every call).

## Dropped decisions

These no longer hold and are here for the record. Apart from the data race and recoverable error items, they were dropped on 5 November
together with the generation model and the arena:

- Run-time generation checks for use-after-free (generational references).
- An 8-byte pointer whose top 16 bits are the generation. The decision on generation width (16 bits, mask, no TBI) had been made
  the same day, and it lost its subject when the model was dropped.
- Retiring a slot that overflows.
- A slab allocator and a standard arena API as part of the language.
- `ref` being a second-class parameter mode that is only passed downwards.
- Data races being out of scope in the first version. With threads present, a non-atomic counter leads to a double free,
  so the subject touched memory safety; the thread rule is in the decisions table.
- Settling for escape analysis and avoiding lifetime notation altogether.
- Recoverable errors being left out because they need unwinding. The reasoning was wrong: an error returned as a value
  needs no unwinding (6 November).

Removed on 11 November to make the language smaller. All of them can be added back later, and it is hard to remove something once it has been added:

| Removed | Instead | Cost |
|---|---|---|
| The heavy version of `Closable`: tracking the value everywhere, spreading to structs, the ban on generics and `shared`, `IgnoreClose`, the deferred `try using var` | The version that looks only at local variables, "Close error" in the decisions table | If a value moved into a field or a collection is dropped without being closed, the compiler does not see it |
| Automatic `Ok` | `return Ok(value)`, `return Ok()` | A few characters on every success return |
| The "assign back on every exit" check when moving a field through a `ref` | Always `take` or `replace` | Negligible, Rust is the same |
| A block that produces a value on its own, `var x = { ... }` | The variable is declared and assigned inside `if/else`. The block in a `match` arm stays | A few lines |
| `ThreadFunc`, `shared Func` | Thread work starts with `spawn f(args)` | A work queue that takes lambdas (a thread pool) cannot be written in user code |
| `string.fromBytes` | `string.fromUtf8(bytes)`, `.clone()` for a copy | None |

Removed on 12 November. The measure, in the author's words: performance and simplicity are not given up. Lambdas lost on both:

| Removed | Instead | Cost |
|---|---|---|
| Lambda notation (`o => ...`) and capture: borrowing without `new`, moving with `new`, the hidden `checked` on what a lambda writes to, `Func<...>*` as an owner, the rules for writing after a copy and for moving out of a lambda | A function value is the address of a named function ("Function value" in the decisions table). Data a rule needs is passed as a parameter or carried in an `enum` variant | A few more lines where a one-line lambda stood; in exchange no run-time check, no heap, and about ten rules fewer |
| The list methods that take a lambda: `filter`, `map`, `any`, `forEach`, `removeAll`, `sortBy` | A `for` loop; `sort` with `Comparable` | The loop is written out. The machine code is the same or better |

## Notes on the first drafts

Noticed on 5 November 2026, on a second reading of the first day's texts.

### Gaps in the first memory model

The memory model gaps in this section lost their subject when the generation model was dropped, and they are kept for the record.

- **An arena cannot be invalidated "in a single operation".** The model both keeps the generation in the slot header and says "when the arena
  dies all slot generations increase, a single operation". With a generation per slot, the work is proportional
  to the number of slots. For a truly single operation the generation must be at arena level, and then where the check
  looks, with the same pointer layout, has to be solved again.
- **ARM TBI does not cover 16 bits.** Solved: 16 bits and a mask were chosen, the reason is in the decisions table.
  The sentence "on ARM, TBI gives the mask for free" in the memory model does not hold.
- **Retired memory is not negligible.** The memory model says "the memory loss is negligible". With a 64-byte
  slot and 1 million alloc/free per second, at 16 bits that makes about 84 MB a day and about 30 GB a year
  (a calculation, not a measurement). The physical memory of a fully retired page must be given back to the operating
  system. The loss then shifts to the virtual address space, but a single long-lived object left on a page prevents
  the page from being given back.
- **If an empty page is given to another size class, generations can match by chance.** The slot boundaries shift, and an old
  pointer lands on a new slot. New generations must start above the highest old generation on the page.
- **What happens if `&` is taken to a field on the heap?** The model defines `&T` for local variables.
  `&n.value` is undefined. If this expression produces an unchecked `&T`, use-after-free comes back when the function it is
  passed down to frees the object. It looks as if a reference to a heap field has to produce a generation-checked
  `*T`.
- **2-10 percent is not this design's figure.** That measurement is for Vale's layout. Here, on every dereference,
  the slot is additionally computed from the page header and the generation is read from the header. The claim "cache behaviour is the same as
  C" also holds only for pointer size. The cost must be counted as unknown until it is measured.
