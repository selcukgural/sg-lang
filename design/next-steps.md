1. Reach 10-15 example programs in total, and compare the notation across 2-3 variants. Written so far: calculator, stack, threads, `List`, log
   summary, folder tree, order rules, cities and roads (graph), stock and invoice (modules, `use`), HTTP request (byte slice), sensor window (fixed-size array), stock tests (`test`, `assert`; approved on 12 November). The next example has not been chosen.

   Fourth slice (the same day): `enum`, `match` (expression and statement, `when`, `_`, `var other`, the check that every

Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-69) (501 to 516) and were approved the same day (["Raw memory, as built"](rules/c-and-the-machine.md#raw-memory-as-built) to ["Raw memory, measured"](rules/c-and-the-machine.md#raw-memory-measured)). Seventieth slice (15 November): the second of the three, in the checker, the interpreter and compiled code together: `extern` blocks and their calls inside `unsafe`, the libraries they link, `CString`, `string.fromCString` and `buffer.pointer()`; the interpreter calls C through a library of wrappers it builds with `cc` and opens with `dlopen`, compiled code calls C directly, and zlib is wrapped in a module whose users write no `unsafe` (`examples/zlib`). Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-70) (517 to 530) and were approved the same day (["Calling C, as built"](rules/c-and-the-machine.md#calling-c-as-built) to ["Calling C, measured"](rules/c-and-the-machine.md#calling-c-measured)). Seventy-first slice (15 November): the last of the three, in the checker, the interpreter and compiled code together: `Disposable` and `Closable` on structs of the program, types of C seen only behind a pointer (`struct sqlite3` in an `extern` block), and structs of plain data given to C and given back by value; zlib's stream is wrapped in a `Deflater` that gives back what zlib holds when it ends (`examples/zlib`), and compresses a gigabyte in 1.04 times the time of the same calls in C. Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-71) (531 to 544) and were approved the same day (["`Disposable`, as built"](rules/ownership.md#disposable-as-built) to ["A library that keeps state, wrapped"](rules/c-and-the-machine.md#a-library-that-keeps-state-wrapped)). Seventy-second slice (15 November): the clock, the first item of the plan after calling C, in the checker, the interpreter and compiled code together: `Instant` (the monotonic clock), `Duration` (a span of time in nanoseconds) and `DateTime` (the calendar in UTC), written in SG in the language's own module `std`, which a program gets when it names one of them; only the two readings of the clock are the compiler's. A delay in the interpreter now waits its time on the real clock too, also after a long computation. Ten million readings of the clock take the time of `clock_gettime` in C, and taking ten million moments apart takes 0.29 times `gmtime_r`. Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-72) (545 to 555) and were approved the same day (["The clock, as built"](rules/library.md#the-clock-as-built) to ["The clock, measured"](rules/library.md#the-clock-measured)). Seventy-third slice (15 November): random numbers, the next item of the plan, in the checker, the interpreter and compiled code together: `Random` (xoshiro256** seeded with SplitMix64, the same numbers for the same seed everywhere, not `Copyable`, lent with `ref`, no generator the program does not make) and `SecureRandom` (the random bytes of the system, for keys and tokens, with `hexString`), written in SG in a second file of the module `std`; only the random bytes of the system are the compiler's, and the key of a hash table is drawn with the same function. The language has no overloads, so the 64 random bits are `nextUlong()` and `nextLong(low, high)` is the range. A hundred million numbers in a range and a gigabyte of the system's bytes take the time of the same code in C. Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-73) (556 to 566) and were approved the same day (["Random numbers, as built"](rules/library.md#random-numbers-as-built) to ["Random numbers, measured"](rules/library.md#random-numbers-measured)). Seventy-fourth slice (15 November): folders, paths and the environment, the next item of the plan, in the checker, the interpreter and compiled code together, with the twelve decisions taken before it. `File.delete`, `File.move` (never takes the place of a file, told in the same step as the rename), `File.replace` and `File.copy` are built in; `Directory`, `DirectoryEntry`, `FileInfo`, `FileKind`, `Path`, `Environment` and `VariableError` are written in SG in three more files of the module `std`, over calls of the system that only that module makes, and `File.info` and `File.exists` are done there too. A listing is sorted by the bytes of the names, `deleteAll` never follows a link, and the variables of the environment are only read. `IoError` has three more variants. Listing a folder of ten thousand files and asking about a file take the time of `readdir` and `stat` in C. Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-74) (567 to 580) and were approved the same day (["Folders and files, as built"](rules/input-output.md#folders-and-files-as-built) to ["Folders, measured"](rules/input-output.md#folders-measured)). Seventy-fifth slice (15 November): three small leftovers of the slices before it, in the checker, the interpreter and compiled code. `wait` takes the task a call gives in one line (`Task.delay(100).wait()`), as `await` already did; a panic inside the language's own module is shown at the call of the program that led there, without the hint that named the module's code, as `#[track_caller]` does in Rust (compiled code hands the place of the call to the functions of the module as one more parameter); and `for` over what a `try` opens is compiled; `assert(a < b)` on a struct with its own `compare` no longer makes the C compiler warn, and the C of every program now compiles under `-Wall -Wextra -Werror` with clang and gcc, which the tests hold it to (one warning left on: a function nobody calls). Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-75) (581 to 587) and were approved the same day (["Waiting for a task in one line"](rules/concurrency.md#waiting-for-a-task-in-one-line) to ["The C, without warnings"](rules/tools.md#the-c-without-warnings)). Seventy-sixth slice (15 November): a local variable nothing reads is a compile error, decided before the slice (["A variable nothing reads"](directions/calling-c.md#a-variable-nothing-reads)): one never used and one only written, the name of a `for` and of a pattern with `_` for one not needed, a write to a copy of a struct with the borrow as its hint. The checker notes what each name stands for, and a pass of its own tells reads from writes after every other check; compiled code no longer tells the C compiler these names are used, so its warnings check the rule a second time. It found 51 names nobody used in the code already written. Its choices are in [the record of 15 November](decisions/2026-11-15.md#slice-76) (588 to 596) and were approved the same day (["A variable nothing reads, as built"](rules/statements.md#a-variable-nothing-reads-as-built), ["The rule, built and followed in C"](rules/statements.md#the-rule-built-and-followed-in-c)). Seventy-seventh slice (16 November): another program run and waited for, decided before the slice: `Command` with `arg`, `args`, `directory`, `setVariable`, `removeVariable`, `clearVariables` and `input`, and `run`, `output` and `status`, written in SG in the language's own module over two calls of the system. No shell reads the words, a name is looked for only in the folders of `PATH` that start with `/`, an end with anything but 0 is an error of `run` and `output`, the program gets an environment of its own and none of our descriptors (four `open` calls of the runtime were found without close-on-exec), and an async function does not make these calls. The value of every call is now an error when nobody uses it (`try cmd.status()`, `xs.removeLast()` or a function of your own alone, `_ =` to drop it), closing a gap the slice found; it replaces the two rows that let some calls stand alone. Its choices are in [the record of 16 November](decisions/2026-11-16.md#slice-77) (597 to 616); they were approved the same day. Seventy-eighth slice (16 November): a program started and talked to while it runs, decided before the slice: `cmd.start()` gives a `Process`, the pipes asked for with `pipeInput`, `pipeOutput` and `pipeError` are taken out of it once as streams (`takeInput`, `takeOutput`, `takeError`, each a `T?`), `wait` takes it and closes the input it still holds, `kill` and `terminate` stop it, and one that is not waited for is a compile error in a local variable and stopped with the signal 9 anywhere else. `runAsync`, `outputAsync`, `statusAsync` and `waitAsync` take a token that may come last, and a cancel stops the program. For them, and chosen by the user during the slice, a method can now be async, and a function of the language's own module may leave out a token that comes last. Its choices are in [the record of 16 November](decisions/2026-11-16.md#slice-78) (617 to 634); they were approved the same day. Seventy-ninth slice (16 November): the Unicode tables (17.0), decided before the slice: `isLetter`, `isNumeric`, `isAlphanumeric`, `isUpper`, `isLower` and `isControl` on `char` by the general categories, `toUpper` and `toLower` on `char` one character for one and on a text by the full mappings with Final_Sigma, `equalsIgnoreCase` and `foldCase` by the full folding, no language taken into account (the Turkish mappings left for later), and one set of tables made from the Unicode Character Database for the interpreter and compiled code. Its choices are in [the record of 16 November](decisions/2026-11-16.md#slice-79) (635 to 647); they were approved the same day. Eightieth slice (16 November): datagrams, decided before the slice: `UdpSocket` (`bind` as `TcpListener.bind`, `sendTo`, `receiveFrom` giving a `Received` with `count` and `from`, `connect` with `send` and `receive`, every method through a `read` borrow, no `close`, the async versions with a token), `SocketAddress` written in the language's own module (`parse`, `lookup`, `lookupAsync`, printed as RFC 5952 asks), the new variant `IoError.MessageTooLong` for a datagram that does not fit, and the two addresses of a `TcpStream`; multicast and broadcast later. Its choices are in [the record of 16 November](decisions/2026-11-16.md#slice-80) (648 to 666); they were approved the same day (["Datagrams"](rules/input-output.md#datagrams) to ["Datagrams in compiled code"](rules/input-output.md#datagrams-in-compiled-code)). Eighty-first slice (16 November): the first of three slices toward the scheduler of Tokio, written in the C of the runtime with no library, decided before the slice after a measurement found the async echo 28 times C on Linux: the loop of the network has no thread of its own, a thread of the pool with nothing to do waits on it, and one thread at a time is woken to look for work. Its choices are in [the record of 16 November](decisions/2026-11-16.md#slice-81) (667 to 677); they were approved the same day (["One runtime"](directions/async.md#one-runtime), ["The loop of the network"](directions/async.md#the-loop-of-the-network), ["The network in compiled code"](rules/input-output.md#the-network-in-compiled-code), ["The network the async way, measured"](rules/input-output.md#the-network-the-async-way-measured)). Eighty-second slice (16 November): the second of the three, a socket goes on the loop of the network once, the first time a task waits for it, edge-triggered, and stays until it is closed; a wait is no call of the system, and the copy of a socket made for each wait of a listener or a datagram socket is gone. Its choices are in [the record of 16 November](decisions/2026-11-16.md#slice-82) (678 to 689); they were approved the same day (["The loop of the network"](directions/async.md#the-loop-of-the-network), ["The network in compiled code"](rules/input-output.md#the-network-in-compiled-code), ["The network the async way, measured"](rules/input-output.md#the-network-the-async-way-measured)). On the way it was found that macOS gives `EAGAIN` to `MSG_DONTWAIT` while another thread receives from the same socket, though a datagram is there, so a datagram socket now stops blocking on its first async call, as a connection does. Eighty-third slice (16 November): the last of the three, each thread of the pool has a ring of 256 tasks of its own, from which the others steal half when they have nothing, and a slot for the task that the task it runs woke, which runs next, three in a row at most; a task woken outside the pool goes on a queue the threads share. The async echo takes 0.89 times C on macOS and 7.4 times on Linux (18.7 before, Tokio 5.5), with 450,000 calls of `futex` instead of 1.1 million. Its choices are in [the record of 16 November](decisions/2026-11-16.md#slice-83) (690 to 702); they were approved the same day. On the way, Tokio's rule that the thread which finds work always wakes the next was found to wake a thread for nothing on each async read of the input, so it wakes the next only if work is left. 3. Once the language is complete: write a program that is known and used in the industry, and has not been rewritten in Rust yet, in SG. Noted on 13 November. The speed-ups reported for programs rewritten in Rust come mostly from leaving an interpreted language for compiled code; C or Zig would have given the same. SG's claim is that speed together with memory safety in a language as small as C, and a real program is where it can be shown. The program was chosen on 13 November: **gifsicle**, the C tool that shrinks and edits GIF images. It has not been rewritten in Rust (there is a crate that wraps its C code, and one part of it, the lossy LZW compressor, was rewritten); its work is bytes and bits (LZW decoding and encoding, cutting down the colours, resizing), so the same algorithm can be measured against the C original; and it has had a memory bug of the kind SG rules out (CVE-2023-36193, a heap overflow set off by a crafted GIF). The program does not decide the order of the slices: the language goes on in its own order, and the program is taken up when the language is further along. Others that were looked at: jq (has a Rust clone, jaq, and is slow C, so being faster than it would not show much about the language), cmark (comrak is a line-by-line Rust port), and a part of Redis (the best known, but it needs the network, an event loop and time first).
