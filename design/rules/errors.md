# Errors and panics

Errors as values (`Result`, `try`, `??`) and what a panic does. Each row is a decision with its reason, in the order it was made; the choices
of each slice are in [the records by day](../decisions/README.md), and the other topics in
[the decisions by topic](README.md).

**On this page:** [Panic](#panic) · [Recoverable errors](#recoverable-errors) · [Error propagation](#error-propagation) · [`Result` unwrapping](#result-unwrapping) · [Error conversion](#error-conversion) · [Unused `Result`](#unused-result) · [Type of `Ok` and `Error`](#type-of-ok-and-error) · [Taken names](#taken-names) · [`Result` in a variable](#result-in-a-variable) · [`_ = e`](#underscore-e) · [`??` on `Result<void, E>`](#question-question-on-result-void-e) · [`tryDivide`](#trydivide) · [`Result` in compiled code](#result-in-compiled-code) · [Panic and buffers](#panic-and-buffers) · [`Result` with a borrowed success](#result-with-a-borrowed-success)

| Topic | Decision | Reason |
|---|---|---|
| <a id="panic"></a>Panic | Only for programmer errors (array bounds, `checked` conflict), the whole process stops. The only exception is `print`, in the ["`print` error"](input-output.md#print-error) row | No unwinding. Errors expected from the environment are returned as values with `Result` and need no unwinding |
| <a id="recoverable-errors"></a>Recoverable errors | `Result<T, E>` is an ordinary enum: `Ok(T value)`, `Error(E cause)`. Success is `return Ok(value)`, and for an operation that returns no value `Result<void, E>` and `return Ok()`, matched as `Ok()` or `Ok` (choice 2150, 28 November 2026). `main` can return it too, the error is printed and the exit code is 1 When the output cannot be written either (a full disk), the program's error is told first and then the output's, exit code 1 (choice 1603, 20 November); a pipe whose reader is gone is not told. | No new type feature is needed, and because it is a value it can be stored and passed to generic code. The `int f() fails E` notation was ruled out for this reason |
| <a id="error-propagation"></a>Error propagation | `try x`, a prefix like `await`. On an error it returns to the caller, on a `T?` it returns `null`. Parentheses in a chain: `(try a()).b()` | `?` is used as a type suffix. Returning through `try` is a normal exit, `dispose` runs |
| <a id="result-unwrapping"></a>`Result` unwrapping | `x ?? default`, `x ?? panic("message")`. There can be a `return` on the right of `??` | The same operator as for `T?`, like `x ?? throw` in C# |
| <a id="error-conversion"></a>Error conversion | `try` finds by itself the variant of the target error type whose only field is the source type. If there is none or more than one, a compile error | No hand-written `From` as in Rust, and no macro either |
| <a id="unused-result"></a>Unused `Result` | Compile error, and `_ = f()` to discard on purpose. A `Result` that is assigned to a variable and never unwrapped gives the same error, an exit through `try` is exempt | An error should not be lost silently |
| <a id="type-of-ok-and-error"></a>Type of `Ok` and `Error` | `Ok(...)` and `Error(...)` take their type from where the value goes, like `null`: a `return`, a declaration with a type, an argument, a field. `var r = Ok(1)` is a compile error, and the hint is to write the type | Nothing in `Ok(1)` says what the error type is. Rust infers it from later lines; here a line is read on its own |
| <a id="taken-names"></a>Taken names | `Result`, `Ok` and `Error`: no type called `Result`, no function called `Ok` or `Error`. A variant of your own enum can be called `Ok` (`Status.Ok`) | The short names must mean one thing everywhere |
| <a id="result-in-a-variable"></a>`Result` in a variable | "Never unwrapped" is checked as "never looked at": any read of the variable counts (`try r`, `r ?? 0`, `match r`, `r is Ok(v)`, passing it on) | Exact for the common mistake, and needs no flow analysis |
| <a id="underscore-e"></a>`_ = e` | Drops any value on purpose, not only a `Result`. On a call that returns nothing it is a compile error | One way to say "I do not want this"; with `void` there is nothing to drop |
| <a id="question-question-on-result-void-e"></a>`??` on `Result<void, E>` | Compile error; the hint is `try` or `_ = ...` | Success carries nothing, so there is nothing to fall back to |
| <a id="trydivide"></a>`tryDivide` | Gives `null` for division by zero too, not only for overflow | Rust's `checked_div`. "`null` where the operator would panic" is one rule for the whole `try...` family |
| <a id="result-in-compiled-code"></a>`Result` in compiled code | A `Result<T, E>` has the shape of an enum: a tag of one byte and room for the larger of the value and the error; a `Result<void, E>` is the tag and the error. `try` is one test of the tag and, on an error, a `return`: the error is moved, wrapped in the caller's error type where that is asked for (one more tag), and the function frees what it owns on the way out. `??` frees the error, then computes the right side. A `Result` moved out of its place gets the tag 255, like an enum. An error that `main` ends with is written as `error: ...` and the exit code is 1. Limits of the back end for now, not rules of the language: `try` and `?? return` are compiled wherever no value that owns something was computed before them in the statement and is still without a name (after such an argument or field only since the twenty-eighth slice, which keeps it under a name; not as an argument of a method call, inside `$"..."`, on the right of `&&`, `||`, `??`, or inside `assert`); the error of `main` is text, a number or a `bool`. Decided on 12 November | No unwinding and no tables: an error costs what a returned value costs. Rust's `Result` and `?` are the same, with the tag packed further. The parsing benchmark runs in the time of C that returns error codes (0.99 to 1.05) |
| <a id="panic-and-buffers"></a>Panic and buffers | `dispose` does not run on a panic, the last lines in a file buffer are lost, and this was accepted. `stdout` is flushed before the panic message. `writer.autoFlush = true` (the C# name) writes every line at once and is the recommended way for logs | The half-written file of a crashed program is not to be trusted anyway, and trying to write a buffer in a broken state means running code. Cost: a log that does not turn on `autoFlush` loses the lines from the moment of the crash |
| <a id="result-with-a-borrowed-success"></a>`Result` with a borrowed success | `Result<read T, E>` can be written; a function that returns one says where the borrow comes from with `from`, like any type that carries a borrow. A borrow as the error is not allowed yet | `string.fromUtf8` gives a `Result<read string, TextError>`, and a function must be able to pass it on. Approved on 13 November 2026 |
