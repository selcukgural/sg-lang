# Modules and packages

How a program is split into modules, what each one shows, and packages. Each row is a decision with its reason, in the order it was made; the choices
of each slice are in [the records by day](../decisions/README.md), and the other topics in
[the decisions by topic](README.md).

**On this page:** [Module](#module) · [Visibility](#visibility) · [Consequences of visibility](#consequences-of-visibility) · [`use`](#use) · [`use` details](#use-details) · [A program is a file or a folder](#a-program-is-a-file-or-a-folder) · [Name of a module](#name-of-a-module) · [Which name wins](#which-name-wins) · [`readonly` goes all the way down](#readonly-goes-all-the-way-down) · [Modules in messages](#modules-in-messages) · [Modules in compiled code](#modules-in-compiled-code) · [Packages](#packages) · [Packages, as built](#packages-as-built) · [The folder `internal`](#the-folder-internal)

| Topic | Decision | Reason |
|---|---|---|
| <a id="module"></a>Module | A folder is a module. There is no module declaration in a file, the name comes from the folder path (`shop.stock`). Files in the same folder are one module and see each other without writing `use` | The Go way. In Rust a file is a module and `mod stock;` is written in the parent file, in C# `namespace` is written in the file and can drift away from the folder. Since there is nothing to write, there is nothing to write wrongly. Cost: a folder is created to split a large module |
| <a id="visibility"></a>Visibility | A name without `public` is visible inside the module. One rule for types, functions, fields and methods, two levels. Enum variants are visible together with the enum. A `public` field can be written from outside, and if it should only be read, `public readonly`. *(28 November 2026, choice 2254: there is no `private`; `private int x` is refused with the hint that a name without `public` stays in its module, and that a type whose fields the files beside it must not touch goes in a folder of its own)* | Rust's rule (inside the module if there is no `pub`). In C# a field is private to the type and a type is open to the project; because there are free functions, that distinction would need a third word here. Cost: another file in the same module can change the field |
| <a id="consequences-of-visibility"></a>Consequences of visibility | A `public` function, field or alias cannot expose a type that is not `public`, and the compile error shows both lines. A struct with a field that is not visible cannot be built outside with `T { ... }`, the hint is `T(args)` | Not a new rule, it follows from the visibility rule. The first is an error in C# and a warning in Rust; the second is the same in Rust too |
| <a id="use"></a>`use` | `use stock` brings in all the `public` names of the module directly. It is written at the top of the file. If two modules have the same name, it is a compile error where the name is used, and the hint is the full name: `billing.Line`. The full name is valid without `use` too. On an unknown name the hint writes the missing `use` line | The word is from Rust, the behaviour is C#'s `using`: Rust lists names one by one (`use stock::Warehouse`). C# spends `using` on three things (bringing in names, a second name for a type, closing a value); SG gives each its own word (`use`, `alias`, `Disposable`). Cost: which module a name comes from cannot be read from the code, the editor shows it |
| <a id="use-details"></a>`use` details | Modules can `use` each other mutually. An unused `use` is not an error, the editor shows it dimmed. The basic standard names need no `use`: `List`, `HashMap`, `HashSet`, `string`, `Result`, `File`, `Stdin`, `Stdout`, `Stderr`, `print` and the others that appear in the earlier examples | Mutual use is allowed in Rust and C# too, and a ban (Go) pushes towards splitting code artificially. An unused `use` produces no wrong result, and if it were an error the code would not compile while experimenting. The ready names are as in new C# projects; in Rust `HashMap` and `File` need `use`. The exact list of ready names will be settled with the standard library |
| <a id="a-program-is-a-file-or-a-folder"></a>A program is a file or a folder | `sg main.sg`: that file alone is the root module, and the folders next to it are the modules it can name. `sg shop`: every `.sg` file of the folder is the root module. A module is read when a file names it, with `use` or with a full name *(28 November 2026, choice 2215: a name in front of a dot that a variable declared before it in an open block has, `var x`, `Point x`, a parameter, `for x in`, `as x`, is that variable, which wins over a module, and no folder is read for it)*; the test command with a folder reads every folder under it and runs the tests of all of them. A folder is a module only if its name can be written as a name. Decided on 13 November | The first form lets one folder hold many small programs, each with its own `main`; Go does the same (`go run file.go`, `go run .`). A folder nobody names is not read, so a mistake in it does not stop the program |
| <a id="name-of-a-module"></a>Name of a module | Always the whole path from the root of the program: `use shop.stock`, also from inside `shop`. The root has no name: no module can `use` it, and `public` says nothing there, so the rule that a `public` name does not show a type that is not `public` is checked in the modules only. `use` lines stand before everything else in a file; the same line twice and a folder that is not there are errors. Decided on 13 November | One way to write a module, no short form to learn. Cost: a long path is written in full |
| <a id="which-name-wins"></a>Which name wins | A variable, then a name of the file's own module, then a `public` name brought in by `use`, then a type of the language's own module (`std`). A `Point` of your own next to a `use` that brings another `Point` is yours and no error; the other is `stock.Point`. A `Log` of a module named with `use` is that module's, not the language's, which is then `std.Log` (choice 1456, 19 November 2026: before, the language's type came before those of `use`). The same name in two modules named with `use` is an error where it is used, for functions as for types. This holds for every type of the language: a program's own `Duration`, `List`, `File`, `IoError` or `TcpStream` is its own, and the language's is written with its module, `std.Duration`, `std.List<int>`, `std.File.readText(path)` (in a pattern a variant is written alone, as always); where the two meet, the message says that two types have the name, and a program's `List` written with `<...>` gets the hint `std.List<int>`. A function, const or static may have such a name too. Kept are only the words of the language, the types of numbers, `bool`, `char`, `string` and `void` (a const or a static cannot be named so; a function can, `int double(int x)`), the three types the syntax makes, `Result` (`try`, `Ok`, `Error`), `Task` (`async`) and `Func` (a function's name as a value), and `Stdin`, `Stdout` and `Stderr`, which are not types but the streams every function has (choices 2250-2252, 28 November 2026; before, choice 2192 kept the 38 names the checker knows types by, and before that the types of `std/time.sg`, `random.sg`, `files.sg`, `path.sg` and `environment.sg` were reserved too). A folder still cannot have the name of a type of the language (choice 1591, kept by 2253). Decided on 13 November | C# and Rust do the same (Rust's prelude is shadowed by what is imported). Otherwise adding a name to a module, or a type to `std`, could break every file that uses it |
| <a id="readonly-goes-all-the-way-down"></a>`readonly` goes all the way down | Nothing behind a `readonly` field can be changed: no assignment, no `ref`, no `ref this` method on it, no `add` on a `readonly List`. It holds inside the module too. The value that holds the field can still be replaced as a whole. Decided on 13 November. *As built for a field that shares its value (choice 2151, 28 November 2026):* through a `readonly` `shared locked` or `shared checked` field the value is only read, in a `lock` block (its name only reads) and in `read ... as`; `ref ... as` is refused. An owner taken with `share` changes it as every owner does: `readonly` covers the field, not the other owners | C#'s `readonly` goes all the way for a struct and stops at the assignment for a class; here every value is owned like a C# struct. No cost at run time |
| <a id="modules-in-messages"></a>Modules in messages | `print` writes the name of a type without its module (`Product { ... }`); the checker's messages write the full name of a type of another module. The test command writes the module in front of a test's name (`stock: nothing ships`), and two tests may share a name in two modules, not in one. A name that was not found but is `public` in a folder nobody named gets the hint `use stock`. Decided on 13 November | The output of a program should not change when a type moves to another folder; an error should say exactly which type is meant |
| <a id="modules-in-compiled-code"></a>Modules in compiled code | `sg build` takes what `sg` takes, a file or a folder, and compiles the modules the program names with it into one C file; `test` blocks are not compiled, the test command runs them in the interpreter. A name of a module is written into its C name with each folder and its length in front (`shop.parts.Part` is `S_4shop_5parts_Part`); a name of the root is written as it is. A compiled panic names the file of the module it happened in. The stock and invoice example is compiled and compared with the interpreter. Decided on 13 November | No name of the root starts with a digit, so a root name and a module name never meet, and the lengths keep two modules apart whatever they are called. Nothing of this is seen from the language |
| <a id="packages"></a>Packages | A program's `sg.project` names the packages it uses, a line each: `require xml example.com/ada/xml 1.4.0`, with `unsafe` at its end for one that has `unsafe` code; `package` gives the project's own address, `local xml ../xml` takes a package from a folder (read only in the program's file); `//` is a comment. `sg.lock`, written by `sg`, holds the SHA-256 of each package's files, its `unsafe` and its libraries of C. A version is a tag `v1.4.0`, chosen inside its major version by minimal version selection; two major versions are two packages. Fetched by `git` alone, over HTTPS; no code of a package runs while it is fetched or built, and a package gives no C to compile. Kept once for the user, read only (`SG_CACHE`). `sg add`, `sg update`, `sg remove`; a build never changes the lock. Approved on 20 November 2026 (choices 1552, 1555-1564) | Go's and Zig's way, with no registry, so no name is taken first; Go's `go.mod` form, read in a page of code with no dependency. Rust runs `build.rs` and npm `postinstall` where a package is installed, the widest door of attacks on what programs are made of; Rust shows no `unsafe` of its crates |
| <a id="packages-as-built"></a>Packages, as built | `sg.project` is read beside the program (the folder given, or the file's). A package is named by the name the program gives it (the last part of the address when none is written) and its modules are kept under it: the root files of `xml` are the module `xml`, its folder `reader` is `xml.reader`. Inside a package its folders are named from its root (`use reader`) and the packages it uses by the names its own `sg.project` gives them; a module of the program, or of a package it does not name, is not there for it. A package has a `package` line, the address of its `require` line; a folder of the program named as a package is an error, and a folder with an `sg.project` of its own is not a module of the program around it. A `local` line's folder is cleaned as Go's `filepath.Clean` does; a package's tests are not run by the program's. Approved on 20 November 2026 (choices 1555, 1556, 1561, 1565-1570). Fetching: into a bare repository, from which `sg` lists the files, refuses links, submodules, names not every system can hold, two names that differ only in case and a package over 64 MB, 16 MB a file or 10,000 files, and writes the files itself, so no filter of git runs; the SHA-256 is of the tree (each path, a 0, its length, its bytes, in the order of the paths), the cache a read-only folder for each SHA-256; a package's every file but the folders with an `sg.project` of their own; an address is a repository, fetched from `https://` and it; a package only another uses is not named by the program and is kept under a name no file reaches (`utf_1`); `sg lock` makes the lock fit without raising a version, and a program stops on one that does not fit; `unsafe` and `extern` are found in the source of every package read and allowed only by the package's own `require` line; `SG_MIRROR` takes packages from a folder of bare repositories in place of the network. Approved on 20 November 2026 (choices 1571-1588). Made safer after the second review (1591): git runs in an empty folder of `sg`'s own, finds no repository above it, takes a bare one only by `--git-dir` and gets no `GIT_` variable of the user's; `sg.project` and `sg.lock` are written into a new file put in their place, never through a link; a library's name enters the lock only as the checker takes it, and text of a package with a control character, a mark of direction or one of no width is refused or printed as its number; the cache keeps a package under its address and version (`example.com/ada/xml@1.4.0/sha256-...`), read only, folders too, and only once its SHA-256 is the lock's and its `package` line its address; git's listing is stopped past 20,000 files, an `sg.project` is at most 1 MB; the files are written each once and read back, so a system that takes two names for one refuses the package; a package or a folder of modules cannot have the name of a type of the language; the language server fetches nothing | Compiled, a package's modules are modules: nothing is added when the program runs. Fetching runs no code of the package, as Zig's, and git is the one tool `sg` asks of the machine |
| <a id="the-folder-internal"></a>The folder `internal` | A module in a folder named `internal` is named only from inside the folder that holds it: `xml.internal` from `xml` and its folders, `stock.internal` from `stock` and its folders. Approved on 20 November 2026 (choice 1561) | Go's rule. It gives a library a level for "my own folders see it, the user does not" (`internal` in C#, `pub(crate)` in Rust) with no new word |
