# The standard library

of each slice are in [the records by day](../decisions/README.md), and the other topics in
[the decisions by topic](README.md).

| <a id="the-clock-as-built"></a>The clock, as built | `Instant` (the monotonic clock: `Instant.now()`, `elapsed`, `since`, `plus`, `minus`; not printed), `Duration` (a `long` of nanoseconds that may be negative: `fromNanoseconds` to `fromSeconds`, the whole units cut toward zero, `totalSeconds`, `plus`, `minus`, `times`; printed `1.5s`, `250ms`, `3µs`) and `DateTime` (UTC, nanoseconds since 1970, the years 1677 to 2262: `now`, `utc(...)` giving a `Result<DateTime, DateError>`, `fromUnixSeconds`, the parts, `dayOfWeek`, `unixSeconds`, `since`, `plus`, `minus`; printed in ISO 8601). Methods, not operators; the arithmetic follows the rule of the numbers. Time zones and reading a date: ["Time zones and dates in text"](../directions/async.md#time-zones-and-dates-in-text); `Task.delay` keeps its `int`. Approved on 15 November 2026 (choices 546 to 548, 551) | Two clocks are two types, so the time between two readings is taken on one clock |
| <a id="the-language-s-own-module"></a>The language's own module | The clock is written in SG, in a module `std` that a program gets when it names one of its types, seen from every module with nothing written; its fields are its own, `use std` is an error, and only it calls the two readings of the clock, the compiler's. A panic inside it is shown at the call of the program that led there, without the hint about the module's code (since the seventy-fifth slice, row ["A panic of the language's own module"](#a-panic-of-the-language-s-own-module)). Compiled, the two readings are one call of `clock_gettime` (on macOS the monotonic one `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)` since the hundred-and-fifty-third slice, choice 1674); the interpreter reads the same clocks. Approved on 15 November 2026 (choices 545, 549, 552) | Everything a struct of a program has comes with it, in both the interpreter and compiled code; the first piece of a standard library written in the language |
| <a id="a-delay-on-the-real-clock-in-the-interpreter"></a>A delay on the real clock, in the interpreter | The clock of the run gives the order of the timers; each also waits until its time has really gone by since it was made, so a delay asked for after a long computation still waits. Approved on 15 November 2026 (choice 550) | The output stays the same on every run, and what a program measures is true |
| <a id="the-clock-measured"></a>The clock, measured | Ten million readings of the monotonic clock take 1.01 times `clock_gettime` in C; taking ten million moments apart takes 0.29 times `gmtime_r`. Approved on 15 November 2026 (choices 553 to 555) | |
| <a id="random-numbers-as-built"></a>Random numbers, as built | `Random` (xoshiro256\*\* seeded with SplitMix64: `Random.fromSeed(long)`, `Random.fromSystem()`; `nextInt(low, high)` and `nextLong(low, high)` from `low` up to `high`, without it, every number as likely, an empty range a panic in every build; `nextDouble`, `nextBool`, `nextUlong`, `fill(ref bytes)`), the same numbers for the same seed in the interpreter, in compiled code and on every system; not `Copyable` and not `Formattable`, lent with `ref`, no generator the program does not make. Written in SG in a second file of the module `std`, which a program gets when it names one of its types. The language has no overloads, so the 64 random bits are `nextUlong()`. Approved on 15 November 2026 (choices 556 to 560, 563) | No `Random.Shared` as in C#: the language has no globals. A copy would give the same numbers again, so a move is the only way to hand a generator over |
| <a id="the-system-s-random-bytes"></a>The system's random bytes | `SecureRandom.fill(ref bytes)`, `nextUlong()`, `nextInt(low, high)`, `nextLong(low, high)` and `hexString(length)` (lower-case hex digits, four random bits each) read `arc4random_buf` on macOS and the BSDs and `getrandom` on Linux; never an error, a panic if the system gave no bytes. Only the language's own module calls `Entropy.fill`; the key of a hash table is drawn with the same function. Approved on 15 November 2026 (choices 561, 562) | As Go's `crypto/rand` since 1.24 and Rust's `OsRng`: a `Result` here would invite `?? 0` |
| <a id="random-numbers-measured"></a>Random numbers, measured | A hundred million numbers in a range take 1.00 times the same algorithm in C; a gigabyte of the system's bytes 1.00 times `arc4random_buf`. Approved on 15 November 2026 (choices 564 to 566) | |
| <a id="hex-and-base64-as-built"></a>Hex and Base64, as built | `Hex.encode(read data)`, `Hex.encodeInto(ref text, read data)` and `Hex.decode(text)`; `Base64.encode` and `decode` (standard alphabet, `=` padding), `encodeUrl` and `decodeUrl` (`-` and `_`, no padding), in `std/encoding.sg`. Decoding gives `Result<List<byte>, DecodeError>`; a space, a line break, a character of another alphabet, misplaced padding or bits left beyond the last byte is `InvalidCharacter(position)`, an impossible length `InvalidLength`. Inside, a digit is read through a table of 256 values, Base64 six bytes or eight digits at a step, and what is written goes through a block of 64 bytes on the stack before the text or the list (21 November 2026, choice 1664). Approved on 19 November 2026, the hundred-and-twenty-fourth slice (choices 1406, 1407) | One text for each set of bytes, and no two readers that disagree; C#'s `FromBase64String` skips white space, Rust's `base64` does not |
| <a id="crc-32-as-built"></a>CRC-32, as built | `Crc32.of(read data)` gives the CRC-32 of zlib, gzip, PNG and ZIP (IEEE 802.3, reflected, `0xEDB88320`) as a `uint`; `var c = Crc32()`, `c.update(read piece)` and `c.value()` give the same piece by piece, `value()` between pieces too. In `std/checksum.sg`, sixteen bytes in a step through sixteen tables of 256 numbers that are a const found when the program is compiled; since the hundred-and-fifty-first slice a compiled program folds 64 bytes or more with the processor's carry-less product where it has it (ARMv8 PMULL with `crc32x` for the rest, x86-64 PCLMULQDQ), asked once through `System.crc32Hardware`, a call only `std` makes, and the tables do the rest, the interpreter's included: the same bytes either way, 0.69 times zlib's time on macOS. `Adler32` sums eight lanes a run (1658). Approved on 19 November 2026, the hundred-and-twenty-fifth slice (choices 1408, 1414, 1415), the instructions on 21 November 2026 (1656) | Rust's `crc32fast` takes sixteen bytes in a step where the processor has no CRC instructions, and folds with them where it has, as SG now does |
| <a id="sha-256-and-hmac-as-built"></a>SHA-256 and HMAC, as built | `Sha256.of(read data)` gives the SHA-256 of FIPS 180-4 as a `byte[32]`; `var h = Sha256()`, `h.update(read piece)` and `h.finish()` give the same piece by piece, and `finish` does not end the hash. `Hmac.sha256(read key, read data)` is HMAC-SHA-256 (RFC 2104). `Bytes.equalInConstantTime(read a, read b)` goes over every byte with no branch on what they hold; lengths that differ give `false` at once. In `std/hash.sg`, SG, whose blocks a compiled program hands to the processor's SHA instructions where it has them (ARMv8 SHA2, x86-64 SHA-NI) through `System.sha256Hardware`, since the hundred-and-fifty-first slice (1657, which takes back 1409's word of no such instructions): 1.17 times OpenSSL's time on macOS, where it took 8.93; the 64 rounds in SG elsewhere and in the interpreter. No other hash and no cipher in `std`. Approved on 19 November 2026, the hundred-and-twenty-sixth slice (choices 1409, 1419-1422), the instructions on 21 November 2026 | Rust's `sha2` uses the SHA instructions where the processor has them, as SG now does, and `hmac` with `subtle` compares tags in constant time; Go's `crypto/sha256` and `crypto/hmac` likewise |
| <a id="the-command-line-as-built"></a>The command line, as built | `var cl = CommandLine("gifcrop", "Crops GIF images.")`, `cl.flag(name, letter, help)`, `cl.option(name, letter, valueName, help)` (the letter a `char?`, `null` for none), `cl.positional(name, help)` (must be given, in order), `cl.rest(name, help)` (the words left, once and last) and `cl.version(text)` (`--version`, no short letter); `cl.parseOrExit(read args)` gives an `Arguments` or ends the program (the help or the version to the output with 0, an error and `Try 'gifcrop --help'.` to the standard error with 2), `cl.parse(read args)` a `Result<Arguments, CommandLineError>`. GNU's way of writing: `--name value`, `--name=value`, `-vq`, `-ovalue`, options after the words, `--`, a lone `-` a word; an option takes the next word whatever it is; a long name is never shortened, and an unknown one is told the declared name at most two edits from it. `a.option(name)` gives the last value, `a.options(name)` all. What is declared or asked wrongly (a name twice, `-h`, a name not declared or declared as another kind) is a panic with what to write. The values are text. In `std/command_line.sg`. Approved on 19 November 2026, the hundred-and-twenty-seventh slice (choices 1410, 1423-1433) Since the hundred-and-forty-second slice (20 November, choice 1594, from the second scan of the library): a word in an error has the characters a reader does not see escaped, and the nearest name is looked for only among names of about its length (a word of a megabyte took a minute in the interpreter). | Rust's `clap` with its builder, which also never shortens a long name; Go's `flag`, which stops at the first word and has no words that must be given; GNU's `getopt_long`, which takes `--verb` for `--verbose` |
| <a id="json-as-built"></a>JSON, as built | `Json.parse(read text)` gives a `Result<JsonValue, JsonError>` (`Json.parse(read text, options)` since the hundred-and-forty-eighth slice); `JsonValue` is `Null`, `Bool`, `Integer` (a whole number that fits a `long`), `Number` (every other, written back with a `.` or an exponent), `String`, `Array` or `Object`, a `JsonObject` that keeps its members in order (`add` panics on a name that is there, `set`, `remove`, `get`, `names()`) and finds a name by looking at each up to 16 members, through a table past that. `v.get(name)`, `v.at(i)` and `as*` give `null`, never a panic. `toJson()` on one line, `toJson(JsonOptions { indent = n })` on lines (`toJsonIndented(n)` until the hundred-and-forty-eighth slice), escaping only the quote, the backslash and the control characters; writing NaN or an infinity is a panic. Strict RFC 8259: no comments, trailing commas, `NaN` or byte order mark, a name twice an error, half of a surrogate pair an error, nesting to 128; a `JsonError` has the line, the column in characters and a `JsonErrorKind`, a character that cannot be seen named by its code. `==` compares objects in any order. In `std/json.sg`, tested with the 318 parsing cases of JSONTestSuite; 1.15 times cJSON's time. Approved on 19 November 2026, the hundred-and-twenty-eighth slice (choices 1411, 1434-1445) Since the hundred-and-forty-second slice (20 November, choice 1594, from the second scan of the library): a key in an error has the characters a reader does not see escaped (`UnicodeCategory.hides`, shared with `Log`, zip names and the command line); `remove` stays linear, as `IndexMap.shift_remove`; a value read takes 50 to 200 bytes a byte of text, written in the library page; `toJson` writes any depth, which `Json.parse` reads to 128. Since the hundred-and-forty-eighth slice (21 November, choices 1600, 1617-1619, 1623): `toJson` writes 128 levels too and one more is a panic; `JsonOptions { maxDepth = n, indent = k }`, `Copyable` and given by value, sets the depth of both and the indentation of `toJson`, with no upper bound (each level takes some stack); `TooDeep(limit)` says the depth. Since the hundred-and-forty-ninth slice (21 November, choices 1638-1640, from measuring `std` against Rust and Zig): a `JsonValue` takes 32 bytes, not 96, since a `JsonObject` holds its members behind one pointer, `null` while it has none, and a value read takes about 10 to 30 bytes a byte of text; `o.values()` gives the values in the order of `o.names()`; on 100 MB SG reads, walks and writes JSON faster than `serde_json` and Zig's `std.json`, in less memory (the table is in [the library's benchmarks](../../benchmarks/library.md)). | serde_json's `Value` with `preserve_order`, which reads a name twice and keeps the last (Go's `encoding/json` too); SG refuses it so that two readers cannot disagree. No `#[derive(Serialize)]`: no reflection or macros |
| <a id="std-measured-against-rust-and-zig"></a>`std` measured against Rust and Zig | Every module of `std` is measured against the crates Rust's people use for the job and Zig's own library, as the trials are: time, the most memory held, size and lines, in `trials/std/<module>` with `trials/measure.py`, the outputs held the same byte for byte; a case where SG takes more than 1.10 times the faster of the two is profiled and fixed for every program, with no check taken away, or written under "Slower than C"; the tables are in `benchmarks/library.md`, and a test fails while a module is neither measured nor in the list of those not yet. JSON first: 32-byte values and `values()` made SG the fastest of the three in all four cases. SHA-256, HMAC, CRC-32 and Adler-32 in the hundred-and-fifty-first slice (1653-1658), with the processor's instructions. Hex, Base64 and Unicode in the hundred-and-fifty-second (1659-1666): hex and Base64 made five to seven times faster, to between 1.25 and 1.54 times the faster of the two; the categories and normal forms of Unicode ahead of ICU4X and ICU4C as they were. Time, random numbers and the log in the hundred-and-fifty-third (1667-1677): a number written with a least count of digits no longer goes through `snprintf` (dates written 2.4 times as fast, as fast as `chrono`), the lines of tasks on macOS wait on a lock of the program's own, and the monotonic clock of macOS is `CLOCK_UPTIME_RAW`; a moment in the time zone stays with `localtime_r` and a token with the system's random bytes, both under "Slower than C". Approved on 21 November 2026, the hundred-and-forty-ninth slice (choices 1553, 1629-1640) | Rust measures with `criterion` in `benches/`, Zig with its own `std.time` loops; neither holds a library to another language's |
| <a id="log"></a>Log | *Decided on 19 November 2026 (choices 1412, 1416, 1417, 1447-1455).* `Log.trace`, `debug`, `info`, `warn` and `error` write a line to the standard error, `2026-11-19T20:15:03.123Z INFO  message`: the time in UTC to the millisecond and the level padded to five letters. `LogLevel` is `Trace`, `Debug`, `Info`, `Warn`, `Error` or `Off`; `Log.setLevel`, `Log.level()` and `Log.isOn(level)`. A program starts at `Info` or at what `SG_LOG` names (any case), and `setLevel` changes it after; a value that names no level is told in one line and `Info` is used. The compiler writes `Log.debug(text)` as `if Log.isOn(LogLevel.Debug) { ... }`, so the text of a level that is off is never built, and a call in it does not run. The text of a message is never read for anything in it: no lookups (`${...}`), no pattern with arguments. Control characters, the marks of direction, the characters of no width, the byte order mark and the backslash are escaped when written, so one line is one call. A line is made whole and written at once, under the lock of `printError`. On a terminal the level is coloured, never with `NO_COLOR` or `TERM=dumb`, and on Windows only where the console takes the escape sequences. No files, rotation, structured fields or levels for each module | Rust's `log` with `env_logger`, Go's `slog` and .NET's console logger. Lookups are left out for good after Log4Shell (CVE-2021-44228); escaping follows CWE-117 (log forging) and Trojan Source (CVE-2021-42574). Lazy text is the macros of Rust and the interpolated-string handlers of C#, kept to `Log` alone: a general lazy argument would be a closure |
| <a id="log-as-built"></a>Log, as built | `std/log.sg`, written in SG. The level is a `static atomic int` found the first time a line asks for it, from `SG_LOG`; a line that is off costs the branch of the static, a load and a compare, measured at 1.01 to 1.10 times a test of an atomic global in C (`bench/log`). A `$"..."` given to `Log` is made a `string` inside the `if`. `System.colourTerminal()`, which only `std` calls, asks whether the standard error is a terminal (`isatty`; on Windows `GetConsoleMode`, turning on `ENABLE_VIRTUAL_TERMINAL_PROCESSING`). `std.Log.debug(...)` is guarded too; a `Log` of the program or of a module named with `use` is not the language's and is left alone (choice 1456). Built on 19 November 2026, in the hundred-and-twenty-ninth slice Since the hundred-and-forty-second slice (20 November, choice 1594, from the second scan of the library): every character of format (Cf), C1, the separators of lines and the fillers are escaped, not only the marks of direction; `\u{e0041}` past U+FFFF. | |
| <a id="regular-expressions"></a>Regular expressions | *Decided on 20 November 2026 (choices 1457-1464, 1469-1474, 1477-1481).* `Regex` comes with the language, written in SG; TLS and encryption stay with C libraries. RE2's meaning: a match takes time in proportion to the text, so no back references and no look-around. Go's syntax with `\d \w \s \b` in ASCII and `\p` by the general category; `(?i)` by Unicode's simple case folding (C and S of CaseFolding.txt). `Regex.of(pattern)` takes only a pattern written in the program, checked when the program is compiled, and gives a `Regex`; kept in a `static` it is compiled once. `Regex.compile(pattern)` gives a `Result<Regex, RegexError>`, and a pattern written there is checked when the program is compiled too. `isMatch`, `find` (a `Match`: `start` and `end` in bytes), `findAll`, `captures` (by number and by name), `replaceAll` (`$1`, `${name}`, `$$`; `$1x` is group 1 and `x`, a group the pattern lacks a panic), `split`. Only the leftmost match the pattern prefers; a `string`, not bytes. A count at most 1000, a program at most 100,000 steps, groups 250 deep, a name given to two groups an error | Go keeps `regexp` in its library, Rust leaves `regex` to a crate; both mean what RE2 means. The pattern a program writes is known when it is compiled, so its mistakes are compile errors, where Go's `MustCompile` panics and Rust's `unwrap` does |
| <a id="regular-expressions-as-built"></a>Regular expressions, as built | `std/regex.sg`: the pattern is read into a tree, compiled to a program (Thompson's construction) and run by Pike's machine; plain text every match starts with is looked for first. A search makes its own lists of threads (`findAll` and `replaceAll` once), so a `Regex` is never written by a search and a `static` one is read by any number of tasks without a lock. Since the hundred-and-thirty-third slice (20 November, choices 1535-1539, found by the `grep` of 1418): an inner text every match holds is looked for first; lazy DFAs answer `isMatch`, find where the preferred match ends (forwards, in Pike's order) and where it starts (the reverse program, backwards), and Pike's machine runs only for the groups; their states and Pike's machines are kept in the `Regex` in a `shared locked` field, so a `static` one is still searched by any task, taking the lock once a search. `grep` over 100 MB is 1.5 to 1.8 times Rust's `regex` where the DFA reads every byte and faster where an inner text skips; 1.8 to 2.3 times Zig with PCRE2's JIT there (choices 1540-1542 put Zig in the trials in the place of Go). `x*` of an `x` that can match nothing is `(x+)?`, as Go. A pattern written in the program is read by `Regex.problem` when the program is compiled, the way a const is found. Tested by RE2's search tests (1772 cases, none wrong) and, while it was written, 207,000 random patterns and texts against Go's `regexp`; at about Go's speed then. The hundred-and-thirtieth slice Since the hundred-and-forty-second slice (20 November, choice 1594, from the second scan of the library): `x*` counts its body among the 100,000 steps (`((a{1000})*){1000}` was a program of a gigabyte); each DFA is emptied at about 2 MB counted in bytes, the moves past ASCII with them; the slots of the groups grow with the threads alive, by thread, not with the program; a `[:` with no `:]` is looked for once; the items of a class with `(?i)` are folded once, when the class is finished; a repetition after `\Q...\E` repeats its last character, as Go. Since the hundred-and-forty-sixth slice (21 November, choice 1598): Pike's machine copies a thread's slots once, as Rust's PikeVM, its closure walking on the thread's own slots and giving each save back as its stack unwinds; `captures` and `replaceAll` find where the match starts and ends first, by the DFAs or, when they give up, by Pike's machine with two slots, and the machine of every group runs only there. 4,000 groups kept alive take Rust's time with a fifth of its memory. | |
| <a id="compression"></a>Compression | *Decided on 20 November 2026 (choices 1465, 1466, 1482-1489).* `Deflate`, `Zlib` and `Gzip` come with the language, written in SG: `compress(read data, level)` gives a `List<byte>`, `decompress(read data, limit)` a `Result<List<byte>, CompressError>`; `writer(StreamWriter, level)` a `Compressor` and `reader(StreamReader, limit)` a `Decompressor` with the calls of a `StreamReader`. The bytes are zlib's at every level, 0 to 9 (a level written in the program outside them is a compile error). Opening always takes a limit, `TooLarge` past it, so a bomb is refused by the signature; strict: bytes after the end are `TrailingData`, checksums and lengths are checked; members of gzip one after the other open as one. `Adler32` comes into `std` beside `Crc32` | Go keeps `compress/*` in its library, Rust leaves `flate2` to a crate; both leave the bound of what is opened to the program. The same bytes as zlib let a test compare bytes and make SG's files the files every other tool makes |
| <a id="compression-as-built"></a>Compression, as built | `std/compression.sg`: zlib 1.3.1's `deflate.c` and `trees.c` written again in SG, with zlib's licence, and an inflate of tables (9 bits for a literal or a length, 6 for a distance, tables below them). Compared with zlib on 390 cases and 176 streams cut in pieces, all the same bytes, and on 23,000 streams changed at random, which both open into the same bytes or both refuse. Compressing takes about zlib's time, opening 2.6 times it ("Slower than C"; 0.95 and 1.74 times since the hundred-and-fiftieth slice). A folder is a module only when its name is spelled as the program writes it (1500). The hundred-and-thirty-first slice (1490-1500) Since the hundred-and-forty-second slice (20 November, choice 1594, from the second scan of the library): `readLine` and `readText` open more of the stream when a line or a character is cut by what is ready (they looped for ever); a limit of `long.MaxValue` no longer overflows; a symbol of codes is begun only with 48 bits held while more input is to come, so a valid stream whose long codes meet the end of the reader's block is no longer `Truncated` (a test made by a generator that follows the inflater's bits). Since the hundred-and-fiftieth slice (21 November, choices 1646, 1647, 1649, 1651, from measuring `std` against Rust and Zig): the search for a match compares eight bytes at a time; a match at a distance of 8 or more is copied eight bytes at a time, the output keeping 266 bytes of room; a call that compresses all at once makes its window, chains and symbols the size of its input, the sizes zlib counts with kept, so the bytes are zlib's at every level still and 99,640 records of about 370 bytes compress and open in the time of `flate2`; tables are made by `List<T>.repeat`. The CRC-32 of the processor waits for the hundred-and-fifty-first slice. | |
| <a id="zip-archives"></a>Zip archives | *Decided on 20 November 2026 (choices 1467, 1490, 1491, 1501-1512).* `ZipReader.open(path)` reads the central directory and checks it before anything is given: a name that could lead out of a folder on any system (`..`, a root, `\`, `:`, NUL, a device name of Windows, empty) is `InsecurePath`, two entries of one name `DuplicateName`, data that lie over each other `Overlap`, more entries than the directory holds `Corrupt`; the archive is refused, not the entry. `entries()`, then `readBytes(read entry, limit)` or `copyTo(read entry, ref writer, limit)`, with `TooLarge`, `SizeMismatch` and `ChecksumMismatch`. `ZipWriter.create(target)` with `add`, `addFrom` and `addDirectory`, each taking the time of the entry, and `close`; zip64 where needed; the writer refuses what a reader refuses. No call unpacks a whole archive to the disk | Go's `archive/zip` reads and writes the same archives but leaves an overlapping bomb, a name of a device and a file named as a folder to the program, and its writer looks at no name; Rust leaves zip to a crate. A name checked where the archive is opened refuses Zip Slip before a program can write the entry |
| <a id="zip-archives-as-built"></a>Zip archives, as built | `std/zip.sg`, over the DEFLATE of `std/compression.sg`: one inflater for all the entries of a reader and one compressor for a writer, restarted as zlib's `deflateReset` restarts it, so each entry has the bytes of `Deflate.compress(data, 6)`. Go's `archive/zip/testdata` reads as Go reads it but for a file named as a folder (1523), a time of DOS that makes no day (1515) and `NotZip`; Fifield's overlapping bomb is refused when it is opened.
