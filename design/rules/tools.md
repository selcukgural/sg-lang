# The compiler and its tools

The back end, the `sg` command, tests, the editor, hardening, limits and the leak report. Each row is a decision with its reason, in the order it was made; the choices
of each slice are in [the records by day](../decisions/README.md), and the other topics in
[the decisions by topic](README.md).

| <a id="back-end"></a>Back end | The compiler writes C and a C compiler makes the program (`sg build`, `--release` for a release build): the smallest path, every platform has a C compiler, and its optimiser does the heavy work. A compiled program panics with the same text as the interpreter, which stays as the reference: every program the back end accepts is compiled and compared with it. Deep recursion is not caught in compiled code (the stack depth question stays open). Decided on 12 November | Machine code or LLVM's form would be a much larger step for the same result at this stage |
| <a id="tests-in-compiled-code"></a>Tests in compiled code | `sg test <path> --compiled` runs the `test` blocks as compiled code; without the word the interpreter runs them, as the reference that needs no C compiler. `sg build <path> --test` keeps the program that runs them. Each test runs in a process of its own, so a panic ends that test only, and the report is the interpreter's, letter for letter, with the exit code 1 if a test failed. A `try` that meets an error in a test writes it and ends the test, freeing what the test owns. `--only N` runs one test in the same process; *(as built, 28 November 2026, choice 2233: N is digits and one of the tests, and any other word is told on the standard error and ends the program with 2 having run nothing)*. The tests of the back end compare the two reports, run the compiled tests under the sanitizers and look at every passing test for leaks. For now POSIX only (`fork`). Decided on 13 November | The process per test is what ["Test"](#test) decided; here it costs one `fork` for each test. The same `.out` file checks both ways of running, so they cannot drift apart |
| <a id="the-sg-command-as-built"></a>The `sg` command, as built | Its exit codes: 0, what `exit` gives, 1 for an error of the program, a panic or a failed test, 2 for a command line that is not a usage and for a path of it that does not lead anywhere (a program that cannot be read, a folder of `-L` or of `-o` that is not there, an output that is a folder: `sg build shop` from the folder above `shop` asks for `-o`, as Go does, 19 November, choice 1398; an output, or the header of a library, that would replace the program's own file, a file of SG or of C, or a header `sg build` did not write, before anything is compiled, 27 November, choice 2089). What the tool writes itself (the C of `emit-c`, the line `built ...`) ends quietly when what reads it closes, as a program does (1399). So does what it tells on the standard error (a check's error, its usage, what it could not do) when no one reads it, by `SIGPIPE` on Linux and macOS; any other failure there loses the line and keeps the code (21 November, choice 1604; it ended with 101 before, a panic of Rust). The folders under a program are walked once each, a link that leads back passed over (choice 1596). A second program, a flag given twice, `-o` or `--target` with nothing after it, and `-o` with `emit-c` are not usages (18 November). What a build makes on the way (the C, the object of a library, the program of compiled tests) is in a folder of the temporary folder made new for it, at a name no one can guess, that only its user opens, and removed at the end (18 November, the hundred-and-sixteenth slice, choice 1333). The C compiler is the one `CC` names, on every system, else `cc` on Linux and macOS and Clang on Windows (20 November, choice 1533, found by the trials of 1418). What the C compiler writes is written on, and a build that fails says whose mistake it is: a C file of the program's own, with the compiler's first errors again; a compiler that names no error or ends with 0 and writes nothing, as perhaps no C compiler; only C sg wrote is "a mistake in sg" (28 November, choice 2230). A shared library's link line takes the name `-o` gave it, or its path when `-l` cannot find that name (2231); `sg build .` names the program after the folder (2232); a file of a folder given alone names the file beside it that has a name not found, and the folder (2242); `sg emit-c` takes `--shared` for the C of `--library`, and its hints name `sg emit-c` (2240). Tested from outside in `tests/cli.rs` | rustc refuses `-o` twice; Go's flags keep the last, which leaves a mistyped line built as something else |
| <a id="flags-of-c-as-built"></a>Flags of C, as built | `sg build file.sg -- <flags of C>` gives them to the C compiler on every build (a program, `--test`, `--library`, `--shared`, `--freestanding`), after sg's own, so that the last written wins (`-O3` over `-O2`); `-l`, `-L`, `-I` and `-Wl,` go in the same list. `emit-c` with `--` is a usage error; there is no variable of the environment for them. Three kinds (choice 1937): most go on quietly, unknown ones too (`-O3`, `-march=native`, `-flto`, `-g`, `-fsanitize=...`); some go on with a warning written on every build and never silenced (1938): what changes fractional results (`-ffast-math`, `-Ofast`, `-ffp-contract=fast` or `on`, `-funsafe-math-optimizations`, `-ffinite-math-only`, `-fno-signed-zeros`, `-freciprocal-math`, `-fassociative-math`, `-mfpmath=387`), what takes a guard away (`-fno-stack-clash-protection`, `execstack` and `norelro` to the linker), and a setting of SG's runtime (`-DSG_...`, `-USG_...`); and some are refused with 2 before anything is compiled: what sg owns (`-o`, `-c`, `-S`, `-E`, `-x`, `-std=`, `-shared`, `-static`, `--target`) and what changes the size or the layout of C's types (`-m32`, `-mx32`, `-fshort-enums`, `-fpack-struct`, `-fshort-wchar`, `-funsigned-char`, `-fsigned-char`). A flag of C turns off no check of SG: overflow and the other checks of a debug build are `--release`'s to leave out, a debug build with `-O3` still stops on an overflow (1939). Clang's warning at each `NAN` and `INFINITY` under `-ffast-math` is turned off in the runtime and the C sg writes, not in the program's own C files: sg's warning has said it (28 November, choice 2235). A program has no `--target` (1940). On Windows the same, written as GNU writes them, Clang being the driver (1941). Built on 26 November 2026, slice 187 (1935-1941); before, flags of C were taken only with `--freestanding` | Cargo's `RUSTFLAGS` and Go's `CGO_CFLAGS` pass flags on in silence; sg says what changes a promise of the language and keeps what it owns |
| <a id="debugging-as-built"></a>Debugging, as built | A debug build carries what the system's debugger reads (`-g`): inside the program on Linux, in `x.dSYM` beside it on macOS, in `x.pdb` on Windows; a release build carries none unless given `-- -g` (choice 1943). The C names, before every function and statement of SG, the line of SG it stands for, with the file's absolute path (`#line`), in every build (1944), so a breakpoint is set on a line of a `.sg` file and the stack names the program's own lines; what has no line of SG (the runtime, C's `main`) names the C file (1945). The debugger shows the names of the C (`f_sum`, `v_total_1`, `m_x`, 1946); the language's own module is named `<built-in>/std/...` (1947). Tested with lldb and gdb (`tests/debugger.rs`, 1948). Decided on 26 November 2026, slice 188 | A language for systems is debugged in the system's debugger, as C, Rust and Zig are; going through C, the lines are given to the C compiler, which writes them as it writes its own |
| <a id="editor-support-as-built"></a>Editor support, as built | `sg lsp` is the language server, in `sg` itself with no dependency: as a file is written it shows the first error of the program the file belongs to (one at a time, since the checker stops there), with its notes and hint, and a hint whose code is certain is a fix applied with one click: a conversion, `.clone()` of a borrowed text, `_ = ` before a value dropped on purpose, the missing `use`. A `use` that brings no name is shown dimmed when the program has no error: a hint with the tag `Unnecessary` (28 November 2026, choice 2256). There is no hover, going to a definition or completion. `editors/vscode` colours SG in VS Code (a TextMate grammar) and starts `sg lsp`. Built on 19 November 2026, in the hundred-and-twentieth slice (choices 1369 to 1376). What is shown of an error is made inside the guard that catches a mistake of the checker, so such a mistake is shown as one and the server goes on checking; a folder whose links lead back is checked once (21 November, choice 1596). `sg lsp --stdio` is `sg lsp`, the word clients add (28 November, choice 2237), and a `Content-Length` too long for a number is told as a message too large (2236) | What the principle at the top asks for: the error shows in the editor while typing, and a mechanical hint is applied with one click |
| <a id="help-as-built"></a>Help, as built | `sg help <name>` prints the page of a word of SG in the terminal, from `sg` itself, with no network: the text `man` shows for the word's manual page, which `website/plain/build.mjs` makes from the same Markdown as the site (`website/words/`) and writes into `interpreter/src/help/`, which `build.rs` lists and `sg` carries. A name of the index with no page gives its line and the address of the index; `sg help index` lists every name with its line, and `sg help` the commands and the words with a page. The name is looked for as written, then in any case, then as a command (`build` is `sg build`), then as the file of a page (`sg-build`), then a sign by its marks alone (`??` is `x ?? y`, choice 2086); a name it does not know is an error (exit 2) naming the names it starts like, and an empty name is told as one (28 November, choice 2238). Plain text, no colour and no pager, the same on every system. Built on 27 November 2026 (choice 2082); the packages of the preview are to install the manual pages too (2083). A command has a page too, its manual page in section 1 (`sg-build(1)`, choice 2087), and `sg <command> --help` or `-h`, before a `--`, prints it; `sg --help` prints `sg(1)` (2088) | Go's `go doc` and Python's `help()` read their pages from the tool itself; `man` and `rustup doc` read pages installed beside the compiler, which a build from source and Windows do not have |
| <a id="hardening-as-built"></a>Hardening, as built | Before the preview, what is built was tried four ways (choices 1318 to 1325): the `sg` command end to end (`tests/cli.rs`); a review of the soundness of the checker, the generated C, the boundary of `unsafe` and the tool, a finding counted only with a program that shows it; the front end fuzzed with libFuzzer (`fuzz/`), and generated programs run by the interpreter and compiled under the sanitizers (`fuzz/difference`); and mutants of the functions that make the rules of safety (`.cargo/mutants.toml`), then only on what a change touches. Each finding was fixed after a test that shows it. Done on 18 and 19 November 2026, in the hundred-and-fifteenth to hundred-and-nineteenth slices. After the second review (1589), the generator writes programs that borrow too (1593): not written to be right, each is fitted by taking away the statement the checker's first error names until it is taken, and what is run must read no freed memory under the address sanitizer; on the code before the fixes of 1592 it found their shapes in minutes. It lends ranges of lists as `ref` beside other ranges too (1610), and on the code before that fix found the shape in 89 of 648 programs | Rust has Miri, cargo-fuzz and cargo-mutants for the same ends; Go has its built-in fuzzing |
| <a id="limits-as-built"></a>Limits, as built | A value takes at most 2^61 - 1 bytes (an array, a struct, an enum, a `T?`), counted as C lays it out: a type whose values would take more is a compile error where it is written, with the hint of a `List<T>`. A program nests at most 1000 deep (blocks, expressions, the operators of a chain, the names read one after another, types and patterns, together), and beyond that the error says to give a part a name. The interpreter panics (*stack overflow*) when writing or comparing a value nested too deep for its stack, and when an array is more than the memory holds. In compiled code a function whose values may take a page of its stack or more touches that room a page at a time before its frame is made (`sg_probe_stack`), unless the frame lies wholly above the bottom eighth of its thread's stack, which no frame there can reach the page below from (24 November, choice 1836), and `sg build` gives GCC and Clang `-fstack-clash-protection` on Linux, so a frame larger than the stack ends at the page below it, never in another thread's memory. A function whose values may take more than 256 MB of its stack is an error of `sg build` on every machine, with the hint of a `List<T>`: no thread's stack holds it, and Windows on Arm builds none (choice 1346). Built on 19 November 2026, in the hundred-and-sixteenth slice (choices 1338, 1341 to 1346). The code of texts nested deeper than the parser takes is not looked into for names before it parses, and `sg lsp` reads a line of a header up to 8 KB and a message up to 64 MB (21 November, choice 1596) | Rust's bound of a value is `isize::MAX`, cut here to what Clang allows an array; Rust probes the stack on every machine too. Rust and Go grow the compiler's stack instead of bounding the nesting; a bound costs nothing and no program written by hand comes near it |
| <a id="the-leak-report-in-a-debug-build"></a>The leak report in a debug build | A debug build and the tests keep the `shared` values that are alive in a list (48 bytes in front of the counts) and report them with the interpreter's text; a release build keeps no list and reports nothing. Approved on 14 November 2026 (choice 351) | As the design wrote: "in test and debug builds" |
| <a id="what-leaks-on-purpose-in-cargo-test"></a>What leaks on purpose in `cargo test` | A program that leaks by design reports it itself; its blocks are still reached from the list, so the system's leak check does not count them. Approved on 14 November 2026 (choice 352) | Every other program frees all it took |
| <a id="test"></a>Test | `test "name" { }`, a block written at the top level of a file. Only the test command compiles and runs it, it is not part of a normal build. `test` is a keyword only at the top level and when followed by a string, and it can be used as a name. A test belongs to the module of the folder it is written in: it sees every name of the module, and only the `public` names of other modules. In the block `try` works with every error type; an error fails the test and is printed (it must be `Formattable`, as for `main`). A failing test is a panic, and the test command runs each test in a separate process | Zig's notation. In Rust `#[test] fn` and `#[cfg(test)] mod tests`, in C# a separate project and a library, in Go a naming rule (a `_test` file, a function starting with `Test`). A separate `main` program cannot see what is not `public` and stops at the first error. Go's naming rule adds no word but makes people memorise two invisible rules, and a test name cannot be a sentence. The visibility follows from the module rule, it is not a new rule. Cost: one word; the only place where `try` works without a target error type being written; the time to start a process per test (a tooling decision) |
| <a id="assert"></a>`assert` | `assert(condition)`: panics if it is false. The message prints the text of the expression and, if it is a comparison, the values of both sides, `Formattable` or not (as built; written so on 28 November 2026, choice 2255). Valid outside tests too, and on in release too. There is no `assertEqual` | A single form. In Rust three macros (`assert!`, `assert_eq!`, `debug_assert!`), in C# `Assert.Equal` is in a library and `Debug.Assert` is deleted in release. In the same direction as the rule that safety checks cannot be turned off. Cost: since there are no macros the compiler knows `assert`, like `$"..."` |
| <a id="test-command"></a>Test command | `sg test file` compiles the file with its tests and runs them: one line per test, `ok    name` or `FAIL  name` followed by the panic or `error: ...`, then a count; exit code 1 if any failed. A test file needs no `main`. Two tests with the same name are a compile error, and so is a name with a control character, which would not be one line of the report, the same in both ways of running (28 November, choice 2234). `try` on a `T?` in a test is a compile error (there is no caller to give `null` to; the hint is `... ?? panic("...")`, since `assert` does not narrow; 19 November, choice 1401). The `test` blocks are checked only by the test command: `sg file.sg` and `sg build` leave them out, as `cargo build` leaves out `#[cfg(test)]`, and `sg lsp` checks them (1402). With a file, the tests of the modules it reads run too. `test "..."` inside a function is a compile error. Decided on 12 November | What the ["Test"](#test) row left open. The interpreter runs the tests one after the other in one process, each with variables of its own; with no global state the difference to a process per test cannot be seen yet |
| <a id="the-c-without-warnings"></a>The C, without warnings | Every compiled program builds under `-Wall -Wextra -Werror` with clang and gcc in the tests; a function nobody calls is left a warning, and three of gcc's analyses that see paths that cannot happen are allowed only in the one program each is in. What SG lets a program leave unused is marked used in the C. A failed call of the system never reads as success (`errno` 0 becomes `EIO`). Approved on 15 November 2026 (choices 585 to 587) | A warning of the C compiler fails a test instead of reaching a user; whether a variable written and never read becomes an error is an open question |
