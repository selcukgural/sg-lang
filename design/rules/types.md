| Topic | Decision | Reason |
|---|---|---|
| <a id="null"></a>Null | No universal null: `T` cannot be empty, every type has `T?`, built into the language | Implicit null is a source of bugs; `Option<T>` would need generics, and magic values like `-1` should go too. `Node*?` is 8 bytes; in compiled code an `int?` is the `int` and a flag, 8 bytes. `Memory.sizeOf` takes only plain data, which a `T?` is not, so the size is not one a program can ask for (#36) |
| <a id="t-check"></a>`T?` check | `if x is null`, `while x is not null`; flow narrowing on local variables and parameters. Since the forty-fifth slice also along `&&` and `\|\|` (["Narrowing along `&&` and `\|\|`"](patterns.md#narrowing-along-and)), since the forty-ninth under `!` and after a `while` (["Narrowing under `!`"](patterns.md#narrowing-under), ["Narrowing after a `while`"](patterns.md#narrowing-after-a-while)) | After the check the same name counts as `T`. Fields are not narrowed, a local copy is taken first |
| <a id="t-unwrapping"></a>`T?` unwrapping | `x ?? default`, `x ?? panic("message")`; `orelse` is gone. As built (#35): the right side is a `T`, and the result a `T`, never a `T?` (a `T?` on the right takes a `??` of its own: `a ?? b ?? c`); on a `T?` that owns what it holds, `x ?? y` takes the value and `x` is moved, while `read x ?? y` only looks. `return` is the only statement on the right (`?? break` is an error whose hint tests with `is`), and there is no `??=` | No separate `throw.ifnull` is needed: `throw` suggests something that can be caught, while panic stands in for every type |
| <a id="name-of-the-empty-value"></a>Name of the empty value | `null` | Familiar from C#, but valid only in the `T?` type |
| <a id="t-notation"></a>`T*?` notation | Postfix, read left to right | `Node*?` is a nullable pointer, `Node?*` is a pointer to a nullable value; C#'s pointer notation |
| <a id="methods"></a>Methods | In the body of a struct or an enum (since the forty-third slice, ["Methods on enums"](#methods-on-enums)), with `read this`, `ref this` or `this` as the first parameter. Field access must be written `this.x`. At the call, `read`/`ref` is not written for the receiver. *As built:* a method cannot have the name of a field of its type (`` `timeout` is already a field of `Request` ``) | `this` follows the same rule as the other parameters, and fields are not confused with local variables |
| <a id="interface"></a>Interface | C# notation: `struct Version : Comparable`, `where T : Comparable`, the implementing type is `Self`. Generic interfaces exist *(12 November: an `interface` of your own and `where` are deferred with generics; the built-in ones stay: `Copyable`, `Clonable`, `Formattable`, `Equatable`, `Hashable`, `Comparable`, `Disposable`, `Closable`, eight, and `unsafe Sendable`, the writer's promise for raw pointers. An interface is not a type: `read Formattable value` is an error whose note says so.)* | Static dispatch in the first version |
| <a id="enum"></a>`enum` | Variants carry data: `Circle(int radius)`. Construction with the full name: `Shape.Circle(2)`, `new Expr.Number(1)` | Takes a tag plus the size of the largest variant, no heap. An enum that contains itself needs `T*`, also through a `T?`, an array or either side of a `Result` (choice 1596, 21 November 2026) |
| <a id="copyable-receiver"></a>`Copyable` receiver | A method that takes `this` by value copies a `Copyable` receiver, so the value stays usable | The argument rule applied to the receiver; the same in Rust |
| <a id="generated-text"></a>Generated text | A `Formattable` type without its own `format` is written the way it is built: `Place { line = 3, file = "a.txt" }`; a variant without its enum: `NotFound("x.txt")`, `Ready`; text inside another value is in quotes; a missing value is `null`; a `T*` is written as what it owns. The error `main` ends with is written this way: `error: Syntax(NumberTooLarge(0))`. A struct with its own `format` may hold fields that are not `Formattable` | Our own construction notation instead of a second one (Rust writes `line: 3`). Quotes keep the parts apart |
| <a id="formatter"></a>`Formatter` | A taken type name. `f.write(x)` takes whatever `print` takes | |
| <a id="comparable-is-written"></a>`Comparable` is written | `: Comparable` needs a `compare` method written by hand: `int compare(read this, read T other)`. It is not made from the fields; only `equals` and `hash` are. An enum cannot be `Comparable` until enums have methods (they came in the forty-third slice: ["Interfaces on an enum"](#interfaces-on-an-enum)). Decided on 12 November. *(18 November 2026, the hundred-and-seventh slice: an enum with numbers that writes none is ordered by its numbers, which are written; see ["Enums with numbers, as built"](#enums-with-numbers-as-built).)* | An order made from the order of the fields is rarely the one that is meant, and it would change silently when a field is moved. Rust's `#[derive(Ord)]` does exactly that |
| <a id="equatable-and-hashable-details"></a>`Equatable` and `Hashable` details | `==` wants the same type on both sides and looks through `read` and `T*`; `a != b` is `!a.equals(b)`. A `T?` is compared with a `T?` or a `T` of the same type, equal when both are `null` or both hold equal values (2131, 28 November 2026). In the generated `equals` a `T?` field is equal when both are `null` or both hold equal values, and a `T*` field is compared by what it owns. `Hashable` needs `Equatable`. Integers and text have `a.compare(b)` and `a.equals(b)` (`bool` has `equals`). A failed `assert(a == b)` writes both sides field by field, `Formattable` or not. Decided on 12 November *(28 November 2026, #15 and #48, choice 2170: built for every type in both back ends, `int*` and `string*` too, and `<` and the other orders the same way; a key that holds a `T*?` is hashed by what it owns. The other operators work on numbers, not on a `T*`: `count + 1` and `count += 1` on a `var count = new 5` are errors whose hint drops the `new`)* | What the design's rows on equality left unsaid |
| <a id="constructor"></a>Constructor | `T(args)` is short for the call `T.create(args)`. `create` is an ordinary function and can return a `Result` | There is no half-built object, and no separate constructor concept is needed |
| <a id="field-order"></a>Field order | The compiler orders struct fields freely so that no gaps remain *(as built, 28 November 2026, #42, choice 2177: the fields of every struct lie in the order they are written, as C lays them out, in the interpreter and in compiled code; `struct S { byte a` / `long b` / `byte c }` takes 24 bytes and the same fields from the largest down 16. A plain struct goes to C as it is, so its order is C's; the gaps are the writer's to leave out by the order)* | Since C compatibility is unimportant, a memory gain at no cost |
| <a id="copyable-and-enums"></a>`Copyable` and enums | The same as for structs: all fields of all variants must be `Copyable`. `read T` and `raw T` count; `ref T`, `T*`, `string`, `shared T`, `weak T`, `locked T`, `checked T` do not. On a generic type `: Copyable` holds if the type parameters are `Copyable` too | Without this, `T?` and `Result<T, E>` could never be copied |
| <a id="readonly-field"></a>`readonly` field | Given only at construction, cannot be assigned afterwards. The whole object can be changed through a `ref` | Immutability should be checked at compile time. It does not replace `read`: `read` is a borrow, a `readonly` field owns its own data |
| <a id="formattable"></a>`Formattable` | `void format(read this, ref Formatter f)`. `print` and `writeLine` accept it. If no body is written the compiler generates one, and all fields must be `Formattable`. The error type of `main` must be `Formattable` | A write error stays in the `Formatter`, and `writeLine` returns it. This way there is no `try` noise inside every `format` |
| <a id="this-with-a-type"></a>`this` with a type | `this` can also take a type: `read FolderRef this`, `FolderRef this`. `read this` is short for `read Folder this`. The method is called only on a value of that type | `ref this` does not give the wrapper that holds the counter, so the method could not write `weak this` or `share this`. The method does not lock the object for the whole call, and code that walks upwards does not conflict with itself. `read shared checked this` was considered too, and since an alias cannot be written there, a single form remained |
| <a id="type-alias"></a>Type alias | `alias FolderRef = shared checked Folder`, as D writes it, can take `public`. It is not a new type but the same type, and it disappears at compile time. `new FolderRef(args)` means `new shared checked Folder(args)`, and `FolderRef?` is `shared checked Folder?` | Repeating `shared checked` was making signatures long. It was written with C#'s `using` until 25 November 2026 (choices 1918-1920): the word says what the line does, and in C# `using` means three things. |
| <a id="equality"></a>Equality | `Equatable` (`bool equals(read this, read Self other)`), `Hashable` (`long hash(read this)`). If no body is written the compiler generates one field by field *(28 November 2026, choice 2213: the generated `equals` is called by name too, `a.equals(read b)` being `a == b`, through a `T*` as well; the generated hash serves `HashMap` and `HashSet` only and is not called by name, since the number is no part of the language and the interpreter and compiled code hash apart)*. `a == b` is short for `a.equals(b)`; `a < b` is short for the call `a.compare(b) < 0`. `==` on a type that is not `Equatable` is a compile error. `HashMap<K, V> where K : Equatable, Hashable`. Numbers and `string` implement all three | The `xs[i]` pattern: no general operator definition is needed. There is no silent reference comparison as in C# |
| <a id="function-value"></a>Function value | `Func<int, bool>` is the type of a function, the last parameter is the return type (`Func<int, void>` for none). A value of it is the address of a named function and nothing more: `Copyable`, no heap, no captured data. It is written by naming the function (`Func<read Order, bool> rule = isPaid`, `apply(isPaid)`) and called like one (`rule(order)`). A method bound to an object is not a function value. There is no lambda notation; what a function needs comes in as a parameter. Decided on 12 November | C's function pointer, and it costs what a call through a pointer costs. Lambdas that capture were removed the same day: they brought a run-time check and the largest group of rules in the language |
| <a id="function-value-details"></a>Function value details | Only a top-level function is a value: not a method, not a function inside a struct, not `main`, not a built-in. A variable that holds a function value wins over a function of the same name when it is called. The result of a call is not called directly (`pick(true)(2)`): a variable goes in between. A function value is not written as text and not compared with `==`. `x => ...` in an argument is a compile error that says there are no lambdas. Decided on 12 November | The smallest form that covers callbacks and tables of operations |
| <a id="heap-and-missing-values-in-compiled-code"></a>Heap and missing values in compiled code | A `T*` is one pointer to a block made by `new`, freed with what it owns where its owner ends. A `T*?` is the same pointer, with `null` as the address zero; every other `T?` is a flag and the value. A struct that points to itself through one field (a list) is freed in a loop, not by recursion, so a long list cannot run out of stack; a tree is still freed as deep as it is. `print(p)` with `int* p` writes the number. The methods of numbers, `bool` and text are found through a `T*`, like fields and the methods of a struct. A move on a right side of `??` that always leaves (`?? return list`, `?? panic(...)`) does not count for the code after it. A limit of the back end for now, not a rule of the language: the output needs GNU statement expressions (clang, gcc); where `try` and `?? return` can stand is in ["`Result` in compiled code"](errors.md#result-in-compiled-code). Decided on 12 November | A missing pointer costs nothing (Rust does the same for `Option<Box<T>>`); the list benchmark runs in 1.01 times the time of C. Rust frees a list by recursion unless `Drop` is written by hand |
| <a id="enums-in-compiled-code"></a>Enums in compiled code | An enum is a tag of one byte and, beside it, room for the largest variant; an enum whose variants carry nothing is the tag alone. `match` is a chain of tests on the tag (not a C `switch`: `break` and `continue` in an arm mean the loop around it). A `match` on an owned value takes it apart: the names of the arm own what the variant carried, what the pattern skips is freed as the arm starts, a `T*` subject gives its block back; on a borrow the names are pointers into the value. An enum moved out of its place is left with a tag that is no variant (255, so at most 254 variants). The drop of a variable that was certainly moved is not written. At first `match` was compiled only as a statement or as the whole right side of one, and the names of `is` and of a borrowing `match` needed a value that has a name; both limits are gone (twenty-fifth and twenty-eighth slice). Decided on 12 November | What a C programmer writes by hand; Rust packs the tag further, which is not done here. The expression-tree benchmark runs in 1.02 times the time of C |
| <a id="writing-and-comparing-in-compiled-code"></a>Writing and comparing in compiled code | A struct, an enum or a list is written by a helper of its type (field by field or by its own `format`; text inside in quotes) into a text that is then printed: one allocation for a value that is written, none for numbers and text. A `Formatter` is that text. `==` compares two values where they are, through pointers, by the struct's own `equals` where it wrote one; `<` and the others call `compare`. `sort` keeps equal items in the order they had (a merge sort, with one block as large as the list while it runs; since the 166th slice it merges the runs the items already make, as Rust's and Python's sorts do, so items in order or in the reverse order are read once). Decided on 12 November. Since the twenty-fifth slice (13 November) printing a struct allocates nothing: the value is written into one block that the program keeps and uses again (not straight into the output, so that a line still comes out whole; a block that one line made larger than 64 KB is given back as soon as it is empty), and `f.write` writes a struct straight into the text it is adding to. The block was approved on 13 November after writing straight into the output was measured (2.7 times slower: every piece is a call into the C library's output); `f.write` always writes so, which the rule for the values of a line makes possible (see ["Order of evaluation"](statements.md#order-of-evaluation)); both approved on 13 November | The same text as the interpreter's. Rust's `Display` allocates nothing and keeps no block; Rust's `sort` is stable too. The printing benchmark runs in 0.57 times the time of a C `printf` |
| <a id="identity-and-equality"></a>Identity and equality | `a == b` compares content on every type, on `shared T` too; if `T` is not `Equatable` it is a compile error, and the hint is `same`. `same(a, b)` is `true` if two `shared` values point to the same object (`ReferenceEquals` in C#, `Rc::ptr_eq` in Rust). For a structure that refers back to itself (`City.roads`) the compiler cannot generate `equals`, and whoever wants it writes it by hand | In C# `==` looks at identity on a class and at content on a `string`, and one has to know which. Two words for two questions |
| <a id="consts"></a>Consts | `const T Name = e`, the type always written: at the top of a file (`public const` follows the rule of visibility) and in a block, where it is seen to the end of the block; a name it hides is an error, as for a local (["A name that hides another"](statements.md#a-name-that-hides-another)). It holds an integer, `float`, `double`, `bool`, `char` or a text, or an array, a `Copyable` struct or enum of them; not a `List`, an owned `string`, a pointer, `shared` or `raw`. Its value is made of numbers, texts, other consts in any order (one that needs itself is an error), operators, casts, `MinValue`, `MaxValue`, `Pi` and the others, arrays (`int[3] { ... }`, `byte[256](../0)`), structs and variants, `.length()` of a const array or text, and an item or a field of one; an overflow, a division by zero or an index outside is a compile error. Every use reads the one value: `var t = Masks` copies it, `Masks[i]` and `read Masks` read it where it lies, a borrow of it lasts for the run (a function with no borrowed parameter may return one, as a text constant), and writing into it, `ref` and a method that changes it are compile errors whose hint is a copy. An integer const gives the count of an array (`byte[BlockSize]`), and a const of a number, a `char`, a text or a `bool` stands for its value in a pattern, since a local never takes the name of a const it sees. `const int[] Primes = { 2, 3, 5, 7 }` counts the items (`int[4]`); `const byte[] Logo = embed("logo.gif")` holds the bytes of a file beside the source, read when the program is compiled (C23's `#embed`, Rust's `include_bytes!`). In compiled code a number is written where it is used and a table is one `static const`. Approved on 17 November 2026, before the hundred-and-third slice (choices 1080 to 1087, 1098 and 1099) | C23's `constexpr` and Rust's `const`, with C#'s notation. A table known when the program is compiled lies in the data the program only reads, with no cost at run time, and an error in it is found before the program runs. The type is written because it is what the const says. A `List` cannot be one: it owns a block of the heap, so a copy of it would allocate where nothing shows it, and growing it would write into data that is only read; a table is an array, and a list built once at run time is a static (choices 1088 to 1097, after the calls in a const) |
| <a id="consts-as-built"></a>Consts, as built | A const of an array, a struct or an enum is, where it is used, a `read` borrow of the one value for the whole run, so the rules of `read` refuse what would change it; a const of a number, a `bool` or a `char` is a value, and one of a text is the text itself. The checker finds every value with the interpreter, once each initializer is checked, and a panic on the way is a compile error that names the const. The count of an array is found from the text of an integer const before the types are, and found again later; the two agree. A variant of the enum looked at comes before a const of its name in a pattern. No text inside an array, a struct or an enum yet. `embed` takes a path written out, from the folder of the file, of a file of one byte to 64 MB, and is written only where a const is given its value. In C a table is defined only where the code reads it. Built on 17 November 2026, in the hundred-and-third slice (choices 1109 to 1119) *(19 November 2026, choice 1339: the path is written with `/`, without `..`, `.`, an empty part, a `\` or a `:`, and the file lies in the folder of the file or below it also where a link leads, as Go's `//go:embed` takes it)* | What the decisions asked for, with the rules the language has already; a table of texts waits for a program that needs it |
| <a id="no-call-in-a-const"></a>No call in a const | A const calls no function: its value is made of numbers, texts, other consts, operators and casts, `MinValue` and the others, `.length()`, an item or a field of a const, and arrays, structs and enums of them, as in C#, Go and C. A value a function finds is a `static` (`static uint[256] Crc = crcTable()`), found the first time the program uses it; a table the program needs from its start is written out, made by a script beside the code (zlib's `crc32.h`). The same holds for the default value of a field, the number of a variant and a `const assert`, each refused in its own words, with the hint of a `static`, of a `test` or of `assert`. Approved on 20 November 2026, during the hundred-and-forty-fourth slice (choice 1606); it takes back the calls of choices 1100 to 1108 (17 November 2026): the rule of what may run, its errors (`` `size` calls `load`, which reads or writes a file here ``), the ban of `sin` and its kin, the budget of 100 000 000 steps, the 64 MB a growing text or list stopped at, a const that reaches itself through the functions it calls, and the bodies that waited for a const and were checked again | A call in a const ran the program inside the compiler: an editor, a package or a build could be held for seconds and gigabytes by what it only checks, and the language had a second way to find a value beside `static`. Without it the consts are found before any body, from what is written, and the compiler runs no code of the program. The cost is a table written out, or a load and a branch where a static is read |
| <a id="no-call-in-a-const-as-built"></a>No call in a const, as built | `const int[] Squares = squares()`, `int[Count]` from such a const, `const assert(f() == 4)`, `int retries = twice(3)` in a struct and `Image = base()` are refused at the call (`a const calls no function`). Every const is found once, before the bodies, and the checker no longer runs a body for one. The compile-time check of a pattern of `Regex` stays (choice 1607): it runs the `std` module's own `Regex.problem`, never the program's code, within the budget of 100 000 000 steps, the only one left (1 000 000 when the front end is fuzzed). The tables of `std` that were found by calls (CRC-32's 4096 entries, deflate's four) are written out in the module by `tools/std_tables.py`, which `--check` compares with the files (choice 1608): a static would cost each call of `crc32` a load and a branch. Built on 21 November 2026, in the hundred-and-forty-fifth slice (choices 1606 to 1608) | What a const holds is what the source says, so the compiler, `sg lsp` and a package's check cost the same whatever the program does |
| <a id="statics"></a>Statics | `static T Name = e`: one value for the program, which lives until it ends and is never assigned. Three kinds: read only (every use gives a `read` borrow; `atomic` fields inside it are changed by their methods through it), `static atomic T`, and `static locked T`, the one place `locked` stands without `shared` (409's exception): the value is the program's, so no owner is counted. No static that is assigned freely and none for each thread (["Globals, as decided"](concurrency.md#globals-as-decided)). A value given by the rule of a const (inside `atomic` and `locked` too) lies in the data of the program, with no check and no cost; any other is found the first time the static is used, safely for threads and once (Rust's `LazyLock`), and a later read is one acquire load and one branch. Finding every static before `main` was refused: C++'s order of initialization, a slower start, and a library has no `main`. What finds a value cannot `lock`, `wait` or `await`, through the functions it calls (the rule of a `lock` block), so finding cannot deadlock; one that needs itself is a compile error where the calls show it and a panic where a `Func` makes the circle. What a static holds follows the thread rule (no borrow, no `shared checked` value without a lock, no `Task`) and is not `Disposable` or `Closable`: a static is never dropped, so a file in one would never be closed; the hint gives the value as a parameter. A static is never freed (as in Rust), and the leak report and LSan do not count it. The interpreter runs each test with the statics as the program starts; a compiled test runs in a process of its own. A static is written at the top of a file (`public static`) and in a function, where its name is seen only there (C's `static` inside a function). In C a static is a global of the unit; a `locked` one with a constant value has its mutex initialized statically (`PTHREAD_MUTEX_INITIALIZER`, `SRWLOCK_INIT`); one found later has a once of three states in the runtime, with the wait the runtime has, and spins without an operating system. Approved on 17 November 2026, before the hundred-and-fifth slice (choices 1088 to 1097) | Rust's `static`, `LazyLock` and `static Mutex`, C11's `call_once`, C#'s `static readonly` and Go's package variables, kept to what cannot race: the compiler sees every task that reaches a static, as it sees the arguments of `Task.run`. A table found once and read everywhere, a counter of requests, the settings of a server and a kernel's count of ticks need no parameter threaded through every call |
| <a id="statics-as-built"></a>Statics, as built | The value is the body of a function of its own (`Name#init`), checked as any body; a static of a block sees the consts and statics of the blocks around it and no local. The value lies in the program from its start when it is made of numbers, consts, operators and casts, arrays, structs and enums of them, `atomic` around them, of a type a const can hold; a static given a call is found where it is first used (a const calls none, choice 1606). A number, a `bool`, a `char` or a function is read as a value, anything else lent as `read`; assigning, `ref` and `read` on a number are errors that point at `atomic` and `locked`. A `static locked` value is written only in a `lock`; a local does not take the name of a static; a static that holds a function is copied to a local to be called. The circle is followed through the calls, the `format`, `equals`, `hash`, `compare` and `dispose` that run unwritten, and the statics read on the way. At run time a task that finds a static being found by itself, or by a task that waits for one it is finding, panics, in the interpreter and in compiled code alike. A debug build and the interpreter let go of what the statics hold when the program or a test ends, before the leaks are counted; a release build does nothing.
