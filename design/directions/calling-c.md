# Calling C, the direction

*Decided on 15 November 2026, before the sixty-ninth slice.* Calling C comes in three slices: raw memory (`raw T`, `unsafe`,
`Memory`), then `extern` blocks and their calls, then `Disposable` on types of your own, opaque C types and C structs, with a
library wrapped in a safe type. The rows below were decided together; those of raw memory are built in the sixty-ninth slice, and
`extern` blocks, their calls, C text and a buffer for C in the seventieth; `Disposable` on types of your own, `Closable` on
them, opaque C types and structs by value in the seventy-first.

| Topic | Direction | Reason |
|---|---|---|
| <a id="declaring-c-functions"></a>Declaring C functions | `extern "z" { int compress(...) }`: a block per library, which is linked (`-lz`); `extern { }` is the C library itself. C names are written as C writes them, the one place the camelCase rule does not hold *Built on 15 November 2026, in the seventieth slice:* at the top level of a file only, one function on each line, with no body; the functions are private to their module unless `public` is written on one, and a C function declared in two modules is declared the same way in both | Rust's and Zig's form; there are no attributes for C#'s `[DllImport]` |
| <a id="headers"></a>Headers | No C header is included: the prototype is written from the SG declaration *Built on 15 November 2026, in the seventieth slice:* compiled code includes headers of its own for the runtime, so a C function is declared under a name of the runtime and bound to its C name with a label (`__asm__`), and clashes with no header | Nothing is looked for, and nothing clashes with the names of the runtime. A wrong declaration is not always caught by the C compiler, as in Rust |
| <a id="safety"></a>Safety | Every call of an `extern` function is written inside `unsafe`; there is no `safe` mark for now *Built on 15 November 2026, in the seventieth slice.* | The risky way is chosen on purpose. A safe type wraps a library, and its users see no `unsafe`. A `safe` mark (Rust 2024's) can come if the noise asks for it |
| <a id="what-a-signature-holds"></a>What a signature holds | The integer types, `float`, `double` and `bool` as their C types; `raw T` as `T*`; `ref T` as `T*` and `read T` as `const T*`, for the time of the call; `read CString` as `const char*`. `string`, `List` and `T?` are not in a signature *Built on 15 November 2026, in the seventieth slice:* `ref T` and `read T` of plain data that is not an array (C takes the address of the first item, which `buffer.pointer()` gives); `char` is an error whose hint is `byte`; a struct by value comes with C structs *Built on 15 November 2026, in the seventy-first slice:* a struct of plain data by value, as an argument and as what C gives; `ref raw T` is C's `T**` | What C can take without a copy that nobody sees |
| <a id="text"></a>Text | `CString.from(read text)` makes an owned text that ends in a zero byte, an error for a zero byte inside; `unsafe string.fromCString(p)` copies what C gives and checks that it is UTF-8 *Built on 15 November 2026, in the seventieth slice:* `CString.from` gives a `Result<CString, TextError>`, the `position` of the zero byte; `string.fromCString` takes a `raw byte` and gives a `Result<string, TextError>` | A `string` has no zero at its end, and is always UTF-8 |
| <a id="a-buffer-for-c"></a>A buffer for C | `unsafe buffer.pointer()` gives a `raw byte` to a slice or an array; its count is passed apart *Changed on 15 November 2026, before the seventieth slice:* `buffer.pointer()` is written only as an argument of a C function (inside its `unsafe`), on a list, an array or a slice of plain data, and gives a `raw T`; in the call it counts as a `ref` of the buffer. The interpreter can then copy the items to C and back, and no pointer outlives the call; memory C keeps comes from `Memory.allocate` | C takes a pointer and a count |
| <a id="c-in-the-interpreter"></a>C in the interpreter | The interpreter writes a small C file for the `extern` functions a program uses, builds it as a shared library with `cc` and opens it with `dlopen`; no libffi *Built on 15 November 2026, in the seventieth slice:* in a folder of its own that only the user can open, made new for each run; and `Memory.allocate` and `Memory.free` are C's `calloc` and `free` in the interpreter too, so memory goes between SG and C both ways | No new dependency, and the interpreter and compiled code stay one language |
| <a id="c-and-tasks"></a>C and tasks | A `raw T`, and a value that holds one, does not go to another task *(16 November 2026, the ninetieth slice, choice 842: unless it is of a type written `: unsafe Sendable`, its writer's promise)* | Whether a C library may be used from two threads is not known |
| <a id="c-and-async"></a>C and async | A call of an `extern` function does not count as holding the thread (["Nothing holds the thread in async code"](../rules/concurrency.md#nothing-holds-the-thread-in-async-code)); a long one is wrapped in `await Task.run(...)` | As `print`; a rule would make most of C an error in async code |
| <a id="later"></a>Later | Calls from C back into SG, `errno`, functions with a varying count of arguments (`printf`), `pkg-config`, Windows; `sg build -L path` for where libraries lie *(16 November 2026: `errno` came in the eighty-fourth slice, calls from C into SG in the eighty-fifth, a varying count of arguments in the eighty-sixth; `-L` and Windows are planned in ["Windows, the direction"](windows.md), choices 941 and 942; `-L` came in the ninety-sixth)* | |
| <a id="raw-memory"></a>Raw memory | A `raw T` points at plain data (numbers, `bool`, `char`, raw pointers, and arrays and structs of them), laid out as C lays it, or is a `raw void`, C's `void*`, which is cast before anything else is done with it. It may be `null` (no `raw T?`); `Memory.allocate<T>(n)` gives zeroed memory, a count below 0 or more than an address can count is a panic; `Memory.copy` copies items, also over itself | What C shares is plain data; owners in raw memory would need rules of their own |
| <a id="what-unsafe-is-for"></a>What `unsafe` is for | An item of raw memory (`p[i]`), `p + n`, a cast between raw pointers, `Memory.free`, `Memory.copy`, and since the seventieth slice `extern` calls and `string.fromCString` (since the eighty-seventh `Memory.view` too); making, copying and comparing a pointer, and `Memory.allocate`, are not. `unsafe { ... }` around statements, `unsafe` in front of a value, binding as `try` does. An `unsafe` that nothing needs, and one inside another, are errors | The word stays where the checker really stops following; there are no warnings |
| <a id="checking-raw-memory"></a>Checking raw memory | The interpreter checks each item against the block it came from: outside it, after `free`, through `null`, a block given back twice, are panics. Compiled code checks nothing; the tests run it under the sanitizers | Rust's Miri, built into the reference |
| <a id="disposable-on-a-type-of-your-own"></a>`Disposable` on a type of your own | *Decided on 15 November 2026, before the seventy-first slice, and built in it.* `struct T : Disposable` has one `void dispose(ref this)`, on a struct (not an enum for now). It runs where the last owner of the value ends (the end of a block, a value written over, an item taken out of a list, the last `shared` owner), before the fields end; not on a panic or `exit`. `x.dispose()` is an error, and a method that takes `this` ends the value where it ends, so a type that frees something there keeps a field that says so. A `Disposable` type is not `Copyable` and not plain data, so it is not in raw memory or in a signature of C; it is in collections, `T?` and `shared` values, and goes to another task unless it holds a `raw T` | C#'s `IDisposable` without `using`, Rust's `Drop`. A `dispose` that nobody calls cannot be called twice |
| <a id="closable-on-a-type-of-your-own"></a>`Closable` on a type of your own | *Decided on 15 November 2026, before the seventy-first slice, and built in it.* `: Closable` asks for a `close(this)` that gives a `Result`, and a local of the type is closed before it ends, as a `StreamWriter` is; the hint is `try x.close()`. The type's own methods are exempt for `this` | The error of the last step (a stream's last bytes, a flush) is not lost; `dispose` cannot give it |
| <a id="compiled-dispose-2"></a>Compiled `dispose` | *Decided on 15 November 2026, before the seventy-first slice:* `dispose` is a C function; a move known when the program is compiled costs nothing, one that depends on a condition keeps a flag on its local. *Built differently in the slice, and approved on 15 November 2026 (choice 538):* a `Disposable` struct has one byte more, set where the value is moved out, and its drop looks at it, as a moved text leaves a `NULL` and a moved enum a tag that is no variant | The back end already empties every place a value is moved out of and tests it where it is dropped; the byte is that rule for a struct with nothing else to empty |
| <a id="a-type-of-c-seen-only-behind-a-pointer"></a>A type of C seen only behind a pointer | *Decided on 15 November 2026, before the seventy-first slice, and built in it.* `extern "sqlite3" { struct sqlite3 }`: a struct without a body in an `extern` block, written only as `raw sqlite3` (and `ref raw sqlite3` for C's `sqlite3**`); an item of it, `p + n`, `Memory.allocate<sqlite3>`, a field and a value of it are errors. Private to the module unless `public`; the same name in two modules is two types | What C does not show, SG does not guess; one pointer type cannot be handed to a function that takes another |
| <a id="structs-of-c"></a>Structs of C | *Decided on 15 November 2026, before the seventy-first slice, and built in it.* A struct of plain data is laid out as C lays it out, with no mark; its fields have names of SG, and only their order and types count. It goes to C by value and comes back by value. Unions, bit fields, `packed` and alignment come later; an enum of C is an `int`, a pointer to a function a `raw void` *(16 November, the eighty-fifth slice: a pointer to a function is a `CFunc<...>`)* | Rust's `#[repr(C)]` is what every plain struct already is |
| <a id="a-variable-nothing-reads"></a>A variable nothing reads | *Decided on 15 November 2026, before the seventy-sixth slice, and built in it.* A local variable whose value nothing reads is a compile error: one never used, and one only written. Writing the variable, `x += 1`, and a write to one of its fields or items are not reads, unless the write goes through a borrow, a `shared` value or raw memory; every other use is one, a method called on it and `ref x` given to a call among them. A parameter is not looked at, nor a variable of a `Disposable` type or of a struct that holds one. The name of a `for` and of a pattern are held to it too, with `_` for one not needed. A value written over before it is read, or given after the last read, is not looked at yet | Go makes an unused variable an error, Rust warns; a write to a copy (`var p = rect.corner; p.x = 0`) is the mistake gcc warned on in the C, and the hint is the borrow (`var p = ref rect.corner`). No cost at run time: the checker alone |

Once threads and async are built, a program in SG is promised at compile time: no data race (Rust promises this too); no
deadlock from the order of locks, and none from locks and waits, as long as no channels are used; a wait under a lock (`lock
... when`) for a value no other task owns is always caught, and waits under locks that wait for each other are caught in the
interpreter (in compiled code with the hardening before the preview), as are tasks that wait on channels for each other; a `for`
over a channel that a sender of the same function would keep from ending is a compile error; no `await` while a lock is held; no task cancelled without
being told; no task forgotten or left running, and no error of one lost; no deadlock from waiting for async code the wrong
way and no pool starved by a call that blocks, which C# and Rust both allow; and one runtime. A logic race (a value read in one
`lock` block and written in another, changed by another task in between) is not caught; a two-step change is written in one
block. These are promises of the design until they are built and tested; [what runs today](../../interpreter/docs/features/README.md) says so only then.
