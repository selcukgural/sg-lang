# Windows, the direction

*Decided on 17 November 2026, after the threshold was reached (choices 928 to 942).* SG runs on Linux, macOS and
Windows (["Three systems"](reaching-what-c-reaches.md#three-systems)); the rows below say how Windows is reached. Each slice decides the details of its own part
before it is written, as before.

| Topic | Direction | Reason |
|---|---|---|
| <a id="testing-on-windows"></a>Testing on Windows | GitHub's machines with Windows run `cargo test` on x86-64 and on 64-bit Arm for every push to the branch of Windows, with GitHub's own `actions/checkout` pinned to its commit as the only action and a token that only reads. A virtual machine with Windows on 64-bit Arm is where a slice is tried while it is written. Linux and macOS are still tested where the code is written. No Wine (928) *(17 November 2026, the ninety-seventh slice: built. `.github/workflows/windows.yml`; the repository allows only GitHub's own actions, pinned to their commits; 996)* *(17 November 2026, the hundred-and-second slice: with the last slice of Windows merged, the CI runs on every push to `main`; it installs QEMU, at a fixed version whose installer is checked against its SHA-256, for the kernel; 1072, 1078)* *(23 November 2026, the hundred-and-sixtieth slice: Linux has a job of its own, `.github/workflows/linux.yml`, the whole `cargo test --release` on GitHub's Ubuntu for every push to `main`, the stand of the servers among it; macOS is still tested where the code is written; 1754)* | Wine is not Windows; the machines of a public repository cost nothing |
| <a id="the-machines-and-the-compiler"></a>The machines and the compiler | `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`; Windows 10 1809, Windows Server 2019 and later, 64-bit only. Clang, with its own driver, not `clang-cl`, and LLVM's `lld-link`; of Microsoft's tools only the libraries and the SDK. C's library is linked into the program (`/MT`), so a program needs nothing installed; each DLL then has a heap of its own, and memory goes back through a function of the one that gave it. The compiler is `CC`, then `clang` on `PATH`, then `C:\Program Files\LLVM\bin\clang.exe`, with a hint to install LLVM and the Build Tools when none is there. A program is `x.exe`; `--library` gives `x.lib`, `--shared` gives `x.dll` with `x.dll.lib`; a debug build writes `x.pdb`. Building for Windows from macOS or Linux comes later (929) *(17 November 2026, the ninety-seventh slice: built for programs and tests, `--library` and `--shared` waiting for C's slice. `-fuse-ld=lld -fms-runtime-lib=static`, the manifest written beside the C and embedded by LLVM's linker, `/STACK:8388608`, `/DEPENDENTLOADFLAG:0x1000`, `x.exe` when `-o` names no extension; 983)* *(17 November 2026, the hundred-and-first slice: `--library` and `--shared` built, `x.lib` made by `llvm-lib`; the libraries of the system and `legacy_stdio_definitions`, where Microsoft keeps `printf` and its kin as functions, named by the C itself; `sg build` copies beside a program the DLLs it linked from the folders of `-L`, and those they need, since Windows has no `rpath`; 1054, 1057, 1062)* *(17 November 2026, the hundred-and-second slice: a debug build, which is not optimised, asked the C compiler's library for a division of 128 bits, which Windows does not link; the runtime divides in 64 bits there, and a test holds every program to it on every system; 1070)* | The libraries a program links on Windows are built for Microsoft's ABI; Rust's names for the files, since a static library and an import library would both be `x.lib` |
| <a id="c-s-long"></a>C's `long` | `CLong` and `CULong` are as large as C's `long` and `unsigned long` on the system: 64 bits on Linux and macOS, 32 on Windows. They are types of their own, not other names of `int` or `long`: a value crosses with a cast (`(CLong)n`, `(long)r`), there is no arithmetic on them (the hint is `(long)r + 1`), `==`, `<` and printing work, and a number written without a type goes into one only if it fits in 32 bits, on every system. In an `extern` block they are written where C has `long`; `long` there stays C's `int64_t`. The examples and tests that wrote `long` for C's `long` are put right (930) *(17 November 2026, the ninety-fifth slice: built. A value crosses on its own where that holds on every system, by the rule of mixing integers: an `int` becomes a `CLong`, a `CLong` a `long`; the other way is a cast that checks this system's size. No range, method, `atomic` or bit field of one either, and a `match` on one is looked at as 64 bits. curl and zlib take them, zlib's `uLong` everywhere and the size of its stream from `Memory.sizeOf`; 943 to 949)* | Rust's `c_long` is another name of `i64` or `i32`, so code that compiles on Linux does not on Windows; and the same sum overflows on one system and not on the other |
| <a id="text-at-the-edge-of-the-system"></a>Text at the edge of the system | Windows is called through its functions of UTF-16, the text turned at the edge. A name, an argument or a variable that is not valid UTF-16 is the error one that is not UTF-8 is elsewhere, its position counted in bytes of UTF-8. To a console the text goes through `WriteConsoleW`, a character split between two writes kept until it is whole and a byte that is not UTF-8 shown as `�`, as a terminal shows it; the code page of the console is not changed. From a console the input is read with `ReadConsoleW`, Ctrl-Z at the start of a line ending it. Files are binary: `writeLine` writes `\n` on every system. Every `.exe` and `.dll` carries a manifest: UTF-8 as the code page of C's functions (from Windows 10 1903), long paths, Windows 10 and 11. Names of variables are matched without case, as Windows matches them. A text of UTF-16 for calling Win32 from SG comes later (931) *(17 November 2026, the ninety-seventh slice: built for the output, the standard error, the console's input that waits, the command line and the variables. C's `printf` and its kin reach the console through the runtime; a name that is not UTF-16 becomes WTF-8, which is not UTF-8; 984 to 986)* | A program behaves the same on the three systems, and a library of C linked into it opens a path of UTF-8 |
| <a id="paths-and-files"></a>Paths and files | On Windows `/` and `\` both separate and `Path.join` writes `\`; `C:\`, `C:`, `\\server\share\`, `\\?\` and `\\.\` are roots, and a root at the start of the second part of `join` is dropped, as `/` is. `Path.joinInside(folder, name)` gives an `InvalidInput` for a name with `..`, a root, a drive, a `:`, the name of a device (`CON`, `NUL`, `COM1`) or a dot or a space at its end, on every system the same, so that a name from outside stays inside the folder. A long path goes to Windows as `\\?\` without the program seeing it. A file is opened so that others may read, write, rename and delete it, and a deletion takes the name away at once (POSIX semantics, from Windows 10 1809), as on Linux and macOS. `File.move` never takes the place of a file, `deleteAll` follows no link or junction and works from the handle of each folder, `createTemp` makes a folder only its owner may enter. `Directory.list` gives names in the order of their bytes of UTF-8. On Windows the code of `Other(code)` is Win32's (932) *(17 November 2026, the ninety-fifth slice: `Path.joinInside` built on Linux and macOS, a name of several parts taken, a `\` refused on every system, `a/../b` refused too; `Path.join` keeps a `..` as it is written. A link inside the folder is still followed; opening by the handle of the folder comes later; 950 to 955)* *(17 November 2026, the ninety-seventh slice: built on Windows. A path goes as `\\?\` from 248 characters, as in Rust; `join` keeps a separator the first part ends with; `deleteAll` holds the handle of every folder it is in, so none can be swapped for a link; a folder opened as a file is `IsDirectory` and a file on the way `NotDirectory`, as on Linux; 987; The hundred-and-forty-second slice (choice 1594): `joinInside` refuses C1 control characters too; `\\?\UNC\` is read byte by byte, so a character of several bytes there is no panic.)* | A name that is safe on one system must not lead out of the folder on another |
| <a id="signals-2"></a>Signals | `Interrupt` is Ctrl-C and Ctrl-Break. `Terminate` is the console closed, the user logged off and the system shut down; while a listener lives, Windows is held until the program ends, within the few seconds Windows gives. `Hangup`, `Quit`, `User1`, `User2` and `WindowChange` never come on Windows, and listening for them is no error. `Signals.raise` works there too, with the default of a signal when nothing listens. `kill`, `terminate` and `signal` end another program with `TerminateProcess` and the code 1, since Windows has no polite stop to send (`signal(Signal.WindowChange)` does nothing, and since the 197th slice neither do `Child`, `Continue` and the three of a terminal, which pause no program there; raised with no listener they do nothing either). A group is made with `CREATE_NEW_PROCESS_GROUP`, to which only `Interrupt` (Ctrl-Break) goes; a console has no group in front, so `Terminal.giveTo` and `takeBack` do nothing (2023, 2031). Services of Windows come later (933) *(17 November 2026, the hundredth slice: built. The handler of the console hands the signal on itself, on the thread Windows gives it, and does not return from a `Terminate`; a raised signal with no listener ends the program as Ctrl-C does (`0xC000013A`). The command line is read by the runtime, not by `CommandLineToArgvW`, whose `shell32` brings `user32`, and a console program with `user32` is not told of logging off or shutting down. A listener of `Interrupt` turns off the ignoring of Ctrl-C a program was started with, as a listener on Linux and macOS takes the place of an ignored signal, and it is not turned back on, since Windows does not tell whether it was; 1042 to 1046)* | Go's mapping; a program written once is right on both |
| <a id="other-programs"></a>Other programs | `CreateProcessW`, the command line quoted by the rules C's library reads it with. A program named without `/` or `\` is looked for in the absolute folders of `PATH`, with `.exe` added when it has no extension, and never in the folder the program works in. A `.bat` or `.cmd` runs only when named with its extension, its arguments escaped for `cmd.exe` as Rust does since CVE-2024-24576, and one that cannot be escaped is an `InvalidInput`. The child inherits only its three streams; names of variables have no case. `ExitStatus.Code(int)` on every system, a code with its highest bit set printed in hex (`exited with code 0xC0000005`). A child does not end with its parent, as on Linux and macOS; job objects come later (934) *(17 November 2026, the ninety-fifth slice: `ExitStatus.Code(int)` built; `exit(code)` keeps a `byte`, the code every system keeps whole; 956, 957)* *(17 November 2026, the hundredth slice: built. A folder of `PATH` in quotes is taken whole; the program is named by its handle until it is waited for; the pipes are named pipes, overlapped on our end, and a cancelled read is cancelled with `CancelIoEx` instead of `CancelSynchronousIo`, so the call never reads on and nothing is lost; a cleared environment keeps `SystemRoot`, as Go keeps it; `waitAsync` waits on the pool of threads of the system; the tests start `sg-test-tool` in place of `sh` and its kin on every system; 1032 to 1047)* | `CreateProcess` looks in the working folder first, where a planted program would run |
| <a id="a-terminal-of-its-own"></a>A terminal of its own | A pseudo console (ConPTY, Windows 10 1809 and later), found in `kernel32.dll` when first asked for. The program gets handles that name nothing for its streams, so it does not get those of this program where they were redirected; it takes all three streams or none (`InvalidInput`). The pool of threads of the system closes it as soon as the program ends, so its reader ends without waiting for `Process.wait`. It writes sequences of its own, draws its screen again at a new size, and ends the program when its writer is closed; `Signal.WindowChange` does not come. The raw mode of a console is `SetConsoleMode`; its size is the window of the console. *(Slice 198, 2042-2053.)* | The interpreter cannot give a program a pseudo console through std's `Command`, so it calls `CreateProcessW` itself |
| <a id="the-runtime"></a>The runtime | Threads of `_beginthreadex`, `SRWLOCK` and `CONDITION_VARIABLE`, behind functions of the runtime; the main thread has 1 GB of stack, reserved and taken as it is used, as on Linux and macOS (8 MB before choice 1821), and `EXCEPTION_STACK_OVERFLOW` is told as a panic (1815). The loop of the network polls through `\Device\Afd` on an I/O completion port, as mio and Tokio do, so the scheduler of the eighty-first to eighty-third slices stays as it is; a listener takes `SO_EXCLUSIVEADDRUSE` and never `SO_REUSEADDR`, and a socket is not inherited. Pipes and files are read and written the async way on the threads of input and output. Blocks aligned beyond 16 bytes come from `_aligned_malloc`; `Instant` from `QueryPerformanceCounter`, `DateTime.now` from `GetSystemTimePreciseAsFileTime`, `Task.delay` from a timer of high resolution, `SecureRandom` from `ProcessPrng` (935 to 937) *(17 November 2026, the ninety-seventh slice: blocks aligned beyond 16 bytes, the clocks and `ProcessPrng` built; a block of `_aligned_malloc` goes back through `_aligned_free` everywhere the back end gives one back; 988, 989)* *(17 November 2026, the ninety-eighth slice: threads, locks, conditions, the pool and the clock of delays built; every lock, condition and thread of the runtime goes through one layer, pthread on Linux and macOS, so no name of pthread is taken on Windows; the pool counts the cores of every group; the clock sleeps on the timer of high resolution and an event, and fifty delays of 1 ms take about 97 ms there; a write to the console holds its stream's lock; 999 to 1013)* *(17 November 2026, the ninety-ninth slice: the loop of the network built on AFD and a completion port, a question to the driver asked once and again while tasks wait; a listener and a datagram socket hold their port alone, and a datagram that came back is told as on Linux and macOS, only to a connected socket; names looked up in UTF-16; files and the input stay on the threads of input and output, and a cancelled wait for the input leaves its thread reading; Windows tells of a refused connection after about two seconds; 1015 to 1030)* | A recursion that runs on Linux runs on Windows; on Windows `SO_REUSEADDR` lets another program take the port; a delay of a millisecond does not take sixteen |
| <a id="tests"></a>Tests | `sg test --compiled` starts itself for each test (`--only N`) on every system, and `fork` goes. A debug or test build counts the blocks its runtime gives and takes back and reports a leak as the program ends, on every system; LSan still runs on Linux and macOS. A check a system does not have (TSan on Windows) is said in the output, not passed over (938, 939) *(17 November 2026, the ninety-sixth slice: built on Linux and macOS. The program starts itself again through `posix_spawn`, from the path the system gives; the count is of the blocks of values, raw memory and what the runtime keeps for the process left out, looked at where the `shared` values are, and one below zero is reported too; 972 to 978)* *(17 November 2026, the ninety-seventh slice: on Windows the program of tests starts itself with `CreateProcessW`; the address and undefined-behaviour sanitizers are tried and a missing one is said, leaks are the count of blocks, and the line says the thread sanitizer is not there; 991, 993)* *(17 November 2026, the ninety-eighth slice: a program on several threads runs on Windows under the sanitizers the machine has, and the line says how many ran without the thread sanitizer; 1011)* | One path for the three systems; a check never passes in silence |
| <a id="the-interpreter-and-c"></a>The interpreter and C | The interpreter runs on Windows with declarations of its own of Windows' functions, with no crate. Its wrappers are built into a DLL. A DLL is looked for in the program's folder and in `System32`, never in the working folder or on `PATH`. `C.lastError()` gives the system's last error (`GetLastError` on Windows, `errno` elsewhere) and `IoError.fromCode` takes it; `IoError.fromErrno` takes `C.errno()`, the number of C's library, which on Windows is not Win32's (940) *(17 November 2026, the ninety-fifth slice: `C.lastError()`, `C.setLastError(n)` and `IoError.fromErrno` built, `errno` on Linux and macOS; `IoError.fromCode(C.errno())` and `IoError.fromErrno(C.lastError())` are errors with the right one as the hint; 958 to 960)* *(17 November 2026, the hundred-and-first slice: built. The wrappers are a DLL with C's library as a DLL (`/MD`), the one the interpreter is linked with, so memory and `errno` are one with it; "the program's folder" is the folder of its first file, and the folders of `-L` are looked in too; the folder of the DLL is removed by the next interpreter once its process has ended; `GetLastError` is kept by every call of C beside `errno`; the functions of C in the branch of another system of an `if` on `OperatingSystem` are not linked; the interpreter carries the manifest of compiled programs; 1050 to 1052, 1058, 1059, 1063)* | A DLL put where a program is started would be loaded otherwise |
| <a id="libraries"></a>Libraries | `sg build`, `run` and `test` take `-L folder`, and the interpreter looks for DLLs there too. `extern "z", "zlib" { }` names a library by the names it has on the systems; the first one found is linked, and the error names the ones tried and where. On the CI of Windows the libraries of the examples come from vcpkg (941), whose zlib is `libz.lib` since 1.4, so zlib is named `"z", "zlib", "libz"` (1258) *(17 November 2026, the ninety-sixth slice: built on Linux and macOS. A folder of `-L` is also written into the program as its `rpath`, and one others may write into is an error; whether a name is there is asked of the C compiler by linking an empty program with it, only for a block of several names and once a link has failed; 963 to 971)* *(17 November 2026, the hundred-and-first slice: built on Windows. The libraries come from vcpkg as DLLs with their import libraries, not built into the program, which would bring C's library of `/MT` into the interpreter's DLL and leave libcurl's libraries of the system to be named by hand; a folder of `-L` may hold a `:` and is not checked for others writing into it, since nothing of it is written into the program; `extern "m"` and `"c"` link nothing there; 1053 to 1056, 1064)* | zlib is `-lz` on Unix and `zlib.lib` with vcpkg, and Windows has no `pkg-config` |
| <a id="the-order-2"></a>The order | 95: `CLong`, `Path.joinInside`, `ExitStatus.Code(int)`, `C.lastError` and `IoError.fromErrno`. 96: `-L`, an `extern` of several names, tests without `fork`, the count of blocks. Both on Linux and macOS. A test of what Windows does not run yet is listed with its reason in `tests/windows-pending.txt`, which shrinks with each slice and is empty after the last; a preview of the language comes after (942) *(17 November 2026, the hundred-and-second slice: done. Everything is tested on Windows, the program without an operating system and the kernel in QEMU included, and the list is gone; the programs of `bench` are measured against C there too; 1068 to 1079)* | What does not need Windows is done first, where it is tested today |
